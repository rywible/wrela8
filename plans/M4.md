# M4 plan: build images on paper

**Status: ACTIVE.**

First deliverable of the milestone, per the planning convention. The docs
carry the substance — [02-language.md](../docs/language/02-language.md)
§2.1 (manifest), §12.1 (the image constructor),
[04-compiler.md](../docs/language/04-compiler.md) §1 "Closure" / §7 (the
image report) / §8 (reproducibility and phases),
[05-library.md](../docs/language/05-library.md) §9 (builder intrinsics) —
and [ROADMAP.md](../ROADMAP.md) carries the how. When M4 is done, this
file is history, not maintenance.

## Goal

A wrela *project* — manifest, module tree, one `@image` fn — "compiles":
the manifest is parsed and its module graph resolved, the `@image` body
runs in the M3 evaluator with the builder intrinsics as its effects, the
declared runtime graph is checked (wiring, pools, supervision, restart
provisions), and the **image report** comes out as a byte-stable,
diffable golden artifact — before any runtime exists and with zero
instructions emitted. Imports stop failing closed; quotas come from
build profiles instead of hardcoded constants.

## The ROADMAP sentence, scoped honestly (decide once)

ROADMAP M4 says "the virtio example 'compiles' to a diffable report."
[virtio-storage.wr](../docs/language/examples/virtio-storage.wr)'s own
header says it is ASPIRATIONAL and imports modules the stdlib does not
ship; its bodies are full of `await`/`send`/`with`, which stay
fail-closed (async typing is not M4 — non-goals). The M4 realization of
that sentence is therefore: **an M4 example appliance** — a real
multi-module project with devices, drivers, actors (synchronous handler
bodies), pools, supervision, and restart provisions, built from the
shipping intrinsics — compiles to the pinned report. virtio-storage.wr
keeps its existing corpus guarantee (lexes + parses) and graduates to a
real build when the stdlib and async milestones supply what its header
names as missing. The plan records this so nobody quietly weakens either
side.

## Exit criteria

- `cargo xtask check` green with: manifest goldens, the image-graph
  error corpus, report goldens for project-shaped golden cases, the
  report-determinism oracle, and the build bench lane wired in.
- The M4 example appliance builds to a byte-identical report across
  repeated builds (the determinism oracle proves it every `check`).
- `sema.names.imports` flips from gap to test. Every `manifest.*` and
  `image.*` clause below opened and flipped (or opened as an explicit
  gap where stated).
- `cargo xtask fuzz eval` (now seeing `@image`-bearing corpus inputs)
  clean at deep budget; the sema/typed-roundtrip oracles clean over the
  corpus including multi-module golden projects.
- `plans/M5.md` does not exist yet.

## Shape decisions (frozen by goldens — decide once)

1. **The manifest is hand-rolled, strict, schema 1 exactly** (02 §2.1).
   No `toml` crate in the compiler (it has zero external dependencies
   today; the ledger records the reason a general parser is the wrong
   tool: §2.1 *requires* unknown-field, duplicate-key, and
   absolute/parent-path errors, so a strict subset parser is the spec,
   not a shortcut). Fields: `schema`, `language`, `[package]`
   name/version/source_root, `[[dependency]]` alias/package/requirement
   (revision 0.1: exactly the `core` alias is acceptable), `[[profile]]`
   named quota overrides, `[[image]]` name/module/entry/target/profile,
   optional image-test entries (parsed, recorded, fail closed at use —
   scenario runners are M5+). Every parse error is a named
   `error[manifest]` diagnostic with line/col.
2. **Module discovery is a deterministic walk** of `source_root`
   (BTree order over relative paths, `.wr` files only); a file's module
   path must match its declared `module` header or the build errors.
   The `core` dependency alias resolves to the toolchain `stdlib/`
   tree; anything imported from it that does not exist fails closed
   with the missing path (the stdlib ships nearly empty in M4 — that is
   the stdlib milestone's problem, not ours to fake).
3. **Imports resolve whole-program**: collect runs over every
   discovered module first, then resolve sees a global symbol table
   (module path → public names). `from a.b import c` binds `c` locally;
   only `pub` items are importable; collisions and missing names are
   named diagnostics. Sema stays one deterministic batch — no lazy
   loading, no incremental anything. The typed program's maps become
   keyed by fully-qualified names where they were module-local before;
   `--stage` dumps stay per-file and byte-identical for single-module
   programs (existing goldens must not move).
4. **Profiles override quotas only** (02 §2.1 "stating only their
   overrides of language-defined defaults"): step/memory/call-depth/
   exhaustive-cases limits. The M3 constants become the language-defined
   defaults of the unnamed default profile. An `[[image]]` entry names
   its profile; `wrela test`/single-file paths use the default. Nothing
   else is configurable — no target cost models, no feature flags.
5. **`@image` evaluation is the M3 evaluator plus intrinsic effects.**
   The builder surface (05 §9: `Image(name, target)`, `img.device[D]`,
   `img.driver`, `img.actor`, `img.pool[T]`, `img.dma_pool[T]`,
   `img.supervise`, `img.check_layout`, `decl.handle()`,
   `img.seal()`) is compiler-recognized by callee key — prelude-style
   declarations, no stdlib source needed. Intrinsics are legal only
   during an `@image` evaluation (a named diagnostic anywhere else,
   including `@test`s and const initializers); `eval::legal`'s
   exhaustive matches gain their first real illegal arm. Evaluation
   builds one plain `ImageGraph` struct (BTreeMaps + construction-order
   Vecs) — declarations recorded in program order, every argument a
   fully evaluated `Value`.
6. **Exactly one reachable `@image` per image entry** (04 §1 Closure):
   the manifest's `module`+`entry` names it; a second `@image` in the
   reachable graph, or the named one missing/not-`@image`, are named
   diagnostics.
7. **Graph checks are M4's "Closure" subset, each one named** (02
   §12.1, 05 §9): construction edges form a DAG (cycle printed in
   full, the wait-cycle diagnostic precedent); every `pool` name bound
   exactly once by `img.pool`/`img.dma_pool` and never constructed as a
   value; `img.driver`/`img.actor` arguments match the actor's `init`
   after generated capabilities and handles are substituted
   (`decl.handle()` produces `Actor[A]`); exactly one supervising
   parent per actor/driver (the image root is the implicit parent of
   top-level `supervise` groups — pin the doc's exact rule in goldens);
   a resource `init` argument without a recovery source is an error;
   `seal` succeeds only when every declaration is fully bound. What M4
   does **not** check is also named: mailbox capacity derivation
   (declared numbers recorded as-declared, M6), placement (M8), memory
   ceilings (M5).
8. **The report is one stable text artifact in the M1 dump style** —
   `Kind key=value` lines, two-space indent, fixed section order, a
   versioned header line (`ImageReport v0`), facts only: build identity
   (compiler revision, target, profile, input digests), images,
   devices, drivers/actors with their init wiring and declared
   mailboxes, every logical actor edge, pools with capacities and
   restart provisions, the supervision tree, registered (unrun) layout
   asserts. **No placeholders for facts that don't exist yet** — a
   section absent in M4 is absent, and later milestones append sections
   without reshuffling existing ones. The summary is a few fixed lines
   to stdout; the report is the artifact.
9. **Report determinism is an oracle from day one**: `xtask` builds
   every project-shaped golden twice (fresh output dirs) and
   byte-compares the reports — the M4 down-payment on 04 §8's
   `compiler.repro.byte-identical` (which stays a gap until the binary
   image exists, M5). Input digests use a single hardcoded hash
   (implemented in-tree; no new dependency).
10. **`img.check_layout` registers; nothing runs it.** There is no
    layout until M5, so a registered `@layout_assert` is recorded in
    the report and the build then **fails closed** naming M5 if any is
    registered — never "asserted against nothing". Same for
    `img.dma_pool`'s `@layout(dma)` requirement: `@layout` structs are
    not validated until the hardware milestone, so `dma_pool` fails
    closed naming it (gap `image.graph.dma-pools`).
11. **`wrela build <path>`** (manifest file or directory containing
    `wrela.toml`) is the CLI surface: builds every `[[image]]` entry,
    writes `<name>.report.txt` next to the manifest (or `--out-dir`),
    prints the summary, exits nonzero on any diagnostic. Golden cases
    for projects are directories with `wrela.toml` + `src/` + an
    `expected/report.txt` (+ `expected/build-err.txt` for rejection
    cases) — the golden runner learns this one new case shape.
12. **Code layout**: `crates/wrela-compiler/src/manifest.rs` (parse +
    walk), `sema/` grows the multi-module entry (collect-all then the
    existing pipeline per module), `eval/image.rs` (intrinsics +
    `ImageGraph` + graph checks), `report.rs` (rendering). Long obvious
    files, plain structs, BTreeMap everywhere output-touching.

The **group/scoped-pool unification** question is settled (human
decision, 2026-07): two constructs, deliberately — one region model,
two binding disciplines, stated normatively in 04 §3. M4's `img.pool`
goldens pin the two-construct surface with that decision on the record.

## Work items, in order

### A. Manifest + module graph
`manifest.rs`: strict schema-1 parser (decision 1) with a full
`error[manifest]` corpus; deterministic walk + module-header agreement
(decision 2); import resolution whole-program (decision 3);
`sema.names.imports` flips. Goldens: manifest error cases (unknown
field, dup key, abs path, bad schema), a multi-module accept project,
import-error cases (missing module, missing name, non-pub, collision).
Opens: `manifest.schema-one.strict`, `manifest.modules.deterministic-walk`,
flips `sema.names.imports`.

### B. Build profiles
Decision 4: quota overrides parsed, threaded into `eval` (constants
become defaults), per-image-entry selection. An over-quota program
passing under a bigger profile and failing under the default is the
golden pair. Opens: `manifest.profiles.overrides-only`; updates
`comptime.eval.quotas`' note.

### C. `@image` evaluation
Decision 5: intrinsic recognition by callee key, `ImageGraph`
construction in program order, the `@image`-context legality carve-out
(intrinsics illegal elsewhere — `eval/legal.rs`'s first real illegal
arm, and `comptime.legality.inferred` finally earns golden evidence and
flips). `@image` bodies stop failing closed in sema (they are ordinary
comptime-legal code plus intrinsics). Opens:
`image.eval.builder-intrinsics`, `image.eval.comptime-context`; flips
`comptime.legality.inferred`.

### D. Graph checks
Decision 6/7, one named diagnostic + err golden apiece: one-image,
construction DAG (cycle printed), pool bound-once/never-a-value,
init-argument matching with handle substitution, one-parent
supervision, missing recovery source, unsealed/unbound `seal`. Opens:
`image.graph.one-image`, `image.graph.construction-dag`,
`image.graph.pools-bound-once`, `image.graph.init-args-match`,
`image.graph.supervision-one-parent`, `image.graph.seal-fully-bound`;
gap `image.graph.dma-pools` (decision 10).

### E. The image report + example appliance
Decision 8: `report.rs`, the versioned dump, summary lines. The **M4
example appliance** lands as a project-shaped golden (devices, a
driver + two actors with sync bodies, an image pool, supervision with
restart provisions) and its `expected/report.txt` is the milestone's
flagship artifact. The determinism oracle (decision 9) wires into
`check`. Opens: `image.report.stable`, `image.report.deterministic`.

### F. CLI + harness + measurement
`wrela build` (decision 11); the golden runner's project-case shape;
`xtask bench` grows a build lane (build the example appliance,
median locked in `bench/thresholds.toml`); the fuzz-eval seed corpus
grows `@image`-bearing inputs so the existing lane exercises intrinsic
evaluation; `xtask corpus` keeps every doc ```wrela block lexing +
parsing (the virtio example included, unchanged).

### G. Error-corpus sweep
Adversarial pass (haiku tier) over the new surface: manifest edge
cases, import cycles and diamond imports, image graphs at every check's
boundary (self-cycles, double binds, deep supervision trees, sealed
twice, empty images), report determinism under reordered-but-equal
inputs (BTree ordering must win), intrinsics called from `@test`/const
contexts. Any find minimized and pinned before its fix lands.

## Non-goals (M5+ territory)

No code emission, layout, linking, or `@layout_assert` execution (M5);
no async/actor **body** typing — `await`/`send`/`with` stay fail-closed,
actor participation in the image graph is by signature (M6 territory,
and the reason the example appliance's handlers are synchronous); no
mailbox capacity *derivation* from sender sets (M6 — declared capacities
are recorded verbatim); no placement inference (M8); no `@layout` struct
validation or DMA pools (hardware milestone — explicit gap); no package
acquisition or lockfile (revision 0.1 ships `core` only); no image-test
scenario execution (parsed and recorded only); no comptime caching
(unchanged: needs a profile the cleverness budget accepts); no report
fields invented ahead of the milestone that can prove them.
