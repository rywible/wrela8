# M11 plan: the image runtime, generated and generic

**Status: ACTIVE.**

First deliverable of the milestone, per the planning convention.
[ROADMAP.md](../ROADMAP.md) M11 carries the substance — the design
(facts-only generated config + handwritten algorithms), the facts-only
rule, three rejected alternatives, the perf honesty, and the
machine-contract prerequisite. This plan does not relitigate any of it.
What it adds is the ordered item walk, the measured starting state, the
shape decisions this milestone freezes, and the exit criteria.

Human decisions that activated this plan (2026-07-26):

- Insert as the **new M11**; authoring hardening is M12; cycle proxy
  becomes M13; playground M14 (ladder renumber 2026-07-26, hardening
  inserted after M11 activation).
- **Test-runner unification is in scope**, as a late item once the
  migration items have built evidence.
- **Core-count authoring (`cores=N` / relax single-core floor / work-based
  packing) is a follow-up**, not M11 — but M11 must emit `N_CORES` from
  `PlacementTable.cores` so that follow-up stays thin (decisions 708–709).

This milestone settles the REVIEW-QUEUE escalation's dissolve fork
(option ii): ImageStatic specialization is scaffolding, not a permanent
second medium.

### Runtime module loading (acyclic — required for the two-batch front end)

- `stdlib/core/runtime.wr` is always-loaded via
  `loader::load_runtime_module` / `ensure_runtime_module`.
- Names are **not** auto-visible (plans/M10.md decision 584); harness
  reaches helpers via force-rooted `CalleeKey`s.
- User code cannot import or call the runtime. Therefore: evaluate
  `@image` → ImageGraph first; generate config text; feed config +
  `runtime.wr` through the ordinary front end; no cycle.

### Array lengths in `@layout(runtime)` (decision 581, not 580)

Decision 580's literal-only rule was lifted by item A2b (decision 581):
an array field's length may be an integer literal **or** the name of a
module-level `const` whose comptime value is ≥ 1. The generator therefore
emits `const N_TURNS: usize = <literal>` and
`turns: [TurnArea; N_TURNS]` — readable, and already legal.

### What `runtime.wr` contains today

Handwritten machine pages (`MACHINE_INFO`, `CONSOLE_RING`,
`CONSOLE_DATA`), packed `TEST_LINE_BUF` (`[u8; 21]`), console formatter
(`@budget`-bounded digit extract / reverse / append — M11 item B), abort
body. **No** scheduler, mailbox, turn, or dispatch logic — that is still
the 714 ImageStatic words.

### Bench baseline to re-lock before migration

M10 item M recorded `bench guest` on `boot-actors`: median **62914us**
against the 700000us lock (5 timed boots). Item 0 re-measures and pins
the quiet number in this plan before any emitter moves.

## Shape decisions this milestone freezes

Numbered from 700 so they do not collide with M10's 555–697.

**700. Generated config is a pretty-printed `String`, not an AST
synthesis.** Walk the ImageGraph in its existing deterministic order
(`actor#0`, …) and print source text. Feed that text through the same
lexer/parser/sema as any file on disk. No macro system, no comptime
codegen API, no second IR.

**701. Module identity.** Hidden module name
`core.__image_runtime` (exact spelling frozen here). Never imported by
application source. Appears in the report as
`Input path=<generated> sha256=…` (or an equivalent digest line — exact
render shape is item D's golden). Dump stage: `rtconfig`.

**702. Facts-only rule (ledger clause).** Generated text may contain:
module header + version comment; `const` bindings; `@layout(runtime)`
types; exactly one `@placed` static of the runtime-tables type;
exhaustive `match` ladders over comptime-known indices (dispatch /
instance routing). It may **not** contain: loops, `while`/`for`,
`async`, actor declarations, `@budget`, or any decision that is not a
`match` over constants. A unit test over the generator's output (or a
restricted parse of it) enforces this.

**703. Fixed `RTDATA_BASE`.** Item C picks the address and decides the
machine-revision question. Layout **checks** the placed size against
`compute_runtime_tables` rather than bump-allocating after code.
`verify_section_sizes`' 8-byte gap rule is resolved in the same commit
(steer cursor, or placed-section exemption) — carried risk from M10,
must not be rediscovered inside a migration item.

**704. Two-batch front end, not a phase abstraction.** (1) Load/sema user
program + stdlib except deferred `runtime.wr` (or defer only its import
of the config module — item D picks the narrower seam). (2) Evaluate
`@image`. (3) Generate config text. (4) Parse/sema config + `runtime.wr`
through the ordinary front end. (5) Lower/codegen the union. Do not
invent a "runtime compilation" framework.

**705. Migration oracle is the boot transcript, same as M10.** Each
emitter deletion requires byte-identical transcripts on every
runtime-boot golden and green `xtask repro` lanes *before* the Rust
function is removed. Census ratchet decrements in the same commit.

**706. `@budget(bound=N)` for sync loops is the dumbest sound reading of
02 §8.1.** Normative doc decision in its own commit first. Async loops
continue to checkpoint unless budget-proven; this milestone does not
claim cycle proofs (ROADMAP "Cost proofs" intention stays human-gated).

**707. Test-runner unification is in scope as item K, not a non-goal.**
`@test(runtime)` becomes ordinary supervised root turns. Deletes
`build_entry_driver` (94 words). May reconsider the abort long-jump
(floor cat4). Deliberately last before the sweep — highest golden churn.

**708. Application authoring surface does not change in M11.** Image
developers keep writing `@image` / `img.actor` / `img.supervise` /
`img.seal()` and today's optional `core=` pins. The config module is
readable via `--stage=rtconfig`, never authored. **Deferred follow-up
(not this milestone):** an explicit live-core-count surface
(`Image(..., cores=1|2|3)` or equivalent — bring up / pack across N of
the fixed 3-vCPU machine), optional relaxation of the single-core floor
(no pin ⇒ core 0 only), and work-based “intelligent” packing once proofs
exist. Manual `core=` pins stay.

**709. Live core count is a generated fact, never hardcoded.** The
config module emits `const N_CORES: usize = <PlacementTable.cores>` (or
an equivalent spelling frozen in item D) from today's placement output
(1 when no `core=` ≥ 1; `VCPUS` for a cross-core graph). Handwritten
`runtime.wr` and every migrated per-core loop **index that const** —
they must not bake “always core 0” or “always 3” into algorithm source.
That is what makes the deferred `cores=N` follow-up a thin placement /
image-API change rather than a second runtime rewrite.

**720. Item 0 baseline is the quiet `bench guest` median before any M11
code moves.** Measured 2026-07-26: min=60793us median=**63639us**
max=65001us on `boot-actors` (2 warmup + 5 timed); exact counts
transcript=34 / exit_code=0 / exits=1 / choices=0. Lock 700000us
unchanged (≈11× headroom). This number is the before half of the exit
criterion's before/after delta; do not re-lock the threshold here.

**721. `@budget` sync-loop discharge (item A):** a sync `while`/`for`
without a preceding `@budget(bound=N)` is `error[sema]` (narrows
`sema.bounds.loops`; async/ISR halves stay gaps). `N` is a
comptime-known integer ≥ 1. Acceptance emits a hidden trip counter that
aborts if the body runs more than `N` times — fail-closed runtime bound,
no cost model. Doc commit first, then code.

**722. `RTDATA_BASE` (item C):** fix as an in-image packing constant in
`wrela-machine` (relative to `IMAGE_BASE = 0x4050_0000`), sized from
measured peak `code+rodata+abort+checkpoint` plus headroom and a
fail-closed max for mailbox blowups. **Do not bump `MACHINE_REVISION`**
— guest-visible pages/stacks/entry unchanged; REVIEW-QUEUE line records
that choice. Resolve `verify_section_sizes` in the same commit (steer
cursor to the placed address).

**723. Generator seam (item D):** defer only `runtime.wr`'s import of
`core.__image_runtime`; user program batch unchanged. Generator is a
`String` pretty-printer (decisions 700–702).

**730.** Statement-attribute parse: of the built-ins, only `@budget`
may precede a statement, and only immediately before `for`/`while`;
the `Attr` attaches to the loop AST. Other statement attributes / a
loop-position `@budget` on a non-loop are parse errors.

**731.** Sema (sync half of decision 721): when `!in_async`, a
`for`/`while` without a validated `@budget(bound=N)` is
`error[sema]`. `N` is a positive integer literal. Async loops do not
require the attribute; a present attribute is shape-checked but does
not change checkpoint behaviour (async half stays gap). Typed
`While`/`For` carry `budget: Option<u64>` (`Some` only for sync).

**732.** Acceptance emits a hidden trip counter in lower + comptime
interp: each body entry increments; exceeding `N` is
`AssertFail` / abandon with message `loop budget exceeded`. No cost
model.

**733.** Diagnostic category `sema` added to `SEMA_CATEGORIES` so
`error[sema]` is a legitimate fuzzer/check outcome.

**750. `RTDATA_BASE = IMAGE_BASE + 0x1_0000` (`0x4051_0000`).** Measured
peak `code+rodata+abort+checkpoint` over the golden corpus: **28014**
bytes; peak span `IMAGE_BASE` through checkpoint end: **`0x6dc4`
(28100)**. The 64 KiB packing window leaves ≈37 KiB deliberate headroom
(~2.3× the peak span). Every actor-bearing report's `rtdata` base moves
to this constant.

**751. `RTDATA_SIZE_MAX = 256 KiB`.** Fail-closed ceiling on the `rtdata`
section alone. Peak golden `rtdata` today is **6664**; `check-import-lower`
with `mailbox=SETTLED` (71142) demands **1138392** bytes and is now refused
at layout (`error[build]: … exceeds RTDATA_SIZE_MAX (262144)`), pinned by
that golden's `test.txt`.

**752. No `MACHINE_REVISION` bump** (reaffirms 722). `RTDATA_BASE` is an
in-image packing constant; guest-visible pages, stacks, and entry are
unchanged. REVIEW-QUEUE records the flagged question and the answer.

**753. `verify_section_sizes` steered gap.** A ≥8-byte inter-section gap
is legal only when the next section is `rtdata` at exactly
`RTDATA_BASE` (layout steered the cursor there). Not a blanket
placed-section exemption.

**740. Sync loop back-edges do not emit checkpoints.** `emit_fn`
(sync) no longer splices `FnCtx::checkpoint` / `Reloc::CheckpointService`
onto a backward `Jump`. Trip counters (decision 732) are the sole sync
`@budget` discharge. This dissolves M10 decision 597 for console
helpers and is what makes item B's loops legal in multi-core images
(layout's `Reloc::CheckpointService` ownership check). Async
`Transition::Jump` back-edges (await-containing `lower_while_split`
cycles) still checkpoint.

**741. Console formatter is ordinary `@budget`-bounded loops over
`[u8; 21]`.** `TestLineBuf` is a packed `bytes: [u8; LINE_BUF_SIZE]`
field (`LINE_BUF_SIZE = 21`). Digit extract (`bound=20`), reverse
(`bound=10`), and append copies (`bound=21` / `bound=16384`) replace the
named-field ladder and the unrolled / binary-split helpers. Index bounds
still emit `bl __wrela_abort_val`; the abort latch (M10 decision 591)
keeps a second entry from recursing into print.

**742. Bounds-abort-recursion settled by the existing latch, not by
avoiding indexes.** Named `b0..b20` fields were a temporary way around
bounds checks; with decision 740's sync loops and decision 591's latch,
indexed `[u8; 21]` is the steady shape. Status returns (decision 592)
remain the overflow path for append/commit.

**743. Oracle for item B is byte-identical boot transcripts.** Asm /
report / img.hex may move (code shrinks where sync checkpoints fell out;
console helpers grow trip-counter loops). `err-cross-core-checkpoint`
retargets to an async await-in-while on core 1 (the remaining
checkpoint-ownership refusal). `err-cross-core-checkpoint-free-fn`
becomes the positive witness that a free sync `@budget` loop on a
secondary core is legal.

**760. Generator input is the laid-out `RuntimeTables`.** After
`try_layout_program` (post-`stripe_for_cores`, with cross-core rings
when present), `rtconfig::generate` pretty-prints that table. No second
sizing walk; the dump and the report digest share one text.

**761. `N_CORES` spelling.** Exact freeze (decision 709):
`pub const N_CORES: usize = <PlacementTable.cores>` (via
`tables.cores` after stripe). Single-core goldens pin `= 1`;
cross-core pin `= 3` (`VCPUS`).

**762. Opaque overlay for item D.** Generated `@layout(runtime)` type is
`RuntimeTables { bytes: [u8; RTDATA_BYTES] }` with
`RTDATA_BYTES = tables.total_bytes`, `@placed(0x40510000)` (integer
literal — `@placed` still requires a literal per 03 §3.1 / A2c; the
value is `RTDATA_BASE`). Structured fields and match ladders land in
E–J; counts (`N_TURNS`, `N_ACTORS`, `READY_QUEUE_CAPACITY`, …) are
emitted as `pub const` now.

**763. Facts-only enforcement.** Unit test over generator output rejects
whole-word `while` / `for` / `async` / `@actor`. Ledger
`compiler.rtconfig.facts-only`.

**764. Report digest.** `Input path=<generated> sha256=<hex>` inserted
after the last file `Input path=` line. Digest is SHA-256 of the
generated UTF-8 text. Generated module is **not** merged into the
layout/`PlacedStatic` program map in item D (narrow seam) — only
batch-2 typechecks it with unstripped `runtime.wr`.

`from core.__image_runtime import N_CORES`. Batch-1 loads strip that
import (`loader::defer_image_runtime_import`); user-program front end
unchanged. Batch-2 re-parses unstripped `runtime.wr` + generated text
through `check_program_typed`. No phase framework (decision 704 / 723).

**766. Determinism.** `generate` twice over the same `RuntimeTables` is
byte-identical; ledger `compiler.rtconfig.deterministic`.

**767. Dump stage.** `wrela dump --stage=rtconfig`; goldens
`boot-actors` / `boot-cross-core` `expected/rtconfig.txt`; ledger
`compiler.rtconfig.dump-stable`.

**768–779.** Reserved for item D follow-ups if needed; do not borrow.

**780. Stub `core.__image_runtime` in batch-1.** Loader injects
`rtconfig::stub_text()` (idempotent) whenever a runtime-bearing closure
loads `core.runtime`, so `runtime.wr` keeps its generated import and
typechecks before a live image exists. Live images overwrite via

(same spirit as decision 667 for auto-injected `core.runtime`);
`<generated>` is never read as a disk path — digest stays

**781. Structured overlays for deadline.** Generator emits
`TurnArea` / `GroupSlot` / `RuntimeTables` / `GroupArena` with
`pub static RT` @ `RTDATA_BASE` and `pub static GROUPS` @ the placed

**782. Deadline algorithms in `runtime.wr`.** Force-callable
`__wrela_deadline_poll` / `__wrela_deadline_scan` use `@budget` loops
over `GROUP_ARENA_CAPACITY` / `N_TURNS` / `N_CORES`, scalar field
access on `GROUPS.slots[i]` / `RT.turns[t]` (no whole-struct MMIO
loads). Poll arms `MACHINE_INFO.next_deadline` and stores `1` into
each live core's pending word when due.

**783. Vector0 saves LR (and x28) around `BL __wrela_deadline_scan`.**
A bare `bl …; ret` leaves LR at the `ret` and spins — the hang that
blocked the first BL migration. Master inlined the scan; the BL form
needs an explicit frame. Contract: may clobber `x0..x14`, must
preserve `x28`/`sp`.

**784. Live reinject.** After `RuntimeWiring::derive`,
`reinject_runtime_with_rtconfig` re-codegens the two deadline keys
against live RT/GROUPS addresses and inserts them into `program.fns`
only when `group_arena_capacity > 0` and `turn_stride >= 0x48`. They
are **not** in `RUNTIME_FORCE_ROOT_KEYS` — always-rooting blew the
14000-byte layout-assert code budget on every runtime-bearing image.

**785. Harness real-pass Call relocs.** `layout_test_image`'s second

- Optimizing the scheduler (ready-queue population, match→jump-table,
  fusion) — M13-proxy-gated cleverness-budget purchases.
- `@naked` / inline asm.
- Comptime metaprogramming / user-visible codegen.
- Config-as-data / device-tree / function pointers.
- Register allocation, isel catalogs, a second mid-end.
- Cycle proofs / `@latency_assert` (ROADMAP recorded intention).
- Changing the `@image` authoring surface — including a new `cores=N`
  (or equivalent) live-core-count knob, relaxing the single-core floor,
  and work-based intelligent packing (decision 708). **Prerequisite for
  that follow-up is decision 709** (`N_CORES` generated from
  `PlacementTable.cores`); do not hardcode core cardinality in
  `runtime.wr` during E–J.

## Known risks, carried into execution

- **`verify_section_sizes` 8-byte gap rule** — must die in item C, not in
  a migration item. Fires as `internal error:` (fuzz treats as bug).
- **Machine revision bump** for `RTDATA_BASE` — flag in item C; do not
  silently revise `MACHINE_REVISION`.
- **Mailbox capacity unbounded** — a single pathological image can demand
  a huge `rtdata` region; item C's region size needs a fail-closed ceiling
  or a measured tripwire, not an unbounded reservation.
- **Decision 581 const lengths** — generator must emit consts the
  layout-completion pass can see; ordering bugs show up as layout errors,
  not as silent wrong offsets.
- **Deferred sema seam** — keep it "call the same front end twice"; if it
  grows a phase abstraction, stop and simplify.
- **Item K transcript blast radius** — every `@test(runtime)` golden
  moves; budget review time; do not combine with an emitter deletion.
- **Checkpoint floor embedding** — do not call a migration "complete"
  while floor words remain mis-categorized as ImageStatic.
- **Expect the scheduler to get slower** — ROADMAP states this up front.
  The lock is the tripwire; the transcripts are the correctness oracle.
