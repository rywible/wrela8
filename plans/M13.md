# M13 plan: one vocabulary, no silent failure (the unification milestone)

**Status: ACTIVE (2026-07-27).** Activated by item 0 after M12 close.
Decision block 900–999 reserved for this milestone.

Provenance: synthesized from two independent design reviews of the v1
language plus one external review of the combined draft plan (all
2026-07-26), cross-verified against code, ledger, and REVIEW-QUEUE.
The draft was split on that review: representation work went to
`plans/M12.md`; this file is the vocabulary-and-authoring milestone.
Every file:line anchor below was checked on this tree; if an anchor
has moved by activation, re-verify the fact before the item, not the
plan's conclusion — the facts are structural, not positional.

The milestone's one-sentence doctrine: **apply the language's
signature move — computed, published, checked — to its own remaining
exceptions, and let every item delete something** (a type, a spec law,
a name list, a trap, an API family). Net new surface: two knobs
(`CallError` spellable; `resource(manual)`), one attribute
(`@discard`), two language features with existing consumers (field
visibility — already normatively promised by 05 §5's "opaque"
`Instant`; method-owned generics — the 02 §8.3 idiom), and one
analysis (type classes) that replaces two failed ad-hoc ones. Against
that, the deletion tally: `race(...)`, `@detached`, `@no_promote`,
`group(budget=)`, function-level `@budget`, `@task(budget=)`,
`Validated` (demoted to a now-honest idiom), the entire priority-band
apparatus (bands, `must_service_within`, priority/deadline
inheritance), `PeerFailed` and two `Admission` variants, per-actor
restart (04 §5 wholesale, provisions, intensity, three strategies, the
`Restart` enum), and net/sound from machine-v1 conformance.

## Ladder consequence

The renumber is already in ROADMAP (landed 2026-07-26, human-directed:
M12 = representation rung, M13 = this plan, M14 = progress-
constructively, M15 = cycle proxy, M16 = playground). What this plan absorbs and
dissolves from the pre-split authoring-hardening M12:

- Hardening item 1 (**no silent `Err` discard**) is item L — a
  soundness prerequisite for the proof-conditioned collapse (item M)
  that must land over the unified vocabulary (items I–J), not before
  it.
- Hardening items 2–3 (**epoch freshness on send**, **restart
  intensity**) are **dissolved by item F (crash-only)**: stale actor
  epochs exist only because per-actor restart creates them, and
  intensity bounds exist only because restart can storm. With restart
  cut, both lose their subject. Device/reset epochs are hardware truth
  and are untouched (receipt state machine, 03 §9).

## The crash-only decision (made, recorded, still gated at its commit)

Recorded precisely, because the combined draft got this wrong once
(it claimed blanket acceptance of a recommendation the human had not
yet seen — the external review caught it from internal evidence, and
that line is struck):

- **2026-07-26, the human decided: keep crash-only if viable.** The
  viability case is below and the plan's position is that it holds.
  Item F's doc commit remains human-reviewed — that commit, not this
  paragraph, is the gate of record, and the REVIEW-QUEUE line lands
  with it carrying the counterarguments preserved (the external
  review's containment and product-claim objections), not just the
  rationale.

The viability case, stated against the strongest objections:

1. **"It deletes the only fault containment" — conceded as to
   bystanders; we pay with durability.** If the *display driver*
   faults, `OneForOne` restart would preserve the app's document and
   reboot destroys it. Bystander survival *is* the containment value.
   Crash-only **accepts bystander loss** and pays for it with a
   durability requirement: apps checkpoint working state to storage,
   so a whole-image reboot costs seconds of volatile state rather
   than documents. That is an application idiom over the storage
   driver, not language machinery — and it is currently **unbuilt**
   (VMM models `blk`; `ExtentFs` is aspirational; `with pool` is
   still `error[unimplemented]`). Item F's REVIEW-QUEUE line names
   the durable-checkpoint idiom + storage stack as a recorded
   dependency; the doc commit states that `Failure.Reboot`
   *presumes* app durability; conformance goldens pin
   `Failure.Halt` until that idiom exists (halt is honest;
   reboot-with-no-durability is the bad combination). `img.on_failure`
   stays required-explicit with no default — defaults hide decisions.
2. **"It breaks the flat-tail product claim" — no: an abandonment is
   a defect event, not a tail event.** The p99.9 claim is a
   steady-state scheduling claim, conditioned (as every system's tail
   claim is) on the absence of defects. Item F's doc commit says so
   in one sentence rather than leaving it implicit. Reboot time is
   itself bounded and bench-locked (`boot-actors` guest lane), so
   even the defect path has a measured ceiling.
3. **"It is not additive to restore" — conceded, fully.** Crash-only
   is *not* justified by the revision-boundary cut rule (M13 decision
   2 below explicitly does not cover it); it carries its own
   justification and an honest price tag: restoring general per-actor
   restart later would be expensive (epochs thread through mailboxes,
   handles, pools, `CallError`). The hedge that costs nothing to
   keep: **driver-only restart is the named, evidence-gated
   fallback.** Drivers are where faults are hardware-correlated and
   state is reconstructible from the device; device reset epochs
   already exist in the receipt machinery, so the epoch
   infrastructure driver-restart needs is partially built exactly and
   only there. Nothing item F deletes forecloses it: quarantine
   survives, device epochs survive, `Admission.Quarantined` is
   reserved. **Variant settled now so the hedge never needs an
   un-deletion:** the fallback re-adds `Admission.Restarting` (new
   calls refuse as `NotAdmitted(Restarting, …)`; in-flight calls
   resolve `Cancelled` only for true group cancellation — 02 §9.4's
   meaning, not overloaded). No `PeerFailed`. Flip witness: a
   recording in which rebooting through a driver fault mid-session is
   demonstrated unacceptable.

## Where this milestone starts (verified anchors, 2026-07-26)

### Failure vocabulary

- `CallError` is fully modeled internally — patterns type-check with
  variants `Op(E)`, `Cancelled`, `DeadlineExceeded`,
  `NotAdmitted(Admission)`, `PeerFailed(Peer)`
  (`sema/bodies.rs:2783–2810`) — but is **not source-nameable**:
  `sema/types.rs:5358`'s `resolve_named` has no arm for it, so neither
  a `from(take e: CallError[E])` nor a return type can be written, and
  `?` on an awaited actor call is unreachable from source. Ledger gap
  `actors.calls.callerror-nameable`; corpus accepted-disagreement pins
  at `02-language.md:604` / `:674`.
- `Admission` and `Peer` are referenced as `Type::Named` payloads but
  do not exist in `sema/stdlib_enums.rs` (auto-visible set today:
  `Target`, `Restart`, `BootError`, `DriverMode`, `CompletionOutcome`).
- `send`'s error is the bare marker `Type::Named("Rejected", vec![])`
  (`sema/types.rs:9600`); the unproven-send diagnostic names
  `Result[unit, Rejected]` (`sema/send_proof.rs:416`). The doc-promised
  payload handback (`rejected.event`) is not implemented.
- The turn record already carries a typed reply channel:
  `OFF_TURN_REPLY = 24`, `OFF_TURN_REPLY_TAG = 56`, tag `0` = Ok,
  `1` = `Cancelled`, `3` = `NotAdmitted` (decision 559 comment above
  `codegen.rs:5892`; `BRK_ACTOR_TURN_CANCELLED` already retired by
  it). The one surviving representation-gap trap is
  `BRK_AWAIT_ACTOR_REJECTED = 0xACD3` (`codegen.rs:6040`): a rejected
  admission on an *awaited* call's enqueue aborts instead of composing
  `CallError[NotAdmitted]`. Its own comment assigns the fix to "the
  real composition" work — item H.

### Sealing (the prerequisite the draft missed)

- Struct field `pub` is **parsed and dropped**: `DeclField` carries
  only `{ name, ty }`; no sema pass reads a field's `is_pub`. Any
  module can construct any struct — `Instant(nanos=999999)` forges an
  "opaque monotonic point" today. Ledger gap
  `library.time.instant-opaque`; REVIEW-QUEUE (M9 item OO) parked the
  enforcement sentence with the migration already measured: 44
  constructions + 30 reads across 27 packages; 26 fields need `pub`;
  proposed 02 §2 sentence drafted verbatim in that entry. **This
  blocks three items**: `resource(manual)` sealing user typestate
  (item O), the `Validated` demotion (item P — a proof type any
  module can forge is not a proof type), and item S's claim that user
  and sealed typestate are the same mechanism. Item G lands it first.

### Proof-conditioned surface

- The `*_proven` family has exactly **one** live member:
  `VirtQueue.reserve_proven` (checker `sema/bodies.rs:6980`/
  `7018–7080`; ledger clause `hardware.queues.reserve-proven` at
  `ledger.toml:1394`). Pool `get_proven` / `from_str_proven` exist
  only in the ASPIRATIONAL example. 05 §10 legislates the naming
  convention; no separate ledger clause exists for the naming law.
- `send` already implements the collapse this plan generalizes: bare
  statement exactly where proven, `Result` otherwise
  (`sema/send_proof.rs`).

### Loop discharge

- The event-loop exemption is a name allowlist:
  `matches!(fn_name, "__wrela_rt_secondary_entry")`
  (`sema/bodies.rs:2251`), normatively encoded in 02 §8.1 / 04 §2 and
  ledger `sema.bounds.loops.event-loop-entry` (`ledger.toml:172`).
  M11 item K will extend it by one more name (the primary entry
  driver) unless this milestone replaces the rule first — it does
  (item N).
- Vector observation today: `__wrela_rt_checkpoint`
  (`stdlib/core/runtime.wr:962`) services `PENDING.words[0]` — core 0
  only. `PENDING` is `[u64; 3]` (one word per core); cross-core send
  raises `words[dst] |= 1` as a wake doorbell. The secondary park/run
  loop (`runtime.wr:930–936`) observes nothing on its work path; its
  only observation is the conditional `PARK.word = 0` store on the
  idle path. IRQ vectors are serviced on core 0 only, by construction
  of where checkpoint runs — a fact no clause records.

### Classification

- Copyability is already a computed structural class ("data if every
  field is data", `sema/types.rs`).
- Must-consume is a **hardcoded name list**:
  `is_protocol_consuming_type_name` matches exactly
  `DeviceCap | Mmio | IrqCap | VirtQueue | QueuePermit | QueueOp |
  Receipt` (`eval/image_checks.rs:1480–1485`). Composites carrying one
  are handled (`sema/flow.rs:655` `protocol_resource_carried`). A user
  cannot mint a must-consume type: a plain `resource struct` always
  auto-reclaims (02 §3.1).
- Mobility/containment is per-type prose (02 §9.3, 03 §1, 05 §2) and
  has failed once: the `InterruptCell` containment hole, found by an
  adversarial capability-escape sweep (REVIEW-QUEUE, decision 23),
  fixed by widening a sentence. Two failures of the same born-exempt
  shape justify item O.

## Shape decisions this milestone freezes (do not relitigate mid-item)

Decision numbers: this plan reserves **900–999**.

1. **The proof-conditioned rule** (frozen wording for the doc
   commit): *where the compiler proves an operation's failure
   impossible, the operation's result is its success type; otherwise
   it is the declared `Result`. The spelling never changes; the proof
   is displayed, and a failed proof surfaces at the use site with the
   why-chain (which bound, which image fact, what changed).* Scope:
   **compiler-granted strengthenings only** — `send`, the `*_proven`
   family, receipt pre-commit. The assertion family (`@budget`,
   `comptime assert`, `@layout_assert`) is author-demanded proof,
   fails at its declaration, and is out of scope forever.
2. **The revision-boundary cut rule** (item C). A v1 promise with no
   implementation, no ledger clause, and no consumer in the worked
   example or stdlib is cut at the revision boundary, and every cut
   names its surviving replacement idiom in the same commit.
   Restoring any of them is an additive revision — the 06 §10 path.
   **This rule does not cover crash-only** (item F), which is a
   design decision with its own justification and an honest
   non-additive price, recorded in the section above.
3. **Crash-only failure model** (item F). Abandonment runs the
   generated cleanup for the abandoned turn, emits the failure
   attribution diagnostic (actor, fault category, faulting site),
   then the image applies its declared failure policy:
   `Failure.Reboot` or `Failure.Halt`, declared exactly once as
   `img.on_failure(policy=...)` (required-explicit, no default),
   replacing `img.supervise`. Per-actor restart is deleted wholesale:
   04 §5, restart provisions, restart intensity, the three strategies,
   the `Restart` stdlib enum. Device quarantine (03 §9) is retained
   as the degraded-mode story; driver-only restart is the recorded,
   evidence-gated fallback and would re-add `Admission.Restarting`
   (see the decision section). The viability condition is stated in
   the doc commit: we accept bystander loss and pay with a durability
   requirement; `Reboot` *presumes* app durability (durable-checkpoint
   idiom + storage stack — named dependency, currently unbuilt);
   conformance goldens pin `Halt` until that idiom exists; the tail
   claim conditions on no-defect.
4. **`NotAdmitted` payload shape**: `(Admission, args)` where `args`
   is the tuple of the call's `take` arguments in declaration order,
   monomorphized per signature (05 §2's existing sentence, made
   true). Sema payload answer at `bodies.rs:2802` changes from
   `[Admission]` to `[Admission, tuple]` in the same item that builds
   the value (item H) — never split across commits.
5. **`send`'s type** becomes `Result[unit, CallError[never]]` with
   the existing whole-image variant erasure leaving exactly
   `NotAdmitted` reachable; `Rejected` is deleted. Bare-statement
   legality unchanged (it is rule 1 applied to `send`).
6. **Prelude additions**: `CallError` and `Admission` join the 02 §2
   fixed prelude. `Admission` is a fieldless auto-visible enum whose
   variant set after item F is `Full | DeadlineUnmeetable` —
   `Restarting` and `StaleRequest` die with per-actor restart, and
   `Quarantined` is named in the doc as the variant the quarantine
   path will add but is **not** built now (no unreachable variants,
   fail closed). `PeerFailed` is deleted by item F — under crash-only
   no caller survives a peer's abandonment to observe it — so the
   `Peer` struct is never built and `CallError` has exactly four
   variants: `Op(E) | Cancelled | DeadlineExceeded |
   NotAdmitted(Admission, args)`.
7. **Field visibility** (items G1–G3): 02 §2 gains M9-OO's parked
   sentence verbatim — "Struct fields are module-private unless `pub`;
   only the declaring module may construct, read, write, or
   pattern-bind a non-`pub` field." Split across three ordered items
   (M9 OO stopped on this blast radius; GOAL.md session rule): G1
   carries `is_pub` on `DeclField` and ships a non-failing violations
   census; G2 migrates packages with the census shrinking; G3 flips
   the census to `error[sema]`. Sealed construction becomes real,
   closing `library.time.instant-opaque` and unblocking items O, P, S
   (they depend on G3).
8. **`resource(manual)`** is the spelling for a resource struct that
   withholds its reclaim action: no generated reclaim exists, so
   every path must consume it (existing `check_protocol_consumption`
   machinery). Framed in 02 §3.1 as *declining the derived action* —
   the derivation rule ("no known reclaim action ⇒ consume on every
   path") is unchanged; the author merely withholds the action.
9. **`@discard(reason="...")`** is the spelling for deliberate error
   discard (statement attribute, string reason mandatory, 02 §13
   table). Second statement attribute after `@budget`; same placement
   rules.
10. **Inferred error sets spelling**: a *private* `fn` may write
    `-> Result[T]` (one-argument form, private signatures only); the
    compiler infers the exact error set from the closed world and
    typed dumps display it. `pub` still declares a nominal enum. The
    one item whose normative doc revision may be rejected at human
    review; if rejected, item K is recorded as rejected and nothing
    downstream is affected.
11. **The loop-discharge theorem** (frozen wording): *every `for`/
    `while` is discharged by a proven bound (`@budget`) or by
    observation: every path from the loop head to its back edge
    passes a vector-observation point.* An observation point is a
    direct read of the pending-vector page, a direct write of the
    park page (both recognized by placed address against the
    `wrela-machine` constants, never by name), or a call to a
    function whose inferred **observes** bit is set (computed
    transitively from those leaves, the same shape as
    comptime-legality inference). No function-name allowlist
    survives.
12. **Machine-v1 device set** (item D): blk, console, clock, entropy,
    input, display. net and sound move to future machine revisions.
    Drivers are stdlib + VMM deliverables built incrementally against
    the machine contract (06); the language chapters do not change
    per device — 03 is how drivers are written and is untouched by
    device-set scope.
13. **Scheduling semantics are the shipped semantics** (part of item
    C). 04 §2 is rewritten to state FIFO-per-mailbox +
    round-robin-across-ready-actors as *the* semantics, not the
    degenerate case of a band lattice. Bands, `must_service_within`,
    and priority/deadline inheritance become one recorded ROADMAP
    intention, purchasable only under the cleverness budget with a
    recording that shows a missed deadline — the scheduler is wrela
    source since M11, so the budget applies to it like everything
    else.

## Appendix — the ISR gate (decision package, not an item)

Human decision, prepared during this milestone, decided **before the
cycle-proxy milestone (M15) activates** (so the proxy never calibrates
on paths that may not survive). The proposal both reviews converged
on:

- Delete the user-visible ISR: a vector binding becomes a wake of the
  owning driver's bottom-half turn, serviced first in the checkpoint
  walk (an ordering fact, not a band — bands are gone after C.6). The
  runtime keeps checkpoint-granularity delivery (it already walks the
  vector words — item N makes that per-core); **pending-word
  consumption is the ack**, deleting the hot-path MMIO that currently
  contradicts 06 §5 ("MMIO exists only on setup/reset paths").
  `InterruptCell`, the ISR effect set, the masked-interval report
  line, and graph-changing `DriverMode` go with it — and C.7's
  deferred `@task(trigger=)`/`@task(poll=)` rows are decided here
  too; 03 §7's poll mode already demonstrates the concept's removal
  changes no observable semantics.
- Costs, measured before deciding: 56 goldens touch `InterruptCell`;
  `check_isr_effects` and its module references; chapter 03 §6
  rewrite. The latency cost is the gap between checkpoint granularity
  (user top-half today) and turn granularity (bottom-half-only) for
  device ack work specifically — measure max turn-boundary delay vs
  checkpoint interval on the existing `boot-actors` recording and
  attach the number.
- The evidence package is a REVIEW-QUEUE escalation in M11-L style,
  four items: (1) the two latency numbers above, (2) the golden
  inventory, (3) the 06 §5 tension + poll-mode argument, and (4)
  **M14's frozen upward-edge sentence** ("downward is a handle;
  upward is a resolution or a vector") — the gate must preserve or
  replace that rule when it respells the device→driver edge as a
  bottom-half wake; an ordering note, not a work dependency (M14
  freezes the answer space; the gate decides within it). Accept/reject
  spaces. If accepted it is its own milestone; nothing in *this*
  plan's ordered items depends on the outcome.

- **H/J payload tuples**: take-args beyond the current two scalar
  words (aggregates) need frame spill on the fail branch; the fail
  branch is cold, spill-everything is house style — but if an
  aggregate case cannot be constructed locally, fail closed with

  the item's oracle catches it, and the fallback is keeping the clear

  assertion that old and new agree over the corpus, then delete the
