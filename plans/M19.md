## Goal

Ship the **optimization harness** that uses M18's ruler — nothing else:

1. **Two compile modes** hardcoded in the compiler: `dev` (all named opts
   off) and `release` (all named opts on, fixed call order). Default
   product path is `release`.
2. **Proxy-only profitability.** Against the fixed cost corpus, a
   candidate pipeline vs the reference must **not raise any case's proxy
   total** and must **strictly lower at least one**. Score the **full
   pipeline in context** (convolution / pass order matter). Losers are
   deleted or reworked — not kept disabled "for later."
3. **Both modes stay correct** under existing oracles (`diff-eval`,
   goldens, validate). Semantics must not depend on opts.
4. **Smoke (two opts, for convolution):** (1) M18's bounds-elide, folded
   under `release`; (2) **narrow immediate materialization** — `FnCtx::
   load_imm` skips zero `MOVK` halfwords (codegen module doc today
   deliberately always emits MOVZ+3×MOVK; that naive form stays `dev`).
   Two opts so the win oracle exercises full-pipeline / order-in-context
   scoring; close reports corpus proxy drop `dev` → `release`. No third
   opt inventing theatre.
5. **No physical measurement in the loop.** Host wall-time / `profile` /
   `bench guest` A/B are out of process forever for opts. Optional
   offline research may retune `wrela-cost-v1` on suspected proxy
   misrank — ruler maintenance, not a land gate.

**One question:**

> Does this release pipeline (in this order) win on the cost corpus
> under `wrela-cost-v1` without raising any case — and do `dev` and
> `release` both stay semantically correct?

## Vocabulary (settled — do not blur)

| Term | Means |
| --- | --- |
| **`dev`** | Compile mode: every named opt off. Correctness reference. |
| **`release`** | Compile mode: every named opt on, fixed in-code order. Product default. |
| **Named opt** | Ordinary function in the compiler pipeline, skippable by mode. |
| **`BoundsElide`** | M18 capstone: literal in-range `[T; N]` index → `Project` (lower/FlowWir). |
| **`NarrowImm`** | Skip zero `MOVK` halfwords in `FnCtx::load_imm` (naive = always 4 words). Trampoline/reloc helpers that assume a fixed 4-word materialization stay naive. |
| **Release order** | The hardcoded sequence of named opts under `release` (proposed: BoundsElide then NarrowImm). |
| **Proxy win** | On the fixed cost corpus: no case rises in proxy total; ≥1 case strictly falls. Always scored **in context** of the full pipeline. |
| **Cost corpus** | The pinned `tests/golden/cost-*` cases (at plan write: `cost-arith`, `cost-calls`, `cost-bounds-elide`, `cost-runtime`). |
| **Physical** | Host wall-time / flame graphs / `bench guest` opt A/B — **out of process**. |

### Item B — `CompileMode` + in-code opt list

**Files:** Create `crates/wrela-compiler/src/opts.rs` (or `opt.rs`);
`lib.rs` `pub mod opts`.

**Shape (freeze 1402 / 1406):**

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum CompileMode {
    Dev,
    Release,
}

/// Fixed release order. Add opts here — nowhere else.
pub const RELEASE_OPTS: &[OptId] = &[
    OptId::BoundsElide,
    OptId::NarrowImm,
];

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum OptId {
    BoundsElide,
    NarrowImm,
}

pub fn apply_mode(mode: CompileMode) {
    let on = matches!(mode, CompileMode::Release);
    crate::lower::set_bounds_elide(on && RELEASE_OPTS.contains(&OptId::BoundsElide));
    crate::codegen::set_narrow_imm(on && RELEASE_OPTS.contains(&OptId::NarrowImm));
}
```

Keep it dumb: a `const` slice + a match, not a trait/plugin registry.
Order is part of the product: item E must be able to A/B a swapped
slice offline (edit + re-rank), not a searcher.

- [ ] Module + unit: `Dev` disables both; `Release` enables both in order.
- [ ] No new crate deps.

**Cheap:** `cargo test -p wrela-compiler --lib opts::`.
