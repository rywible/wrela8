## Goal

The standard library exists as **wrela source in `stdlib/`**, compiled by
the same pipeline as user code, dumped at every stage, and pinned by the
same goldens. The compiler stops carrying a hardcoded stand-in for it.
The normative chapters stop being lexer inputs and start being
type-checked ones, which is what makes ground-truth rule 1 ("if code
disagrees with the docs, the code is wrong") mechanical rather than
aspirational.

## The honest scope line (decide once)

IN: a `stdlib/core` that the compiler loads as ordinary wrela source, and
the loader path that finds it; the `Format` contract, `deriving(Format)`,
and f-strings with their summed `String[..N]` bound; `from` conversion
and `deriving(From)` as `?` consumes it; the collection surface of 05 §7
(`List`, `SlotMap` and its three-field key discipline, array
`map_take`/`try_map_take`, the two iteration forms); the time surface of
05 §5 (`Duration`, `Instant`, `now()` as a recorded effect); the
`ImageReport` reflection type and `@layout_assert` actually running;
deleting `sema/prelude.rs`; making the doc corpus sema-checked.

OUT (each fails closed, named, with the owner that would take it): SIMD
(05 §8.1 — a closed vector set and a NEON lowering contract, which is a
backend milestone's worth of work and is named by neither ROADMAP M9 nor
this plan's exit criteria); `race` (05 §4 — a sealed contract with
build-proven slot reservation and full loser teardown; `group` already
exists from M6 and `race` is not a stdlib type but a compiler contract);
`SlotMap.reserve()/slot.resolve()`'s turn-splitting service idiom (05 §4
— it generates a later turn, which is M10's runtime territory); a second
device family; runtime-in-wrela (M10); the cost contract (M11).

**Deliberately undecided until item C measures it:** whether
`Validated[F, T]` / `Secret[T]` (05 §6) land here. M8's carry-forward
table recorded them as "stdlib-era (ROADMAP M9)", but ROADMAP's own M9
paragraph does not name them and `values.marked.mechanism` rejects them
today. They are ordered as item G *after* `Format`, because `Secret` is
defined by having no `Format` and cannot be specified before `Format`
exists. If item G balloons past one session it splits per the
item-balloons rule, and the residue is named in the plan rather than
half-built.

## Shape decisions (frozen by goldens — decide once)

1. **The stdlib is wrela source, not a Rust table.** `stdlib/core/*.wr`
   is compiled by the ordinary pipeline. A stdlib type that cannot be
   written in wrela is a finding about the language, to be recorded and
   escalated in this plan — never a reason to reach back for a hardcoded
   entry. The exception set is exactly the intrinsics 05 §9 already names
   as compiler-recognized (`Image` and the builder surface), which are
   recognized *by name* in sema and whose surface may be declared in
   wrela without a body.
2. **The prelude becomes a loaded module, and then stops existing.**
   `sema/prelude.rs` is deleted in one commit, at the end, after every
   name it lists has a real definition. It is not whittled down in
   fifteen commits; a half-deleted prelude is two sources of truth.
3. **The corpus flip lands behind a flag first.** Per GOAL's standing
   risk note, which this plan restates so it is not rediscovered:
   sema-checking the docs will surface a batch of real doc/compiler
   disagreements at once, and a batch that size is exactly where
   ground-truth rule 1 gets quietly inverted to make the build green. So:
   land the flip off by default, fix each disagreement in its own small
   cited commit with the docs winning by default, and only then make
   corpus sema-checking mandatory in `check`. **Never `golden --update` a
   batch that has not been read case by case.**
4. **A doc/compiler disagreement is resolved in favour of the doc**
   unless the doc is internally inconsistent, in which case the tiebreak
   is GOAL's: prefer the reading consistent with the ledger and existing
   goldens, make the minimal doc fix, same-commit clause, REVIEW-QUEUE
   line. Every such fix is its own commit. The count of them is evidence
   and goes in the closing block.
5. **f-strings are bounded at build time or they are a build error.**
   05 §6: `f"..."` sums each operand's `max_formatted_len(spec)` into
   `String[..N]`. There is no dynamic fallback and no truncation; a
   `Format` implementation that cannot state a bound cannot be used in an
   f-string. `panic`'s formatter keeps its own fixed maximum and a
   message that cannot fit stays a build error.

## Numbered decisions

Shape decisions 1–5 above are frozen. Numbered decisions taken *during*
the milestone start at 6 and are appended here as they are taken. Per
the parallel-agent lesson from M8, every agent brief states the agent's
reserved decision-number block up front; two agents independently taking
"decision 12" cost a day in M8.

Reserved: 6–7 orchestrator (item A split); 8–15 item A1/A2; 16–23 item
B; 24–31 item C; 32–39 item D; 40–47 item E; 48–55 item F; **56–59 item
AA** (the intrinsic-surface closure guard); 60+ allocated at dispatch.

6. **A is split into A1 (imported types in type positions) and A2 (the
   stdlib is loaded).** See the starting-state measurement above.
7. **A2 moves a name with no special-casing; `Option` moves under item
   I.** See item A2's own note.
8. **The type namespace consumes imports through one raw-AST arity
   table.** `imports::declared_type_shapes`/`imported_type_shapes` build
   `local name -> generic-parameter count` from raw AST on *both* sides —
   this module's `import` statements and the exporting module's
   `struct`/`enum` headers. `types::declare_with_imports` merges it into
   its own `shapes` table and `bodies::build_module_ctx` merges it into
   `ModuleCtx::shapes`, which is the same table body annotations resolve
   against. Raw AST on both sides is the whole point: the table is
   complete before *any* module's `declare` runs, so no module's type
   table waits on another's and cycles stay free (`sema/mod.rs`'s splice
   note is preserved, not rewritten). Rejected: threading the exporting
   module's finished `DeclStruct` in, which would have ordered the
   modules and broken cycles outright.
9. **An imported type resolves to `Type::Named(<local name>)`** — the
   possibly-aliased spelling the author wrote, not a qualified path. It
   is the key the splice already installs in `ModuleCtx::structs`/`enums`,
   so there is one name table and one spelling, and the `check` dump keeps
   printing what the source says. Rejected: a qualified `mod.Type`
   spelling, which would have needed a second lookup path in every
   consumer of `Type::Named`.
10. **Data-vs-resource classification becomes a whole-closure pass.**
    A local struct with a field of an imported `resource`/`@actor` type is
    a resource, which no module-local pass can compute — and answering
    `Data` for a name it cannot see is a silent wrong answer, not a
    fail-closed one. `types::classify_closure` therefore recomputes every
    module's classification after the declare loop and before the splice,
    reusing the one existing algorithm with its memo/`in_progress` keyed
    `(module, name)`. Cycles are unaffected for the same reason the splice
    leaves them alone: this reads output that already exists. A by-value
    cycle closing across modules gets the same `is infinitely sized`
    diagnostic it already gets within one.
11. **The arity table is built over *specialized* modules, everywhere.**
    A `struct`/`enum` declared inside a module-level `comptime if` only
    exists once `specialize` has run, so a raw-AST table would list fewer
    type names than sema's does. Sema already had the specialized modules
    to hand; the post-sema backend re-derivations (`layout.rs`,
    `mwir.rs`) re-run `specialize` themselves — this file's own
    recompute-rather-than-thread convention — rather than being handed a
    thinner table. Found by probing: the raw-AST version accepted an
    imported `comptime if`-declared type at `--stage=check` and would
    have rejected the same program one layer down as a `LayoutError`.
    Two passes disagreeing about what type names exist is the failure
    this decision exists to prevent.
12. **`Actor[T]` and capability type arguments stay module-local.**
    `types::validate_actor_handles`/`validate_capability_types` still
    require `T` to name a struct declared in the same module; an imported
    `@actor` struct there is rejected, loudly, by the existing named
    diagnostic. Cross-module actor handles are a milestone question
    (02 §9.1 + M6's own scope), not something A1 opens as a side effect of
    a type-name table.
