## Goal

The standard library exists as **wrela source in `stdlib/`**, compiled by
the same pipeline as user code, dumped at every stage, and pinned by the
same goldens. The compiler stops carrying a hardcoded stand-in for it.
The normative chapters stop being lexer inputs and start being
type-checked ones, which is what makes ground-truth rule 1 ("if code
disagrees with the docs, the code is wrong") mechanical rather than
aspirational.

## The honest scope line (decide once)

IN: a `stdlib/core` that the compiler loads as ordinary wrela source, and
the loader path that finds it; the `Format` contract, `deriving(Format)`,
and f-strings with their summed `String[..N]` bound; `from` conversion
and `deriving(From)` as `?` consumes it; the collection surface of 05 §7
(`List`, `SlotMap` and its three-field key discipline, array
`map_take`/`try_map_take`, the two iteration forms); the time surface of
05 §5 (`Duration`, `Instant`, `now()` as a recorded effect); the
`ImageReport` reflection type and `@layout_assert` actually running;
deleting `sema/prelude.rs`; making the doc corpus sema-checked.

OUT (each fails closed, named, with the owner that would take it): SIMD
(05 §8.1 — a closed vector set and a NEON lowering contract, which is a
backend milestone's worth of work and is named by neither ROADMAP M9 nor
this plan's exit criteria); `race` (05 §4 — a sealed contract with
build-proven slot reservation and full loser teardown; `group` already
exists from M6 and `race` is not a stdlib type but a compiler contract);
`SlotMap.reserve()/slot.resolve()`'s turn-splitting service idiom (05 §4
— it generates a later turn, which is M10's runtime territory); a second
device family; runtime-in-wrela (M10); the cost contract (M11).

**Deliberately undecided until item C measures it:** whether
`Validated[F, T]` / `Secret[T]` (05 §6) land here. M8's carry-forward
table recorded them as "stdlib-era (ROADMAP M9)", but ROADMAP's own M9
paragraph does not name them and `values.marked.mechanism` rejects them
today. They are ordered as item G *after* `Format`, because `Secret` is
defined by having no `Format` and cannot be specified before `Format`
exists. If item G balloons past one session it splits per the
item-balloons rule, and the residue is named in the plan rather than
half-built.

## Shape decisions (frozen by goldens — decide once)

1. **The stdlib is wrela source, not a Rust table.** `stdlib/core/*.wr`
   is compiled by the ordinary pipeline. A stdlib type that cannot be
   written in wrela is a finding about the language, to be recorded and
   escalated in this plan — never a reason to reach back for a hardcoded
   entry. The exception set is exactly the intrinsics 05 §9 already names
   as compiler-recognized (`Image` and the builder surface), which are
   recognized *by name* in sema and whose surface may be declared in
   wrela without a body.
2. **The prelude becomes a loaded module, and then stops existing.**
   `sema/prelude.rs` is deleted in one commit, at the end, after every
   name it lists has a real definition. It is not whittled down in
   fifteen commits; a half-deleted prelude is two sources of truth.
3. **The corpus flip lands behind a flag first.** Per GOAL's standing
   risk note, which this plan restates so it is not rediscovered:
   sema-checking the docs will surface a batch of real doc/compiler
   disagreements at once, and a batch that size is exactly where
   ground-truth rule 1 gets quietly inverted to make the build green. So:
   land the flip off by default, fix each disagreement in its own small
   cited commit with the docs winning by default, and only then make
   corpus sema-checking mandatory in `check`. **Never `golden --update` a
   batch that has not been read case by case.**
4. **A doc/compiler disagreement is resolved in favour of the doc**
   unless the doc is internally inconsistent, in which case the tiebreak
   is GOAL's: prefer the reading consistent with the ledger and existing
   goldens, make the minimal doc fix, same-commit clause, REVIEW-QUEUE
   line. Every such fix is its own commit. The count of them is evidence
   and goes in the closing block.
5. **f-strings are bounded at build time or they are a build error.**
   05 §6: `f"..."` sums each operand's `max_formatted_len(spec)` into
   `String[..N]`. There is no dynamic fallback and no truncation; a
   `Format` implementation that cannot state a bound cannot be used in an
   f-string. `panic`'s formatter keeps its own fixed maximum and a
   message that cannot fit stays a build error.

## Numbered decisions

Shape decisions 1–5 above are frozen. Numbered decisions taken *during*
the milestone start at 6 and are appended here as they are taken. Per
the parallel-agent lesson from M8, every agent brief states the agent's
reserved decision-number block up front; two agents independently taking
"decision 12" cost a day in M8.

Reserved: 6–7 orchestrator (item A split); 8–15 item A1/A2 (A1 took
8–12, A1b took 13–15, so A2 draws from 77+); 16–23 item
B; 24–31 item C; 32–39 item D; 40–47 item E; 48–55 item F; **56–59 item
AA** (the intrinsic-surface closure guard); **60–67 item BB** (`?` at
comptime; BB took 60–63); **68–75 item CC** (non-receiver `mut`
write-back; CC took 68–75); **76 orchestrator** (CC's property golden);
77+ allocated at dispatch.

6. **A is split into A1 (imported types in type positions) and A2 (the
   stdlib is loaded).** See the starting-state measurement above.
7. **A2 moves a name with no special-casing; `Option` moves under item
   I.** See item A2's own note.
8. **The type namespace consumes imports through one raw-AST arity
   table.** `imports::declared_type_shapes`/`imported_type_shapes` build
   `local name -> generic-parameter count` from raw AST on *both* sides —
   this module's `import` statements and the exporting module's
   `struct`/`enum` headers. `types::declare_with_imports` merges it into
   its own `shapes` table and `bodies::build_module_ctx` merges it into
   `ModuleCtx::shapes`, which is the same table body annotations resolve
   against. Raw AST on both sides is the whole point: the table is
   complete before *any* module's `declare` runs, so no module's type
   table waits on another's and cycles stay free (`sema/mod.rs`'s splice
   note is preserved, not rewritten). Rejected: threading the exporting
   module's finished `DeclStruct` in, which would have ordered the
   modules and broken cycles outright.
9. **An imported type resolves to `Type::Named(<local name>)`** — the
   possibly-aliased spelling the author wrote, not a qualified path. It
   is the key the splice already installs in `ModuleCtx::structs`/`enums`,
   so there is one name table and one spelling, and the `check` dump keeps
   printing what the source says. Rejected: a qualified `mod.Type`
   spelling, which would have needed a second lookup path in every
   consumer of `Type::Named`.
10. **Data-vs-resource classification becomes a whole-closure pass.**
    A local struct with a field of an imported `resource`/`@actor` type is
    a resource, which no module-local pass can compute — and answering
    `Data` for a name it cannot see is a silent wrong answer, not a
    fail-closed one. `types::classify_closure` therefore recomputes every
    module's classification after the declare loop and before the splice,
    reusing the one existing algorithm with its memo/`in_progress` keyed
    `(module, name)`. Cycles are unaffected for the same reason the splice
    leaves them alone: this reads output that already exists. A by-value
    cycle closing across modules gets the same `is infinitely sized`
    diagnostic it already gets within one.
11. **The arity table is built over *specialized* modules, everywhere.**
    A `struct`/`enum` declared inside a module-level `comptime if` only
    exists once `specialize` has run, so a raw-AST table would list fewer
    type names than sema's does. Sema already had the specialized modules
    to hand; the post-sema backend re-derivations (`layout.rs`,
    `mwir.rs`) re-run `specialize` themselves — this file's own
    recompute-rather-than-thread convention — rather than being handed a
    thinner table. Found by probing: the raw-AST version accepted an
    imported `comptime if`-declared type at `--stage=check` and would
    have rejected the same program one layer down as a `LayoutError`.
    Two passes disagreeing about what type names exist is the failure
    this decision exists to prevent.
12. **`Actor[T]` and capability type arguments stay module-local.**
    `types::validate_actor_handles`/`validate_capability_types` still
    require `T` to name a struct declared in the same module; an imported
    `@actor` struct there is rejected, loudly, by the existing named
    diagnostic. Cross-module actor handles are a milestone question
    (02 §9.1 + M6's own scope), not something A1 opens as a side effect of
    a type-name table.
13. **The comptime evaluator gets one read-only imported-declaration
    window, keyed by local name.** `TypedProgram::imported`
    (`typed::ImportedDecls`) carries the `const`/`fn`/`struct`/`enum` a
    module imports, under the possibly-aliased spelling the typed tree
    already uses (decision 9), plus the exporter's instantiations.
    `sema::mod::splice_imported_decls` fills it *after* every module's
    own `bodies::check`/`generics::check` — read-only reuse of finished
    output, so no module's evaluation waits on another's and cycles stay
    free. Rejected: merging into `TypedProgram::consts`/`fns`/`structs`/
    `enums` directly, which `lower`/`flowwir_lower`/`layout`/`codegen`
    all iterate to emit each declaration exactly once — that would emit
    an imported fn once per importer.
14. **`eval::check_comptime` and the two `eval::legal` whole-program
    checks move to their own loop, after the splice.** They cannot run
    inside the per-module typing loop any more, because the splice needs
    every module's `TypedProgram` complete. The visible consequence is
    diagnostic *ordering* in a closure with errors in more than one
    module: the first diagnostic is now the earliest in pass order, then
    module order — which is what the single-module pipeline this mirrors
    already does. No existing golden moved.
15. **A1b makes the declarations a module *names* evaluable, and says
    so out loud for everything else.** The evaluator walks one
    `TypedProgram`'s flat name tables and has no notion of which module
    a body came from, so an imported body is evaluated against the
    *importing* module's tables. Two shapes follow. (a) A name only the
    exporting module has is absent: precomputed into
    `ImportedDecls::unresolvable` and reported by name
    (`err-import-comptime-private-decl`), never `internal error:`.
    (b) A name the exporter has *and the importer resolves differently*
    would silently resolve to the importer's — a wrong value, not a
    missing one — so a body-bearing splice from a shadowing module is
    **withheld**, turning it back into a named miss
    (`err-import-comptime-shadowed-decl`). Shadowing is tested by
    *value*, not by declaring module: `bodies::check` injects the six
    fixed prelude enums into every module, so every pair of modules in
    every build "declares" all six. Rejected: making the evaluator
    module-aware (evaluating each body against its own module's
    program), which is the real fix and changes every `eval::` entry
    point's signature — owned by A2, which is where the stdlib starts
    calling into itself. Also left standing: `eval::legal::classify`
    stays module-local, so M4 item B's pinned refusal of a cross-module
    callee *from an `@image` fn* is unchanged.
56. **The intrinsic surface is 44 keys, and all four `format!` sites are
    statically knowable.** The fear in item AA's own statement — that
    membership might depend on variables scattered through a
    10,000-line file — did not survive reading. Each of the four
    templated keys is bounded by a guard within a few lines of its
    construction site: `Image.{mname}` by `check_call_index`'s
    `mname == "device" || "pool" || "dma_pool"`; `Mmio.{op}` by
    `check_mmio_access`'s `if !matches!(op, "read" | "write")` early
    return; `InterruptCell.{method}` and `Image.{name}` by the match
    arms their construction sites sit inside. Census below.
57. **The guard is a cargo unit test over compiler *source*, not a
    golden.** There is no artifact to dump — the live set exists only
    while a program is being checked — so the honest oracle reads
    `sema/bodies.rs` as text (`include_str!`, so a missing file is a
    build error rather than an empty scan that passes). Rejected: a
    second hand-maintained table inside `bodies.rs` for the test to
    compare against, which is two sources of truth and exactly the
    silently-passing guard AA exists to avoid. The written-down list
    lives in `crates/wrela-compiler/src/sema/intrinsics.rs`, one place,
    justifications attached.
58. **Hand-resolved `format!` expansions are backed by locking the
    guard's source text.** Resolving a template's range by hand is a
    census act, not a mechanical one, so the closure test alone would
    not notice a *widened* guard (a fifth `InterruptCell` method added
    to its match arm produces a new key from an unchanged construction
    site). `FORMAT_KEY_SITES` therefore carries each bounding guard's
    exact source line and asserts it is present verbatim exactly once.
    Brittle to reformatting those four lines, deliberately: the
    failure is loud and says re-resolve the range.
59a. **The census keys on the weak marker and must classify every
    occurrence** (taken 2026-07-25 after the orchestrator's independent
    verification; numbered 59a rather than 60 to stay inside AA's
    reserved block — 60+ is still unallocated). Decision 57's scan
    matched the whole line `kind: TypedExprKind::Intrinsic {`, and the
    orchestrator evaded it three ways, each passing all six tests: a
    bare construction with no `kind:` prefix; a `kind:`-prefixed one
    with a path-qualified type; and — the serious one — a bare
    construction **inside `bodies.rs` itself**, a false negative in the
    primary closure test. Same class as the field-reorder hole AA had
    already closed, so it gets closed the same way.

    The scan now keys on `TypedExprKind::Intrinsic {` with any prefix
    and any qualification, takes each occurrence's brace-balanced field
    region, and classifies it: a `key:` bound to a string literal or a
    `format!` is a census entry; **no** `key:` is an ordinary pattern
    match and is ignored; a `key:` bound to anything else **panics**.
    That last arm is new surface coverage, not just a plugged hole — a
    key computed from a variable was previously invisible and is now a
    named failure.

    Rejected: the orchestrator's suggested whole-crate occurrence count
    (`occurrences == constructions + allowlisted non-constructions`).
    It closes the same three holes, but every pattern match on this node
    is a locked number, so any ordinary downstream work — a new `match`
    arm in `lower.rs`, exactly what item E and item H will write — bumps
    a count. A ratchet whose numbers get bumped routinely stops being
    read, and this file's whole purpose is being read. Classifying by
    structure costs ~60 more lines and churns only when someone writes a
    genuinely ambiguous site.
59. **The ledger may name a unit test as `unit:<fn name>`.** `xtask
    ledger` accepted only `tests/` paths and `xtask:<command>`, so a
    clause backed by a cargo test had no way to be marked `test`
    honestly. Added and verified mechanically (the function must exist
    under `crates/`), rather than marking the clause `gap` while a real
    guard runs on every `check`. Rejected: relocating the guard into
    `tests/` purely to satisfy the validator, which would move the
    census list away from the code it locks.
59b. **`unit:` requires the `#[test]` attribute, not merely a function
    of that name** (taken 2026-07-25, orchestrator's second review; same
    numbering reasoning as 59a). Decision 59's validator checked for
    `fn <name>(` anywhere under `crates/`, so `unit:main` — this
    workspace's own `xtask` entry point — satisfied a clause and counted
    it among the tested ones. The sibling reference type does not allow
    that: a `golden/foo` ref must exist as a real directory under
    `tests/`. A reference type satisfiable by a non-test lets a clause
    claim coverage it does not have, and the ledger is ground-truth
    rule 2 — the same silent-acceptance class item AA exists to prevent,
    one layer up, and it would have been inherited by every future
    `unit:` clause. The check now requires a literal `#[test]` followed,
    past whitespace only, by `fn <name>(`. Deliberately not an attribute
    parser: a test carrying a second attribute between the two
    (`#[should_panic]`) reports as missing, which is a false negative
    and the safe direction. Found by review, not by the author — worth
    recording because a new mechanism's *own* first use is exactly where
    nobody looks for the weakness.
59c. **A commented-out `#[test]` does not satisfy a `unit:` ref** (taken
    2026-07-25, orchestrator, third review — fixed in the orchestrator's
    own hands rather than a fourth round trip, since it is one
    condition). 59b's check is textual, and a textual scan is happy to
    find `#[test]` inside `// #[test]`. Measured: a `// #[test]`
    directly above `fn orch_fake2()` satisfied the clause and
    `cargo xtask ledger` reported `141 clause(s), 132 tested` clean.
    This is the *realistic* version of the 59b hole rather than the
    contrived one — commenting out an attribute is the ordinary way to
    disable a flaky test, and doing so would have silently left every
    clause citing it counted as covered. The check now walks back to
    the line start and rejects a `//` before the attribute. A
    `/* #[test] */` block comment was already rejected, but for an
    unrelated reason (the `*/` breaks the whitespace-only run) —
    verified rather than assumed. Residue unchanged from 59b.

    The pattern across 59, 59b and 59c is worth stating once: each
    check was verified against the failure its author had in mind (a
    typo, then a wrong-kind name, then a missing attribute) and fell to
    the one they had not. That is an argument for adversarial review of
    new oracles specifically, not for distrusting this one.
60. **`?`'s success arm is decided by the operand's static type, never
    by the variant index.** `eval::value` numbers both builtin sums from
    zero, so an index carries no information about *which* sum it came
    from: index 0 is `None` in one and `Ok` in the other, index 1 is
    `Some` in one and `Err` in the other. `eval::interp`'s `Try` arm now
    reads `inner.ty` — `sema::bodies::check_try` has already proved it
    is exactly `Option[T]` or `Result[T, E]` *and* that the enclosing fn
    returns the same sum — and anything else there is a named internal
    error rather than a guess. The two `payload.pop().expect(...)` calls
    became fail-closed `abandon`s in the same edit; a panic is not a
    diagnostic. Rejected: A1b's own suggestion of branching on
    `expr.ty`, evaluated rather than adopted — `expr.ty` is the
    *success* type (`u32` for a `Result[u32, u32]`) and cannot
    distinguish the two sums at all. The suggestion was right about
    where to look and wrong about which field.
61. **A missing `from` conversion is a named gap, not an `internal
    error:`.** Nothing generates a `from` method for `deriving(From)`
    (item B owns that), and `from` is a reserved word, so no user can
    declare one either — which means *every* `?` needing a conversion
    reaches the evaluator with no body to call, from ordinary source.
    It said `internal error: `from` conversion `WrapError.from` not
    found`; by house rule an `internal error:` is a bug report, not a
    diagnostic. It now fails closed by name and cites item B, matching
    what the backend has always said for the same shape. Pinned as
    `err-try-from-underived`, which stops being an `err-` case when B
    lands — the intended signal. Rejected: rejecting the shape in sema
    instead, which would have re-pinned `check-bodies` (its
    `convert_wrapped` is a legal program under 02 §7.5, merely one this
    compiler cannot finish yet) and taken a decision that belongs to B.
62. **The eval fuzz lane treats an `"internal error: "` message as a
    bug, like every other lane.** CLAUDE.md describes all lanes as
    checking this and the `lower`/`async` lanes have since M7 — the
    latter's own doc comment names `eval/interp.rs`'s ~50 such guards as
    the class it exists to falsify — but the lane that actually
    *evaluates* comptime code never did: a `check_typed` `Err` passed as
    long as its category was in the fixed set, and an `internal error:`
    inside a `@test`'s `FAILED` verdict passed as long as the line was
    well-formed. Decision 61's diagnostic is exactly what it would have
    shrugged at. `eval_outcome_carries_no_internal_error` checks all
    three surfaces an abandonment can reach, reusing the identical
    `starts_with` rule rather than growing a second mechanism. Rejected:
    building a new lane or a new generator for `?`-shaped programs —
    item BB's four `check-try-*` goldens are single-file `input.wr`
    cases and are therefore fuzz seeds from the commit they land in,
    which is the honest fix for a seeding gap (see the item's own "why
    fuzz missed it").
63. **The backend was already right, and the divergence is recorded
    against `compiler.eval.matches-backend` rather than only against the
    new clause.** Both lowering paths destructure the operand's
    `Type::Result` before comparing the tag, and reject `Option`
    outright by name — so `?` on `Result` has always lowered correctly
    and `?` on `Option` has never lowered at all. `xtask diff-eval`
    exists for exactly this class of divergence and reported full
    agreement every run, because no golden carried a comptime-legal
    `@test` whose evaluation crossed a *failing* `?`: an oracle over a
    corpus is exactly as strong as the corpus, and "N tests agree" is
    evidence about the N. That sentence is now in the clause's own note,
    where the next reader of `diff-eval`'s output will meet it.
68. **`run_call` hands back every non-receiver `mut` parameter's final
    value; write-back is the call site's job.** `CallOutcome` carries
    `mut_params: Vec<(usize, Value)>` (param index, final value) alongside
    `final_self`. `eval_call` writes each into the matching call-site
    place through the existing `place_mut`. Rejected: mutating the
    caller's place in place during the call (aliasing the callee frame
    into the caller env), which would make the interpreter's frame model
    disagree with the backend's copy-in/copy-out ABI and bury the
    mirroring rule inside `bind_params`.
69. **A defaulted `mut` argument fails closed by name.** Eliding a `mut`
    parameter that has a default leaves no call-site place to mirror
    into; silently dropping the write-back is the defect this item
    exists to close, and inventing a temporary place would make the
    mutation unobservable — both wrong. Diagnostic:
    `writing back \`mut\` parameter \`<name>\` through a defaulted
    argument is not supported`. Rejected: rejecting defaulted `mut`

    not require and would break any source that already writes one.

    should be unreachable.

    two fields for one rule, and the dump would have two spellings for
    the same fact.

    closed by name.** Only a bare local is addressable today — matching

    writing that back, which would leave the real place untouched and
    reintroduce the silent-drop defect under a different spelling.

    `write_backs`. The callee prologue copies in and saves the pointer;

76. **A merge review that finds no defect lands its probe as a golden**
    (orchestrator, 2026-07-25, verifying item CC). The ten shapes written
    to attack CC's write-back mechanism all passed, and all ten agreed
    across both tiers under `diff-eval`. The tempting conclusion is that
    they were therefore not worth keeping. The opposite is true: they are
    a two-tier lock on properties nothing else in the corpus states —
    that a callee which never assigns its `mut` parameter does not
    clobber it, that an early `return` before the assignment does not
    publish it, that a `defer` after it is included, that two `mut`
    parameters do not cross-write, and that an unassigned sibling field
    survives. Those are exactly the properties a later optimization of
    the write-back path would break, and CC's own cases would not catch
    any of them. So `check-mut-param-properties` lands, and the standing
    rule is: **a review probe that survives is coverage, not a receipt.**
    Rejected: recording the probe's ten shapes in this file as prose
    only, which is a description of a test rather than a test, and which
    the next person to touch `write_backs` would never run.
