**Status: ACTIVE.**

First deliverable of the milestone, per the planning convention. The docs
carry the substance — [03-hardware.md](../docs/language/03-hardware.md) in
full (§1 capabilities, §2 typed MMIO, §3 DMA, §4 queues, §5 receipts, §6

[05-library.md](../docs/language/05-library.md) §9 (`img.device`,
`img.driver`, `img.pool`) — and [ROADMAP.md](../ROADMAP.md) M7: "virtio-blk
model in the VMM + the stdlib driver: capabilities, queues, receipts, DMA
ownership, reset — chapter 03 end to end on one device. Opens: `hardware.*`
clauses."

`hardware.*` has **zero** clauses today. Every one is opened here.

## Goal

A wrela image reads and writes real blocks. The stdlib ships a `@driver`
struct written in the safe language under chapter 03's rules; the VMM ships
the virtio-blk device model that is its other half; and a `@test(runtime)`
image publishes an operation, awaits a receipt, gets its payload back with
a completion status, and survives a reset — all pinned as boot transcripts
on Hypervisor.framework, all byte-identical across repeat boots and
replayable from a choice sequence.

## The honest scope line (decide once)

M7 is **one device, end to end**, not chapter 03 in the abstract.

IN: `DeviceCap[D]`/`Mmio[L]`/`IrqCap[V]`/`DmaPool[P, N]` as unforgeable
capability types minted only at image binding, with transitive provenance
checking; `@layout(mmio|dma|wire)` with `@offset`, `ReadOnly`/`WriteOnly`,
and the compiler's exact size/offset/padding/endianness report; volatile
typed MMIO on setup/reset paths; real image-declared DMA pools
(`img.pool`), `own[P] T` transfer payloads and `DmaShared[P, L]` control
memory; split-ring queue operations as sealed APIs carrying the normative
order; `reserve_proven`'s whole-image capacity proof; `Receipt[P]`'s
four-state machine and the handoff calling convention; vector binding from
the image graph with the ISR effect restriction and `InterruptCell[T]`;
the bottom-half task; `Untrusted[T]` checked-narrowing on device control
values; the virtio-blk bring-up chain and per-queue reset with epochs;
the virtio-blk device model in the VMM; device-completion timing joining
the recorded choice sequence.

OUT (each fails closed, named, with the plan item that would own it):
every other device in 06 §6 — `net`, `input`, `console` as a driver (the
existing console ring stays exactly as M5 built it), `entropy`, `sound`,
`display` (M9); `Validated[F, T]` and `Secret[T]` (03 §8's other two
marked-value policies — only `Untrusted[T]` is needed to read a block);
hybrid IRQ/poll *policy* libraries (03 §7 says these are library code);
`race` (still sealed, unchanged since M6); multicore placement and
`core=` ≠ 0 (M8 — the driver and its bottom half live on core 0);
supervision *restart* mechanics (still M8+; an M7 driver fault stays
image-fatal with a diagnosable line, as M6 decision 12 established);
IOMMU mapping (the flagship host has none — pools are host-mapped
directly, recorded not silently assumed).

## Shape decisions (frozen by goldens — decide once)

1. **The reply transport widens first (item Z).** M6-H1 established that a
   turn record carries ONE scalar reply word, and an aggregate reply is
   rejected at declaration. Chapter 03 breaks that immediately: 03 §5's
   handoff convention is *defined* by the signature `take p: P ->
   Receipt[P]`, and `Result[unit, BootError]`-returning transitions are
   everywhere in §9's bring-up chain. So the transport grows before any
   03 work lands: the turn record carries a pointer to a caller-owned,
   statically sized reply slot (everything here is statically sized —
   the compiler already computes every frame and mailbox), and H1's rule
   relaxes from "must be one scalar word" to "must fit the declared reply
   slot". **Rejected alternative**: special-casing `Receipt[P]` through
   the handoff convention alone, on the reading that 03 §5's receipt is
   installed caller-side *before* the handler runs and therefore never
   travels back through the reply word at all. That reading is correct
   and worth keeping in mind, but it fixes exactly one type and leaves
   every `Result[T, E]`-returning driver method still rejected — a
   special case standing in for a mechanism, which is the shape doctrine
   tells us not to build.
2. **Virtio stays, and M7 buys the option to leave it later.** 06 §6 is
   normative: the device set is virtio-family. Independently, most of
   virtio is *already* deleted from this machine — no GIC (06 §4), no
   trapping notification (§5), no discovery (§3), and a bespoke display
   path (§7); what remains is the split ring, feature negotiation, and
   the per-device request formats. Three consequences are frozen here:
   (a) the QEMU bootstrap implementation (06 §1, scheduled for
   retirement) is used as a **differential oracle** for ring handling
   while it still exists — the one thing that gets permanently harder
   later, since a bespoke ring would have no second implementation to
   disagree with; (b) 03 §2's seam between the sealed transport protocol
   and the driver stays sharp, because that is exactly where a bespoke
   ring would swap in; (c) the report emits the numbers that would decide
   it — descriptors per operation, queue occupancy, expected exits per
   operation (06 §5 already promises the exit-rate line). **Rejected
   alternative**: designing a bespoke single-slot ring now (one
   `@layout(dma)` request with an inline status word, identity
   `(slot, generation)`, no descriptor chaining). It is very likely
   simpler and it deletes a whole class of stale/duplicate/unknown-ID
   validation — but it is a performance-and-simplicity claim, and the
   cleverness budget requires a profile on a replayable workload before
   one lands. M7's device is also the worst case to decide on: storage
   operations are tens of microseconds, so ring bookkeeping is noise
   there in a way it would not be for `net` or `sound`. M7 produces the
   workload; the decision belongs to whoever has it.
3. **Capabilities are checked where `Actor[T]` already is.** 03 §1's
   rules ("`@actor` structs cannot hold capabilities in fields,
   parameters, messages, or captures") are the same *shape* as M6-A's
   `validate_actor_handles`/`validate_message_shape` post-declare pass,
   over a different type set. Extend that pass; do not build a second
   mechanism. Provenance ("a function that touches MMIO, DMA, or IRQ
   state must be reachable through the owning driver's authority") is
   the same whole-graph reachability `eval::legal::classify` already
   computes for comptime legality — reuse its shape, a second color.
4. **`@layout` reports exact bytes or fails.** No implicit padding, no
   target-dependent field, no inference. `wrela dump --stage=layout-types`
   (name TBD in item B) prints size/offsets/padding/endianness for every
   `@layout` type before any driver uses one, golden-covered, per the
   house rule that every stage gets a dump before it gets features.
5. **DMA pools are the only device-reachable memory, and they are
   host-mapped.** The flagship host has no IOMMU, so "targets with an
   IOMMU map only those pools" degenerates to "the VMM maps exactly the
   declared pools and nothing else." Recorded rather than silently
   assumed, because it is a *security* property on the flagship: the
   device model can reach declared pool pages and no other guest memory,
   enforced by what the VMM maps.
6. **`reserve_proven` is the send proof's shape, one milestone on.** M6's
   `sema::send_proof` proves static admission against a declared mailbox
   bound. 03 §4's `reserve_proven` proves static descriptor capacity
   against a declared queue depth. Same analysis shape, same fail-closed
   floor, same "if the proof is too weak to ever fire, say so" honesty.
   Runtime backpressure (03 §4's generated proxy) is item G, separate.
7. **Device completions join the choice sequence.** ROADMAP's recorded
   design constraint names "cross-core admission order plus device
   completion timing" as the machine's only scheduling nondeterminism.
   M6 shipped the `ChoiceEntry` format with `ClockRead`/`DeadlineWake`/
   `VectorRaise`/`Admission`; M7 adds the completion choice, and the
   recorder's format-only `Admission` tag stays format-only until M8.
8. **One driver fault story, unchanged.** M6 decision 12 made an actor
   abandon image-fatal with a diagnosable line; a driver fault is the
   same at M7. 03 §9's quarantine/recovery path and the supervision
   *restart* runtime are M8+. Named, not silently absent.

### Z. Reply transport (decision 1)

The one thing M6 knowingly left in M7's path. Turn records grow a reply
slot pointer; `sema::types`' one-scalar-word rule relaxes to "fits the
declared reply slot"; `golden/err-actor-reply-aggregate` is *replaced* by
a golden proving an aggregate reply now arrives intact — including the
exact shape that was silently wrong before M6-H1
(`Result[u64, FsError]`, both paths, hand-computed values). Nothing in 03
may land before this is green, because every 03 signature depends on it.

### Y. The async fuzz lane

`attempt_layout`'s own doc comment has disclosed since M6-D that the lower
lane never calls `flowwir_lower`, so the async pipeline has **no fuzz
coverage at all**. M6's item-H sweep found a `check_typed`-accepted program
reaching an `internal error:` guard that 2,000,000 iterations × 3 seeds
could not, precisely because of this hole. M7 adds far more async surface
(every driver API is one), so the lane lands before the surface grows,
not after. Same invariants as the sync lane: no panic, deterministic,
rejections in the fixed category set, `"internal error: "` is a bug.

### A–H

Each item: goldens named before code, the ledger clauses it opens listed,
fail-closed arms for everything not yet reached, and a real HVF boot as
the behavioral oracle wherever the item produces guest-visible behavior
(M5/M6 both proved that dump review alone misses register-level bugs —
`enc_umulh`, the x30 save, the `Actor[T]` aggregate misclassification, the
lineage stride, the signed deadline compare were every one of them found
only by running).

### I. Sweep + soak + finalization

Adversarial sweep over: capability forgery attempts, layout aliasing,
DMA ownership after publish, receipt double-resolve and drop, ISR effect
escapes, untrusted values reaching an index unchecked, reset with work in
flight, and completion IDs that are stale/duplicate/unknown. Deep soak
every live lane at its deep default on 3+ fresh seeds. Exit audit,
evidence block, mark complete.

## Non-goals (M8+ territory)

Everything the honest-scope line lists as OUT, plus: no second device of
any kind, no multicore anything, no restart/supervision runtime, no
partial-order reduction or schedule exploration (the coverage pass still
owns it), no bespoke replacement for the split ring without the profile
decision 2 requires, no `@latency_assert` (ROADMAP's recorded intention —
human-gated), and no display work whatsoever.
