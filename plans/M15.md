## Goal

An image authors `Image(..., cores=N?)` (default 1). The compiler packs
actors into `0 .. N-1`, the report seals N and per-core stacks, and the
VMM creates N vCPUs. Stage 1 keeps M8's baton so existing oracles stay
honest. Stage 2 deletes the baton (true overlapping `hv_vcpu_run`),
emits inlined publish/acquire DMBs on cross-core rings, records
Yield-order as enumerable `Progress` choices so replay stays a function
of the log, and flips `machine.cross-core.publish-acquire-barrier` on a
golden that fails when those barriers are deleted under concurrency.
No schedule model checker in this rung.

## Dumbness / maintainability / performance (review, 2026-07-27)

This rung buys real parallel throughput. That does **not** license clever
VMM scheduling, a model checker, or hot-path call overhead. The cuts
below revise the first draft of this plan; shape decisions follow.

| Temptation | Why it fails the doctrine | What we do instead |
| --- | --- | --- |
| `ChoiceEntry::Progress` on every exit | Log grows with host noise; two truths for "what is a choice" | Progress **only at Yield** (park / release) — the same sites the baton already used |
| Full `ChooserMode::Enumerate` over Progress×Admission×Device (old item J) | That is a model checker; M6 deferred schedule exploration on purpose | **Cut item J from this rung.** Replay injects Yield order from Progress; `xtask repro` tamper stays. Exhaustive schedule search stays the named later intention |
| Floor stub + `BL` for every DMB | Correct but slow: BL+DMB+RET on every cross-core publish/drain — the path this rung exists to unlock | **Inline one DMB word** via a runtime-only intrinsic (decision 6) |
| Permanent `WRELA_VMM_BATON=1` second scheduler | Two schedulers forever; bitrot | Baton dies in item I. Barrier control is mutation-under-overlap only; no kept-around serial path |
| Keep `VCPUS` as alias of `CORE_SLOTS` | Two names for one fact | **Delete `VCPUS`.** Bring-up count = report N; packing ceiling = `CORE_SLOTS` |
| Guest loops over `CORE_SLOTS` | O(32) scans on a 1-core image | Algorithms keep indexing **`N_CORES`**; `CORE_SLOTS` is array capacity only |
| Lock-free VMM shared state | Cleverness without a profile | One mutex (or today's Shared lock) around host bookkeeping; guest rings stay SPSC + DMB |
| Growing low stacks / moving `IMAGE_BASE` | Golden churn, no guest win | High-DRAM stacks (already settled) |

**Perf honesty (no cleverness budget spend).** Expected costs that are
*correctness*, not opts: one `DMB ISHST` per cross-core publish, one
`DMB ISHLD` per drained slot (or once per drain burst — item H freezes
**once per slot**, the obvious place). Overlapping `hv_vcpu_run` is the
throughput win; do not pre-optimize the scheduler, ready queue, or
jump tables (M16/M17). Item L records `bench guest` deltas and does
not chase them.

**Maintainability rules for agents.** Prefer long obvious edits in the
files that already own the behavior (`placement.rs`, `boot.rs`,
`runtime.wr`, `record.rs`). Do not add a "multicore subsystem" crate,
a scheduler trait, or a barrier plugin. One machine, one backend.

## Shape decisions this milestone freezes (do not relitigate mid-item)

Decision numbers: this plan reserves **1000–1099**.

1. **`cores=` is an `Image` argument, default 1.** Spelling:
   `Image(name=..., target=..., cores=N?)` with `N` a comptime `usize`
   ≥ 1. Omitting `cores` ⇒ `N = 1` (today's single-core floor). Not a
   machine revision. Unknown `Image(...)` labels become a build error
   in the same item that parses `cores` (stop the silent-drop hole).
2. **Placement domain is exactly `0 .. N-1`.** Explicit pins first;
   `core ≥ N` → build error; unfixed pack by work→bytes→identity as
   today. The binary floor `{0}` vs `VCPUS` is deleted. A pin or
   cross-core edge that needs a core outside `0 .. N-1` fails closed
   (including `cores=1` + `core=1`).
3. **No published `VCPUS_MAX`; delete `VCPUS`.** Soft page-packing
   ceiling **`CORE_SLOTS = 32`**: machine-info `core_marks` and
   pending-word array lengths (fits `0x68 .. 0x200` without moving
   `vector0_observed @ 0x200`: `0x68 + 32*8 = 0x168`). Seal refuses
   `N > CORE_SLOTS` with a diagnostic naming the packing ceiling — same
   shape as `RTDATA_SIZE_MAX`, **not** "the machine has 32 cores."
   VMM additionally refuses when the host cannot create N vCPUs.
   Bring-up count is **only** the report's `Cores count=N`.
4. **Stacks are report-owned in high DRAM; `IMAGE_BASE` stays.**
   ```
   DRAM_END = DRAM_BASE + DRAM_SIZE          # 0x8000_0000
   core_stack_base(n, N) = DRAM_END - (N - n) * CORE_STACK_SIZE
   ```
   Report grows:
   ```
   Cores count=N
   CoreStack core=k base=0x... size=0x100000   # one line per core, k=0..N-1
   ```
   Low `STACKS_BASE` region is retired from the live map (reserved
   padding below `IMAGE_BASE`); do **not** move `IMAGE_BASE` /
   `RTDATA_BASE`. Delete `wrela_machine::VCPUS` in the same commit that
   introduces `CORE_SLOTS` (grep-clean; no alias).
5. **Stage gate: do not close after stage 1.** Stage 1 may land and
   turn CI green under the baton; the milestone's exit criterion still
   requires stage 2. Claiming "parallel throughput" in stage 1 is a
   plan violation. After item I the baton code path is **deleted**, not
   feature-flagged.
6. **Barriers are one inlined instruction, runtime-only.** Add
   `enc_dmb_ishst` / `enc_dmb_ishld` in `encode.rs`. Surface: a
   compiler-recognized intrinsic (spelling frozen in item H, e.g.
   `@dmb(ishst)` / `@dmb(ishld)`) **legal only inside
   `stdlib/core/runtime.wr`** (sema refuse elsewhere — closed surface,
   same spirit as other runtime-only facts). Lowers to **exactly one
   DMB word, no BL/RET**. Call sites: xsend/xreply after `count` store
   and before pending raise; drain after observing `count != 0` and
   before payload loads — **one DMB per drained slot** (dumb, local,
   obviously matched to the load). **Rejected:** `@naked`;
   user/app-visible fences; floor stub + BL (correct but hot-path
   tax); full `DMB SY` when ISHST/ISHLD suffice.
7. **Record overlaps; replay serializes from Yield-`Progress` only.**
   New `ChoiceEntry::Progress { core: u32 }` appended **only** at the
   guest actions that today move the baton: **release** and **park**
   (Yield). Not on every exit, not on every Admission. **Record:**
   overlapping `hv_vcpu_run`; Progress at Yield + existing
   Admission/Device/Clock tags. **Replay:** serial hand-off where
   `next_core` is forced by the next Progress entry; mismatch → named
   divergence. Guest-visible scheduling nondeterminism remains what
   06 §8 already names (admission + device timing); Progress exists
   so replay is a function of the log, not the host. Opaque
   host-scheduler traces stay rejected.
8. **Admission stays a witness; no schedule enumerator in M15.**
   Under overlap, retire `AdmissionWitness`'s "exact Δcount / one core
   ran" rule. Record still appends `Admission` in observed drain order;
   replay checks it under Progress-serialized execution. **Item J
   (enumerate alternate schedules) is cut** — it is the M6 "later
   milestone" schedule explorer, not required to flip the barrier
   clause once Progress replay + concurrent record + DMB mutation
   exist. Retarget the barrier clause note: "interleaving enumerator"
   → "Yield-`Progress` makes the concurrent schedule enumerable for
   replay; exhaustive exploration remains a later intention."
9. **Barrier flip golden is a mutation test under concurrent record.**
   `boot-cross-core-publish-acquire`: intact DMBs → `ok` under overlap;
   DMBs NOPped/omitted → guest-visible failure (stale payload /
   checksum) under overlap within one boot's amplified loop (not a
   flaky host stress harness). **No permanent baton flag** for the
   control arm — the discrimination is "mutation fails under overlap";
   optionally a *compile-time unit test* that the same guest binary's
   reordering window is real, not a second VMM scheduler.

## Verification policy (cheap per item; expensive at close)

`cargo xtask check` is the gate — fmt, all tests, **all** goldens
(including HVF boots), corpus, fuzz smoke, ledger, repro lanes. It is
**too expensive to run after every item.** This rung splits verification:

| Lane | When | What |
| --- | --- | --- |
| **Cheap (required per item)** | Before that item's commit | Unit tests + dumps for **new/changed** behavior only; no full golden suite; no deep fuzz; no `bench guest` |
| **Focused boot (only if the item claims HVF)** | Before that item's commit | Run **the one or two boot goldens the item names**, via `wrela` + `wrela-vmm` on those paths alone — not the whole `boot-*` corpus |
| **Expensive (item L only)** | Milestone close | Full `cargo xtask check`; deep fuzz (all lanes, 3+ seeds); `bench guest` deltas; full `xtask repro` / `diff-eval` as check already wires them |

**Cheap recipes (agents use these, not `xtask check`):**

```bash
# Unit filter (pick the crate the item touched)
cargo test -p wrela-machine --lib <filter>
cargo test -p wrela-compiler --lib <filter>
cargo test -p wrela-vmm --lib <filter>

# One non-boot golden: build wrela, dump/build the case, diff expected/
cargo build -q -p wrela-compiler --bin wrela
./target/debug/wrela dump --stage=<image|check|rtconfig|report|asm> \
  tests/golden/<case>/input.wr | diff -u tests/golden/<case>/expected/<stage>.txt -

# Docs-only items
cargo xtask corpus          # or corpus --sema when relevant
cargo xtask ledger

# Focused boot (items F/G/I/K only — named cases)
cargo build -q -p wrela-compiler --bin wrela
# build image + boot with wrela-vmm for that case only (same shape the
# golden runner uses; do not loop every boot-*)
```

**Rules:**

1. Every item's **Cheap** oracle must fail if the new behavior is wrong
   and pass when it is right — a green unit filter that never touches
   the new code is not an oracle.
2. Do **not** run full `cargo xtask check` or deep fuzz on items 0–K.
   Drift in untouched goldens is item L's job (and the reason L exists).
3. Items that **move** a large golden surface (D's report blast) update
   the expected files in that commit and cheap-verify with **dump/report
   on a representative sample plus unit tests**; the full report corpus
   is re-checked at L. If D's sample misses a class, L fails — fix
   forward, do not silently re-baton.
4. Stage-1 items still owe **byte-identical transcripts** for
   single-core controls they claim — verify that claim on the **named**
   control case in Cheap/Focused, not by replaying the entire suite.
5. Item L is not optional. The rung is not COMPLETE until the expensive
   lane is green.
