## Goal

Make the wire surface real and make schema evolution safe **before** anything
writes bytes that have to be read by a later build.

1. `@layout(wire)` works on **enums**, with a frozen tag-plus-padded-payload
   encoding — the shape an event type needs (S4).
2. Variant tags are **compiler-assigned and lockfile-pinned**, so reordering
   an enum can never silently reinterpret history (S15).
3. `Bytes.read_wire[W]` exists — 05 §6 has specified it since revision 0.1
   with **zero implementation**.
4. A committed **`wire.lock`** with `greenfield` / `production` migration
   dispositions, so a format break is a reviewed diff rather than an emergent
   property of a source edit.
5. FNV-1a in the stdlib; the `db` package alias.

**Why this is its own rung, ahead of any storage.** Retrofitting tag
stability onto a format that already shipped is the exact failure the
lockfile exists to prevent (S15). The lockfile cannot arrive after the log.

## Vocabulary (settled — do not blur)

| Term | Means |
| --- | --- |
| **Wire type** | A `@layout(wire)` struct **or enum** — exact bytes, target-independent, no capability inside (03 §3). |
| **Tag** | The `u32` discriminant of a wire enum variant. Compiler-assigned, lockfile-pinned, never reused. |
| **`wire.lock`** | The committed build-time record of every wire type's shape and every tag assignment. **Not** a package lockfile (02 §2.1) and **not** the disk superblock (a runtime artifact, M23). |
| **Disposition** | The author's declaration that a breaking schema change is intended: `greenfield` (no data worth keeping) or `production` (real data; preservation required). |

## Shape decisions this milestone freezes (do not relitigate mid-item)

Decision numbers: this plan reserves **1800–1899**.

1. **(1810) Wire enum encoding.** `tag: u32` at offset 0; **4 bytes reserved
   zero padding**; variant payload at offset **8**; total size
   `8 + max_over_variants(payload_size)`, rounded up to 8. Payload at 8 keeps
   natural alignment for every scalar including `u64`, so no variant needs
   internal shifting. Unused payload bytes are **zero**, not undefined —
   required for reproducible bytes and so a checksum over the whole extent is
   deterministic (M23 depends on this; freeze it here).
2. **(1811) Tag 0 is reserved and never assigned.** A zero-filled extent
   therefore decodes as an invalid tag rather than as variant #0. This is a
   safety property, not a convention: at M23 an unwritten sector must not
   read as a valid event.
3. **(1812) `wire.lock` is not a package lockfile.** It records *schema*, not
   dependencies; 02 §2.1's "no lockfile" remains true of package acquisition
   and item A says so explicitly. One file per build root, named `wire.lock`,
   sited beside the root source file (02 §2.1's build root is already the
   anchor — no manifest is introduced).
4. **(1813) Lockfile format is TOML, fully sorted.** Sorted by module path,
   then type name, then tag. Deterministic emission is a hard requirement,
   not a nicety: this file is a review surface and a spurious diff destroys
   its value. Mirrors `ledger/ledger.toml`'s role and format.
5. **(1814) Tags are compiler-assigned, ascending from 1**, in declaration
   order at the moment a variant *first* appears. Thereafter the lockfile is
   authoritative and declaration order is irrelevant. Reordering an enum
   produces **no diff**.
6. **(1815) A retired tag is never reused.** The lockfile retains retired
   entries with `retired = true`. Reuse is a build error naming the original
   type and the release that retired it.
7. **(1816) The compiler auto-writes only *additive* lockfile changes**
   (a new type, a new variant, a new tag). Any change that alters an existing
   type's bytes — field added/removed/reordered/resized, tag reuse, encoding
   change — is refused unless the author has **hand-edited** the lockfile to
   bump that type's `format_version` and declare `disposition`. The friction
   is the mechanism: a format break must be a deliberate tracked-file edit.
8. **(1817) Two dispositions only.** `greenfield` — permitted freely, means
   "no data worth keeping"; `production` — requires a `preserves = "..."`
   note naming how existing data survives, which the compiler stores and does
   not interpret. There is no third mode and no migration engine (S15).
9. **(1818) `WireError` is a closed set**: `ShortInput`, `UnknownTag`,
   `ReservedTag`, `BadPadding`. Fail closed on every one. `BadPadding` exists
   because decision 1810 makes padding *normative* zero — a nonzero pad is
   corruption or a foreign writer, never a live value.
10. **(1819) FNV-1a is a 32-bit corruption check with no interop claim.**
    Guest-side only. It is **not** cryptographic, and no doc, API name or
    report line may imply otherwise (S13's rule, enforced from this rung so
    the wrong wording never ships).
11. **(1820) `db` is the third reserved alias**, resolving over `stdlib/db/`
    by the same two-candidate rule as `core`/`drivers`. Charter: store and
    library modules. `@driver` modules stay forbidden there — `stdlib/db/`
    gets its own err golden proving it.
12. **(1821) Wire enums may not nest wire enums** in revision 0.1. A nested
    tag-plus-padding inside a padded payload multiplies worst-case padding
    invisibly, and no consumer needs it. Fail closed with a named error;
    revisit only with a consumer.

## Exit criteria

1. A `@layout(wire)` enum lays out, sizes, and reports per decision 1810,
   with goldens pinning the report.
2. Reordering variants in source produces a **byte-identical** `wire.lock`.
3. Reusing a retired tag, or breaking a format without a declared
   disposition, is a build error naming the type and the fix.
4. `read_wire` decodes every wire type this rung can express and fails closed
   with `WireError`'s closed set on every malformed input, with the fuzz lane
   as the evidence.
5. `cargo xtask stdlib-test` covers FNV-1a against published vectors.
6. `from db.<mod> import …` resolves; a `@driver` under `stdlib/db/` is
   refused.
7. Full `cargo xtask check` green; deep `fuzz wire` clean; every opened
   clause `test` or honestly `gap`.

## Explicit non-goals (do not absorb)

Anything that writes or reads a device. Records, envelopes, superblocks,
geometry constants. Projections or queries. The blk driver. The VMM. 06 §8.
Encryption or any hash beyond FNV-1a. `MAX_EVENT_BYTES` (M23 — it is a
storage bound, and this rung has no storage). A general migration engine.

## Rejected alternatives (do not relitigate)

- **Hand-written protobuf-style tags in source.** Superseded by the lockfile
  (S15): same safety, and nobody maintains numbers by hand. Rejected because
  a hand-written number is a thing an author can get wrong, and a
  compiler-assigned one is not.
- **A CLI flag for the migration disposition.** Rejected: a flag is passable
  by accident and leaves no trace in review. The whole value of the
  disposition is that declaring it is a tracked-file diff.
- **Generalizing the three package aliases into a table.** Rejected
  (doctrine: no framework where three named constants do).
- **Deferring the lockfile to M23 with the log.** Rejected: retrofitting tag
  stability onto a shipped format is precisely the failure it prevents.
- **A `u8` or `u16` tag.** Rejected: payload alignment forces padding to 8
  anyway (decision 1810), so a narrower tag saves nothing and costs headroom.

## Open points deferred (not blocked)

- **`MAX_EVENT_BYTES` and `RECORD_BYTES`** — M23. This rung deliberately
  builds no notion of a record.
- **The variant-skew `warning[performance]` threshold** (S12) — the report
  table it consumes lands in item D; the threshold itself waits for M23,
  where padding has a cost to measure.
- **Guest SHA-256** — S13, with `wrela_machine::sha256` as its differential

- **`Table`'s total operation set** (S7.1: `upsert` / `push_evicting_oldest`

  changes an existing stdlib habit: `List.push` returns
  `Result[unit, ListFull]`, and a projection table must **not**, since a fold
  cannot refuse an event that is already in the log. Whoever writes M24's
  plan starts from that difference rather than copying `List`.
