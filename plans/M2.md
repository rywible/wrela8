## Goal

Every semantically wrong program in a self-contained sema corpus is rejected
with a pinned one-line diagnostic; every correct one produces a stable
resolved-signature dump. `wrela dump --stage=check` is the new pipeline
stage. The three `values.*` ledger gaps flip. Constructs whose checking
belongs to a later milestone fail closed with a named diagnostic — sema
never silently accepts what it has not checked.

## Shape decisions (frozen by goldens — decide once)

1. **Diagnostic format unchanged**: `error[<category>]: <message> at
   <line>:<col>`, one line, fail-fast. New categories: `name`, `type`,
   `access`, `move`, `init`, `overlap`, `match`, `generic`, and
   `unimplemented`. First error wins in frozen pass order; within a pass,
   source order.
2. **The one multi-line exception**: the generic instantiation error uses
   the chain format pinned verbatim in 02 §7.3 (`error[generic]:` line,
   then `required by …` and `instantiated at …` indented lines). The docs
   mandate it; goldens pin it.
3. **Pass order is frozen**: collect (module item table, duplicates) →
   resolve (names) → declare (signature/field types, data-vs-resource
   classification) → bodies (statement/expression typing, patterns, calls)
   → access (mirroring, receiver-effect inference) → flow (definite init +
   moves + exclusivity on one per-body CFG) → matches (exhaustiveness).
   Generic instantiations run the same passes concretely, once each,
   keyed in a `BTreeSet`.
4. **Type representation is dumb**: one plain `Type` enum, structural
   equality, `Box`/`Vec`, `BTreeMap` tables, clone freely. No unification,
   no constraint solver. Inference is expected-type propagation only:
   check against the expected type where the grammar provides one
   (annotations, field types, parameters, returns, scrutinee → pattern);
   synthesize elsewhere; unconstrained integer literals default to `i64`
   (`u64` when only it fits), floats to `f64`; literals are range-checked
   against the expected scalar type. No implicit conversions anywhere.
5. **Builtin surface, not stdlib**: M2 hardcodes the prelude — scalar
   types, `Option`/`Some`/`None`/`Result`/`Ok`/`Err`, `panic`, plus the
   minimum the literal rules require (`Static`, `Str`, `Bytes[N]`) and the
   language forms (`[T; N]`, tuples, `own[P] T`, `fn(...) -> R`). The real
   stdlib replaces this surface at its own milestone; the doc corpus is
   therefore **not** sema-checked in M2 (it names stdlib that does not
   exist). Sema's corpus is its own self-contained golden programs.
6. **Single file, whole program**: `check` operates on one file. `from`
   imports fail closed (`sema.names.imports` opens as an explicit gap —
   package loading needs the manifest walk, later milestone).
7. **Fail-closed set** (each reachable construct produces
   `error[unimplemented]: <construct> is not checked yet`): imports,
   `comptime if`/`comptime assert` evaluation, f-strings (bound
   computation needs comptime), `await`/`send`/actor calls/`with`
   group/pool (M6), `@image` bodies (M4), pool-capacity proofs, loop-bound
   and `@budget` proofs (opened as gap `sema.bounds.loops`), ISR effect
   restriction (M7).
8. **Check dump**: on success, a deterministic resolved-signature summary —
   one line per declaration, two-space indent for members, no spans;
   resolved types spelled fully, access modes explicit, inferred private
   receiver effects shown once the access pass lands, `data`/`resource`
   classification shown on types. Exact grammar is pinned by the first
   `check-*` goldens and extended (with `--update` + clause citation) as
   passes land.
9. **`take` accepts any owned place**, resource or data, and always
   deinitializes the source. The docs' "data copies" means data *may*
   copy implicitly; generic uniformity (`map_take` over data elements)
   requires explicit `take` to work on data too. Copying a resource
   implicitly is the error; taking data is not.
10. **Code layout**: `crates/wrela-compiler/src/sema/` with one file per
    pass — `mod.rs`, `prelude.rs`, `symbols.rs` (collect+resolve),
    `types.rs` (Type + declare), `bodies.rs`, `access.rs`, `paths.rs`
    (storage paths, shared), `flow.rs`, `matches.rs`, `generics.rs`. Long
    obvious files; every pass file exists (stubbed) from item A onward so
    later items land in their own file.

## Work items, in order

### A. Sema spine + name resolution
The `sema/` skeleton (every pass file stubbed and wired), the builtin
prelude table, collect + resolve: every identifier binds to prelude, a
module declaration, or a local introduced by assignment/parameter/pattern/
`for`; duplicate module-scope names, unknown names, and local shadowing are
errors. `wrela dump --stage=check` lands in the CLI; `xtask golden` learns
`check` expectation files (same touch convention).
Cases: `check-module`, `err-name-unknown`, `err-name-duplicate`,
`err-name-shadow`, `err-unimplemented-import`.
Opens: `sema.check.dump-stable`, `sema.names.resolution`,
`sema.names.imports` (gap), `sema.unimplemented.fail-closed`.

### B. Declaration typing + classification
The `Type` enum; resolve every signature, field, and const type;
data-vs-resource classification (`resource struct` by fiat, `own[P] T`,
and any composite containing a resource — transitively); `deriving` list
validation (`Format`, `From` with its one-variant/one-field shape rule;
other names are errors). The check dump graduates to full resolved
signatures.
Cases: `check-decls`, `err-type-unknown`, `err-type-deriving`.
Opens: `sema.types.declarations`.

### C. Body typing
Statements and expressions per 02 §8 under decision 4: assignment
introduction/reassignment (same type), `if`/`while` conditions are `bool`,
`for` over ranges and fixed arrays, operator desugar (builtin scalar ops
with no mixed types; named-method desugar per 02 §7.4 for user types;
structural `==` on data only — comparing resources is an error), call
checking (arity, labels bound at most once, positional/label mix), enum
literals and leading-dot inference, pattern typing, `is`, closures as
structural `fn` types, `?` on `Result`/`Option` with explicit `from`
conversion only, `assert`, `defer` bodies cannot `await` or `?`. The
fail-closed set (decision 7) is enforced here.
Cases: `check-bodies`, `check-operators`, `err-type-mismatch`,
`err-type-arity`, `err-type-label`, `err-type-question`, `err-type-cond`,
`err-type-resource-eq`, `err-unimplemented-await`.
Opens: `sema.types.bodies`, `sema.types.calls`.

### D. Access modes
Call-site mirroring against signatures — missing, extra, or wrong
`mut`/`take` marker; operands must be places (the parser already rejects
`take <rvalue>`; sema rejects the rest); the receiver exception; `pub`
methods must spell their receiver effect while private plain `self` gets
the least effect inferred (and shown in the check dump); operator operands
are `read` — a user method bound to an operator must match the 05 §8
shape.
Cases: `check-access`, `err-access-missing-mut`, `err-access-extra-take`,
`err-access-wrong-marker`, `err-access-pub-receiver`.
Opens: `sema.access.call-mirroring`, `sema.access.receiver-inference`.

### E/F. Flow: definite init, moves, exclusivity (one CFG, one pass file)
Per-body CFG; initialization state per storage path on every edge.
Definite init: read-before-assign, arm merging, `init` fields checked like
uninitialized locals. Moves: `take` deinitializes; use-after-take; a field
`take` must be restored on every normal path before whole-value use or
return; overwriting a live resource; implicit resource copy (assignment,
argument, capture without `take`); runtime-index moves forbidden; fresh
values bind without `take`. Exclusivity: while `mut x` is active no other
path may touch overlapping storage — two overlapping `mut` arguments, or a
`mut` argument plus any later argument reading an overlapping path, are
compile errors on storage paths, not names.
Cases: `check-flow`, `err-init-unassigned`, `err-init-merge`,
`err-init-field-restore`, `err-move-use-after-take`,
`err-move-copy-resource`, `err-move-overwrite-live`, `err-move-index`,
`err-overlap-two-muts`, `err-overlap-mut-read`.
Flips: `values.data.copies-implicitly`, `values.resource.move-spells-take`,
`values.exclusivity.no-overlap`. Opens: `sema.init.definite`,
`values.resource.protocol-consumption` (gap — protocol resources are
stdlib/M7 types; no M2 type has protocol-only consumers).

### G. Match exhaustiveness
Compositional usefulness over closed sums, `bool`, tuples, fixed arrays;
integers and everything unbounded require a wildcard; a wildcard (or any
arm) that covers nothing is an error; guarded arms never contribute; `|`
alternatives bind the same names at the same types.
Cases: `check-match`, `err-match-nonexhaustive`,
`err-match-redundant-wildcard`, `err-match-or-bindings`.
Opens: `sema.match.exhaustive`.

### H. Structural generics
Instantiation-driven: typing a `Generic[Args]` use enqueues the concrete
instantiation, which runs the full pass pipeline once (BTreeSet-keyed).
The requirement chain is inferred, and a missing requirement reports the
multi-line error of decision 2. Const arguments evaluate only as literals,
fieldless-enum variants, and direct `const` references (the comptime
engine is M3); anything else fails closed. Instantiation recursion has a
fixed depth cap.
Cases: `check-generics`, `err-generic-missing-method` (pins the chain
format), `err-generic-const-arg`.
Opens: `sema.generics.structural`.

### I. Hardening + measurement
`cargo xtask fuzz sema`: corpus + golden-input mutation through
lex→parse→check; invariants — never panics, result is a dump or exactly
one diagnostic, deterministic across repeat runs. Smoke budget into
`check`; deep default sized by measurement. `xtask bench compiler` grows a
check-lane measurement (lex+parse+check over every golden input that
checks) with its own locked threshold in `bench/thresholds.toml`.
Opens: `sema.no-panics`. Updates the `compiler.bench.compiler-lane-locked`
note.

### J. Error-corpus sweep
Adversarial pass over every category: at least one committed reject golden
per diagnostic category, hunting for wrong-answer acceptances and
inconsistent messages (M1's sweep found a real parser bug; assume this one
will too). Any find is minimized into a committed golden before its fix
lands.

## Non-goals (M3+ territory)

No comptime evaluation (M3), no image graph or manifest handling (M4), no
actor/async semantics — turns, mailboxes, admission, groups, placement
(M6+), no pool-capacity or loop-bound proofs, no ISR effect sets (M7), no
f-string bound computation (M3), no corpus-wide sema (stdlib milestone —
also where the deferred M1 question about methods named `from`/`read`/
`take` gets decided), no error recovery or multi-error reporting, no
copy-cost reporting or `@budget` (M5's cost lane), no sema performance
work beyond the bench lock.
