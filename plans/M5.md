## Item zero: the HVF smoke probe — ALREADY RUN, PASSED

Per the standing risk note, before any backend work: an ad-hoc-signed
binary carrying the `com.apple.security.hypervisor` entitlement ran
`hv_vm_create(NULL)` → 0 and `hv_vm_destroy()` → 0 on this machine
(2026-07-24, macOS Darwin 24.6.0, Apple Silicon). HVF is viable; no
boot-independent pivot needed. Item E bakes the codesign step into xtask
and re-proves this on every `check` that builds the VMM.

## Goal

`wrela test file.wr` compiles every `@test(runtime)` fn to a real AArch64
image, boots it on the wrela VMM (Hypervisor.framework), and the guest
prints each test's own pinned report line over virtio-console; the
transcript is a golden. The image and report are byte-reproducible
(`repro` proves it), the backend agrees with the M3 evaluator on every
comptime-legal test (`diff-eval` proves it), and the boot workload is
recorded and replayed under counts (`bench guest`/`profile` measure it).
Zero instructions of cleverness: fixed layout, spill-everything codegen,
trap-per-clock-read — every fast path waits for a profile.

## Exit criteria

- `plans/M6.md` does not exist yet.

## Shape decisions (frozen by goldens — decide once)

1. **The guest execution surface is `@test(runtime)`, nothing else**
   (02 §12.2: "a generated image test booted on the digest-pinned wrela
   machine runner — the VMM itself"). No `main`, no invented entry
   surface. `wrela test` gains the runtime tier: all `@test(runtime)` fns
   of the checked program are compiled into ONE test image, booted once;
   the guest prints each test's line (the M3-E pinned shapes, identical)
   over virtio-console in declaration order; the harness appends them
   after the comptime tier's lines (all comptime lines first, then all
   runtime lines, then the one summary line — the dumbest deterministic
   merge; recorded here so nobody argues interleaving later). Scenario
   files (console send/expect) are NOT M5 — nothing sends input yet.
2. **Backend scope = the evaluator's surface, exactly.** The synchronous
   typed-tree subset M3's evaluator executes (02 §6.1 arithmetic with its
   exact overflow/div semantics, structs/enums/arrays by value, match,
   loops, calls, take-as-clone observational semantics) lowers and
   compiles; everything else — async/await/send/with, actor turns, pool
   and group runtime, f-strings, ISR binding — fails closed at lowering
   with a named `error[unimplemented]`. diff-eval (decision 9) is the
   oracle that the two implementations of this one surface agree.

   Sub-note (recorded at item B merge, 2026-07-24): item B shipped
   honestly *narrower* than "the evaluator's surface, exactly" — the
   fail-closed set additionally contains constructs the evaluator does
   execute: closures and indirect calls (no function-value ABI exists in
   this scope), the `?` operator, non-literal `panic` messages
   (golden/err-mwir-dynamic-panic pins the one checkable shape), `|`
   patterns, nested-chain assignment targets, and a handful of exotic
   const shapes — the full enumeration lives in `lower.rs`'s module doc.
   Consequence for decision 9: diff-eval must SKIP (and count, and
   report) comptime-legal tests whose lowering fails closed, never treat
   one as disagreement — the skip count is part of the oracle's own
   output so shrinkage stays visible. Lifting any of these is ordinary
   later work, not an M5 exit criterion.
3. **One lowering, two dumps.** typed tree → **mwir** (the doc's
   MachineWir: a flat, linear, explicitly-ordered instruction list per
   fn — plain enum, no basic-block graph) → naive A76. FlowWir
   materializes when async does (M6); 04 §8's "implementations may fuse
   phases when results and diagnostics are equivalent" is the license,
   recorded here. Dumps: `wrela dump --stage=mwir` and `--stage=asm`
   (stable text, golden-covered before features, per house rule).
4. **Codegen is spill-everything.** Every mwir temp lives in a fixed
   stack slot; every operation loads operands into x9/x10, computes,
   stores x9 back. Fixed frame layout documented in codegen.rs. Calling
   convention: AAPCS64-shaped (args x0–x7 by value or pointer-to-copy for
   large aggregates, result in x0 or via x8 indirect — document the exact
   dumb rule in-file; it is internal-only, no FFI exists). Checked
   arithmetic branches to a per-image abort path that prints the
   evaluator's own abandonment message shape and fails the running test.
5. **The encoder is a pure function with pinned bytes.** A76 subset
   encoder (`encode.rs`): each instruction → `u32`, unit-tested against
   hand-verified ARM ARM encodings, plus an encoding golden (a fixed
   instruction list → hex dump) so the bytes are review-visible. No
   external assembler, no cross-check dependency; HVF execution +
   diff-eval are the behavioral oracle.
6. **Machine layout contract v1 lives in `wrela-machine`** (constants,
   one place, shared by compiler and VMM — the crate's whole purpose):
   guest RAM base and size (1 GiB profile), image load base, per-core
   stack bases/sizes (4 reserved, core 0 used), the machine-info page
   address and field layout, the console tx ring page(s) + doorbell
   address, the clock MMIO address. Published as `pub const`s with the
   doc-comment being the normative-adjacent record; the machine revision
   string `wrela-machine-v1` goes into the report's build identity and
   the info page, and the VMM refuses a mismatch (06 §10).
7. **Layout + emission append to the report; existing report goldens
   move once, deliberately.** New `Layout` section (M4 decision 8's
   append rule): one line per section (code/rodata/data/stacks/pages)
   with base and size, after the existing sections. The image binary is
   one flat blob loaded at the fixed base (no ELF, no linker — 04 §8
   "emit and link" is satisfied by emit-into-one-blob + verifying
   section sizes against the report). `wrela build` writes
   `<name>.img` next to the report. The M4 report goldens gain their
   Layout lines in item D's commit, cited against the layout clause.
8. **`@layout_assert` stays failing closed** — running one needs the
   stdlib `ImageReport` reflection type (stdlib milestone), which does
   not exist. M4's diagnostic text names "M5" and would become a lie:
   item D rewords it to cite the gap clause (`image.graph.dma-pools`
   precedent: name the gap, not a milestone number). REVIEW-QUEUE only
   if any normative doc text must move (none is expected to).
9. **diff-eval is a batch oracle** (flips
   `compiler.eval.matches-backend`): for every golden case whose program
   has comptime-legal `@test` fns, compile those same tests as runtime
   tests into one image, boot it once, and compare each test's
   guest-printed line against the evaluator's line for the same fn.
   Wired as `cargo xtask diff-eval` over the golden corpus; a smoke
   subset (the boot golden + one arithmetic-heavy case) runs inside
   `check`, the full corpus on demand and in item G's soak.
10. **repro builds twice and compares everything** (flips
    `compiler.repro.byte-identical`): image blob + report, two fresh
    in-process builds, byte-compare — the M4 report-determinism oracle
    grown to cover the binary. `cargo xtask repro` = the full-corpus
    form; the in-`check` form covers every golden case that emits.
11. **The VMM is raw HVF FFI, no dependency** (06 §9 permits rust-vmm;
    CLAUDE.md's liability rule says don't until forced — the smoke probe
    proved raw FFI suffices). `hv.rs`: the ~10 calls needed (vm create/
    destroy, memory map, vcpu create/run/exit-info, register get/set).
    vCPU 0 starts at the image entry, EL1, MMU off, flat physical,
    FP/NEON enabled via CPACR_EL1; no MMU work at M5 (nothing needs
    translation; caches/coherency are HVF's problem for a single vCPU).
    Cores 1–3 are reserved in the layout but never started (sync only).
    xtask codesigns the VMM test binaries with the entitlement plist
    (checked into `crates/wrela-vmm/entitlements.plist`) after every
    build — the smoke probe's exact recipe.
12. **Console is a runtime-owned tx ring at M5, virtio-shaped.** The
    generated runtime writes report lines into a split-ring tx queue in
    the shared console pages and rings the doorbell word; the VMM's
    console model drains it to the captured transcript. The stdlib
    virtio-console *driver* (03's machinery) arrives with async (M6+);
    this runtime path speaks the same ring layout and is replaced then —
    recorded so nobody calls the runtime path the driver.
13. **`now()` traps at M5.** One fixed clock MMIO address; every read
    exits to the VMM, which returns monotonic ns and logs the value.
    Recording = the clock-read log + the console output digest; replay
    feeds the logged values back and diffs the digest (06 §8's subset
    that exists with one core, no vectors, no other devices). The
    shared-page fast path is exactly the kind of cleverness that waits
    for a profile — the trap IS the M5 design, not a shortcut.
14. **`bench guest` + `profile` v0 are wall time + exact replay counts**
    (the prescribed dumb version): `bench guest` boots the recorded boot
    workload, replays it, reports median wall time locked in
    `bench/thresholds.toml`, plus deterministic counts (clock reads,
    console bytes, vCPU exits) asserted exactly. `profile` prints the
    per-phase compiler timings (--timings, existing) plus the guest
    counts. `compiler.costs.predicted-vs-measured` STAYS a gap: the
    report predicts no costs yet (exit-rate lines are 06 §5 material for
    the device milestones); the clause note says so honestly.
15. **Boot golden**: `tests/golden/boot-hello/` — a `@test(runtime)`
    program whose tests exercise printing, arithmetic, a struct, a match;
    `expected/boot.txt` is the full console transcript. Runs on every
    `check` (it IS the "prints over virtio-console on a Mac" ROADMAP
    sentence). Timeouts: fixed host-side wall cap per boot (a hang is
    `FAILED (timeout)` with the transcript-so-far shown) and an output
    byte cap — 02 §12.2's "statically bounded output and timeouts" in
    their dumbest harness-side form, constants in the runner.

Sub-notes (decisions this item had to make that the plan itself left
open, recorded here per the plan's own "your call, document it"
invitations):

- **Two-pass emission, not backpatching**: pass 1 measures the fixed-
  shape prologue's word count plus every mwir instruction's own word
  count (a static function of instruction shape, never of a jump
  target's *value*); pass 2 re-runs the identical per-instruction
  emission with the resulting `word_offsets` table, so every local
  `Jump`/`JumpIfFalse`/`Return`-to-epilogue resolves directly. A
  `Call`'s target and every rodata reference stay symbolic
  (`Reloc::Call`/`Reloc::Rodata`) for item D.
- **Aggregates pass by a bare pointer to the caller's own temp slot,
  never a defensive scratch copy** — safe because a callee always
  copies an incoming aggregate into its own local slot at entry and
  only ever mutates that local copy (proved in full in `codegen.rs`'s
  own module doc). This makes `self_write_back` fully automatic:
  it is read nowhere in `codegen.rs`, satisfied entirely by the
  uniform bare-pointer rule plus the callee's own `mode`-driven
  epilogue write-back.
- **`x29` (fp) is never used** — SP-relative addressing throughout, only
  `x30` (lr) saved/restored; no unwinder or debugger exists to satisfy
  in this internal-only ABI.
- **The abort contract**: `__wrela_abort(msg_ptr, msg_len)` for every
  fixed-at-compile-time message; `__wrela_abort_val(prefix_ptr,
  prefix_len, value, value_signed, suffix_ptr, suffix_len)` for the two
  runtime-value-interpolated messages (shift count, index-out-of-
  bounds) — both `BL`, uniformly with every ordinary call, item D/E's
  exact obligation, documented in full at the top of `codegen.rs`.
- **`ADRP`+`ADD`, always** (never bare `ADR`) for every rodata reference
  — decision 5's own "pick ONE form always, dumbest wins".
- **`encode.rs` extended**: `enc_smulh`/`enc_umulh`, the one instruction
  class item A's subset genuinely omitted that 64-bit checked
  multiplication overflow detection cannot be done without (decision
  4's own "smulh compare"). Two new pure functions + their own unit
  tests; `encoding_table_golden` and every other existing test
  untouched.
- **A canonical-slot invariant carries the whole scheme**: every scalar
  temp's 8-byte slot always holds its value's signed 64-bit
  representation (zero-extended if unsigned, sign-extended if signed).
  This is why `Compare` can always use a signed 64-bit compare
  regardless of declared signedness, why bitwise ops need no extra
  truncation, and why narrow checked arithmetic can compute at 64-bit
  width and just bounds-check the raw result.

Sub-notes (decisions this item had to make that the plan itself left
open, recorded here):

- **Build-vs-report layout coverage: both, uniformly, whenever the whole
  program lowers.** Every one of the four M4 report goldens' own
  reachable surface (methods on `@actor`/`@driver` structs, plain helper
  fns) turned out to fully lower/codegen with no fail-closed hit at all —
  `golden/image-basic` never even reaches layout (its registered
  `@layout_assert` fails the report closed first, unchanged from M4) — so
  the dumbest rule that stays honest for both today's and a future,
  narrower program is: `--stage=report` and `wrela build` both attempt
  `layout::try_layout_program` (via the identical shared `build_report`
  tail) after `report::render` succeeds; `Some` appends the `Layout`
  section to whichever caller asked (and `wrela build` additionally
  writes the `.img`), `None` (a future program whose reachable surface
  does not fully lower — decision 2's own fail-closed set) leaves the
  report exactly as M4 left it, for *both* callers, never failing the
  whole build/report over a layout-only shortfall. No fn is ever silently
  dropped from a partial image — it is genuinely all-or-nothing per
  program, `layout.rs`'s own doc comment names this explicitly.
- **A project's reachable surface is spread across every module in the
  closure, not just the one holding `@image`.** `bodies::check` only
  ever populates a module's own `TypedProgram::fns`/`structs` from that
  module's own `ast::Module::items` — an imported struct's own methods
  are never copied into the importer's `TypedProgram` (the import splice
  only ever grows `ModuleCtx`, the name-resolution table, not the final
  typed tree). `layout::try_layout_program` therefore lowers every
  module's own `TypedProgram` independently and merges the results
  (`merge_mwir_programs`, rodata-reindexed per module); `layout::
  merge_layout_ctx` does the identical merge one level down for
  `mwir::build_layout_ctx`'s own struct/enum field-type facts.
- **`wrela build`'s pinned stdout gains no new line for the image.**
  `golden/appliance/expected/build.txt` predates this item and is not
  one of the four report goldens the house rules license to move; the
  `.img` write is silent, golden-covered instead by comparing the
  written file itself (`golden/image-emit`'s new `img.hex` expectation).
- **`golden/image-emit`** (new): a minimal two-fn program (`compute`
  calling `add_one`, plain checked `+`) chosen because none of the three
  fully-lowering appliance-family goldens' own reachable methods happen
  to call each other or trip a checked-arithmetic abort — this case is
  the one dedicated byte-level review surface exercising `Reloc::Call`
  together with `Reloc::AbortFixed`/`Reloc::Rodata` (the shared overflow-
  message intern) end to end. `expected/img.hex`: a 16-bytes-per-line
  offset+hex dump (more reviewable than raw binary in git); `xtask`'s
  `golden` runner gained a fourth expectation-file meaning (`img.hex`,
  reading `build.txt`'s own already-written `.img` back off disk rather
  than invoking `wrela` again) and now defers removing the build-output
  temp dir to the end of each case's own expectation-file loop instead of
  immediately after `build`/`build-err`, so `img.hex` can still see it.

Sub-notes (decisions this item had to make that the plan itself left
open, recorded here per the plan's own "your call, document it"
invitations):

- **`layout_program`/`build_entry_stub`/`build_abort_stub` are
  untouched; a second, parallel placement fn owns the test image.**
  `layout.rs`'s own pre-item-E module doc speculated item E would
  "replace [the placeholder entry's] body wholesale" — it does not: the
  four pre-existing report goldens (`appliance`/`image-basic`/
  `image-project`/`image-helper-accept`/`image-emit`) pin that
  placeholder's exact bytes, and CLAUDE.md's "existing goldens must not
  move" outranks a speculative doc comment written before this item was
  scoped. Instead, `layout_test_image` (new) is a wholly separate
  placement function, used only by `wrela test`'s runtime tier, sharing
  `patch_bl`/`patch_adrp_add`/`round_up`/`pad_to`/`verify_section_sizes`
  with the ordinary path but building its own entry/abort bodies. The
  module doc's own newer text (above the harness code) records this as
  the actual, corrected design.
- **The landing pad, precisely**: one fixed scratch slot,
  `machine_info::OFF_TEST_CONTINUATION` — the entry driver stores the
  address of its own next step (the top of the next test's own block, or
  the summary block for the last test) there, immediately before each
  test's own `BL`; `__wrela_abort`/`__wrela_abort_val`'s own bodies
  (extended, this item) print the `FAILED` line, increment
  `OFF_TEST_FAILED`, then `LDR` the slot and `BR` to it — never `RET` —
  resuming the driver exactly where the aborted test's own "ok" line
  would have run, skipping it. No fallback mechanism was needed; the
  landing pad worked as planned once two bugs in it (below) were fixed.
- **The console ring writer and decimal formatter are two more hand-
  assembled, fixed subroutines** (`__wrela_ring_write`/`__wrela_fmt_dec`,
  `layout.rs`), placed in the same combined "entry" section as the
  driver/abort bodies so every internal call between them is a locally-
  computed `BL` (no `Reloc` needed) — only a call to an `@test(runtime)`
  fn (in `code`) or a literal string (in `rodata`) crosses out via the
  existing `Reloc::Call`/`Reloc::Rodata` machinery. `__wrela_ring_write`
  never populates `avail.ring[]` at all (a disclosed simplification: this
  producer never reorders or skips a descriptor index, so the VMM reads
  `0..avail.idx` directly); an over-capacity write is a silent no-op/
  truncation rather than the plan's own suggested "FAILED (output cap
  exceeded)" marker line (writing that marker would itself need ring
  capacity that's already exhausted — a circularity resolved by simply
  not attempting it, recorded as an honest, undetected-by-any-golden M5
  bound, not a silent approximation).
- **`now()`: checked, not implemented.** `05-library.md` and
  `02-language.md`'s own comptime-clock surface expose no checkable
  `now()` fn at this milestone (grepped, not assumed) — per the task's
  own instruction, no prelude fn is invented ahead of the stdlib
  milestone that actually defines one. The `CLOCK_MMIO_ADDR` trap and its
  log are fully implemented and unit-tested in `wrela-vmm` (`hv.rs`'s ESR
  decoder, `lib.rs`'s exit-loop arm) — dead code today, exactly as the
  plan anticipated ("dead until F's recorder tests it via a hand-written
  word sequence"), which is why `machine.clock.trap-logged` opens as a
  gap rather than a test: nothing *golden-covered* exercises a real
  guest-issued read yet.
- **Real bugs the boot golden itself caught — none of them findable by
  any dump-only golden, since nothing before this item ever executed
  emitted bytes:**
  1. `layout.rs`'s own landing-pad continuation store baked in a raw
     *word index* (`Asm::abs()`) where a real guest *address* was needed
     — the entry driver would `STR` a small integer like `0x80` into
     `OFF_TEST_CONTINUATION`, and a subsequent abort's `BR` would then
     fault trying to fetch from that (unmapped, near-zero) physical
     address. Fixed by adding `Asm::addr(harness_base)` (word index * 4
     + the section's own known base — always `IMAGE_BASE`, since the
     combined harness section is always placed first) and using it at
     the one call site that stores a value a register will later branch
     to, as opposed to every other use of `abs()`, which only ever feeds
     a `BL`/`B`/`B.cond`'s own *relative* immediate and needed no such
     fix.
  2. Both abort bodies (`__wrela_abort`/`__wrela_abort_val`) never wrote
     the trailing newline after their own message text, concatenating
     directly into the next line — a plain omission, fixed by interning
     one shared `"\n"` literal and one more `__wrela_ring_write` call in
     each body.
  3. `encode.rs`'s `enc_umulh` had the signed/unsigned distinction in the
     wrong bit field entirely (`op54`, bits 30:29, instead of `op31`'s
     own top bit) — self-consistent with its own hand-derived unit tests
     (the same reasoning mistake baked into both the code and the test
     that was supposed to catch it), so `cargo test` passed while every
     64-bit *unsigned* checked multiplication decoded, on real hardware,
     as an entirely different, unrelated instruction. Found by bisecting
     a real SIGILL: a plain `pub fn square(n: u64) -> u64: return n * n`
     wrapped in one `@test(runtime)` crashed the VMM outright; narrowed
     to `enc_umulh` alone via a hand-assembled 5-instruction JIT probe
     (`mul`/`umulh`/`cmp`/`b.eq`/`ret`, no codegen involved at all), then
     cross-checked against `clang -target arm64-apple-macos`'s own
     assembler output for two independent register triples (never
     re-derived by hand a second time, which is exactly how the original,
     wrong version of this function's own unit test passed). This is
     06-machine.md §9/decision 5's own "HVF execution is the behavioral
     oracle" framing, realized exactly as intended: no encoding golden or
     `--stage=asm` dump text ever exercises the *bits actually running*,
     only their reviewable rendering. `golden/asm-calls`/
     `golden/asm-enum-match`'s own pinned `umulh` hex word moved
     accordingly (the only bytes affected by the fix).
- **The JIT self-test technique used for `layout.rs`'s own hand-assembled
  routines (`ring_write`/`fmt_dec`) is real execution on this machine's
  own aarch64 CPU** (mmap RW, write words, `mprotect` to R-X, call
  through an `extern "C" fn` pointer) — not a simulation. It caught one
  more real issue during development, unrelated to codegen: a write from
  freshly-JIT'd code to a never-before-touched anonymous `mmap` page was
  not reliably observable without the page being pre-faulted first on
  this host; fixed by having the test harness zero its own host pages up
  front, which also matches `boot_image`'s own real behavior (it zeroes
  the entire guest DRAM reservation before the vCPU ever runs, per
  06 §3) — the fix reflects production reality, not a test-only
  workaround.
- **The test-image "report" is a small, internal, non-golden-pinned text
  format**, not `report::render`'s own richer artifact (which requires an
  `@image` fn — a runtime-test image has none). `bin/wrela.rs`'s runtime
  tier writes `Machine revision=`/`Input path=... digest=...`/`Section
  name=... base=... size=...`/`Entry base=0x...` lines; `wrela-vmm`'s
  `parse_report` validates the machine revision (refused loudly on
  mismatch, 06 §10) and every other fact's own bare *presence* — this VMM
  has no access to the original source files to re-verify a digest
  against, only the compiler does, at build time.
- **`wrela test`'s comptime/runtime merge** (decision 1) is built by
  post-processing `eval::run_tests`'s own text rather than editing
  `eval/` (read-only for this item): every `TestKind::Runtime` test's
  fixed placeholder line is stripped back out (matched verbatim, never a
  prefix guess) and its own contribution to `run_tests`'s internal
  `failed` count subtracted (`runtime_tests.len()`, since each
  contributes exactly one, unconditionally) before the runtime tier's own
  lines and its own image-computed summary are merged in. A program with
  zero `@test(runtime)` fns takes a byte-identical fast path to every
  pre-M5 `wrela test` golden.

- **A third skip category, `quota-skips`, beyond the plan's own two.**

  it somehow completed). The plan's own decision 9/2 text named only two
  skip categories; this is a genuine, load-bearing discovery made while

  by a small, deliberately independent `parse_guest_record` in `xtask`
  itself (`GuestRecord`) rather than adding `wrela-vmm` as a real
  dependency to reuse `RecordFile::parse` — a few `strip_prefix` calls
  over three known keys is simpler than a dependency for what `bench
  guest`/`profile` actually need, and keeps the "one small signed
  binary" boundary crisp at every level, not only at build time.
- **`wrela-vmm`'s own hand-built clock-reading test needed the whole
  workspace `cargo test` step split.** `cargo test --workspace`'s own
  test binaries are never codesigned (only `xtask`'s own
  `build_and_sign_vmm` post-processes the *ordinary* `wrela-vmm` binary)

  roundtrips_and_detects_every_divergence_shape` is the first `#[test]`
  in this workspace that calls `hv_vm_create` for real. `check`'s plain

  (`--exclude wrela-vmm`); a new `test_wrela_vmm_signed` builds that

  cargo's own `Executable ... (path)` stderr lines — no

  of known shape), then runs each directly, single-threaded
  (`--test-threads=1`, the same "no two calls into HVF's one
  process-wide VM context are ever concurrent" reasoning the hand-built
  test's own doc comment gives, enforced at the process level too).
- **The clock-reading test image reuses `wrela-compiler::encode`
  directly, as an in-workspace `[dev-dependencies]` entry on
  `wrela-vmm`** (the plan's own "if adding a dev-dependency ... is
  acceptable, do that" call): re-deriving the same ~12 pinned A76
  encodings (`movz`/`movk`/`ldr`/`str`) by hand a second time would be
  strictly more risk than reusing the already unit-tested/golden-pinned
  ones, and the dependency is test-only, never linked into the
  production `wrela-vmm` binary. `wrela-vmm/Cargo.toml`'s own comment
  names this reasoning.
- **The record file's own "digest" is FNV-1a, not a cryptographic
  hash.** Nothing downstream needs collision resistance — only "did the
  transcript come out the same bytes twice" — and a hand-rolled SHA
  would be a much larger surface to get bit-perfect for zero benefit
  here; `record.rs`'s own `digest_hex` names this choice.
- **`repro`'s standalone form grows one population past
  `report_determinism`'s own reach**: a runtime-test image has no
  `@image` fn, so it never goes through `report_determinism`'s
  `@image`/`wrela build` walk. `repro_test_image` (new) proves
  `tests/golden/boot-hello`'s own test image is byte-reproducible across

  `report_determinism` already proves for the build pipeline — `cargo
  xtask repro` is now `report_determinism()` followed by this, a strict
  superset rather than a bare synonym of `report-determinism`.
- **`profile`'s compiler timings are hand-instrumented, not `--timings`
  itself** — that flag lives on `wrela dump`, which never builds a
  runtime-test image, so `xtask::profile` times the identical phases
  (read/lex/parse/check/lower/codegen/layout) by hand around the same

## Non-goals (M6+ territory)

(M6 — the machine's §4 machinery has nothing to inject into sync code),
no KVM backend (the Pi host milestone), no MMU/EL2, no display/input/
blk/net/entropy/sound devices, no stdlib virtio-console driver (M6+;
decision 12's runtime ring is not it), no scenario files, no
`@layout_assert` execution (decision 8 — needs the stdlib ImageReport

milestone can buy them honestly), no cost prediction in the report, no
comptime caching, no QEMU bootstrap (06 lists it; HVF passed the smoke
probe, so the bootstrap rig is unnecessary — if HVF regresses, that is
a BLOCKED.md event, not a reason to build a second boot path silently).
