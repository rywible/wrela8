The machine is **3 vCPUs, always** — settled in ROADMAP (2026-07-24):
`vCPUs = flagship core count − 1 housekeeping core` (Pi 5: 4 − 1 = 3).
That number change is a golden-moving, deliberately reviewed commit of
its own (06 §1, README, `wrela-machine` stack-region docs, and every
report layout that enumerates `core_stack_N`).

## Goal

An image places actors across three cores, cross-core sends travel on
declared rings, and every mailbox's admission order is a recorded choice
the replay path can inject. Placement is a build output the report
states and the recorder's choice sequence enumerates — not a runtime
heuristic. The M6/M7 single-core surface keeps working; core 0 remains
the home of the virtio-blk driver and its bottom half until a later
item moves one deliberately.

## Shape decisions (frozen by goldens — decide once)

1. **Three vCPUs is a machine-revision constant, not a knob.** ROADMAP
   already settled the derivation. Item A is the golden-moving commit
   that makes the number true in artifacts; no runtime "how many cores"
   discovery (06 §3).
2. **Placement is a build output.** The report names each actor's core;
   source may annotate `core=N` where inference is too weak, and omitted
   annotations are inferred or rejected — never silently defaulted to 0
   for a cross-core graph. The virtio-blk driver and its ISR/bottom half
   stay on core 0 unless an item deliberately moves them with an oracle.
3. **Admission joins the choice sequence for real.** M6's
   `ChoiceEntry::Admission` tag stops being format-only. Cross-core
   admission order is the nondeterminism ROADMAP named beside device
   completion timing; both are injectable. The recorder's representation
   stays an enumerable choice sequence (no opaque timestamps).
4. **One driver-fault story until quarantine lands.** M6 decision 12 /
   M7 decision 8: an actor/driver abandon is image-fatal with a
   diagnosable line. Quarantine and recovery turns are an ordered item
   of this milestone (below), not a silent change to that floor.
5. **Driver mailboxes lift before caller-side `await receipt` executes.**
   M7 decision 22 left `await receipt` typed and lowered but unreachable
   from the flagship because `@driver` mailboxes stay the M6-D floor
   (`golden/err-image-driver-message`). The mechanism is shared with
   sync `claim`; what is missing is the messageable-driver API in
   `05-library.md`. Item order below puts that API before any oracle
   that needs a parked caller-owned receipt.
