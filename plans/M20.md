## The mandate (human, 2026-07-29)

Go all in on Pi 5's specific microarchitecture. Model the machine as
accurately as the published record permits, and accept Pi-5-specificity as
the point rather than a limitation: the model is for *this* board, and opts
tuned on it are expected to transfer to larger machines merely uncalibrated,
not wrong — because Pi 5 is small, so its capacity and issue pressure bind
first, and an opt that wins under binding pressure is not made worse by
slack.

**This reverses M20's first draft.** That draft's decision 1600 was "model
capacity; never policy," with an A76 port map named as a rejected
alternative. That is now the deliverable. Recorded once so it is not
relitigated: the earlier rejection reasoned that ILP fidelity buys accuracy
on the axis this machine wins least on (ROADMAP's "overheads that surround
compute … rather than … ALU throughput"). That reasoning still holds *for
prioritization* — which is why block grain (item C) comes first, and why the
cross-core/barrier dimension (item G) is treated as first-class rather than
as an afterthought behind the port map.

## The research

### Source tiers

Every row in the model carries one. The tier is data, not decoration: it
decides whether a value may be pinned (decision 1602) and how the over-cost
rule applies (decision 1609).

| Tier | Meaning | Sources |
| --- | --- | --- |
| **T1** | Vendor, this core, normative | Cortex-A76 Software Optimization Guide, PJDOC-466751330-7215 v8.0 (46pp) — "SOG §x.y" |
| **T2** | Vendor, this core or cluster, descriptive | Cortex-A76 Core TRM (100798); DynamIQ Shared Unit TRM (100453) |
| **T3** | Third-party measured, **on this board** | tinymembench random single-read curve, Raspberry Pi 5 / BCM2712 |
| **T4** | Third-party measured / derived, generic A76 | 7-cpu.com; WikiChip; AnandTech microarchitecture coverage |
| **T5** | Unresolved, conflicting, **or unpriced by any source** | → sweep box only, never pinned |

**T5 includes "unpriced by absence."** Verified this pass: the SOG contains
**no** barrier (`DMB`/`DSB`/`ISB`), no load/store-exclusive, no
system-register, and no prefetch instruction entry anywhere in its 46 pages —
its instruction tables run §3.3–§3.21 (branch, arithmetic/logical, move/shift,
divide/multiply, saturating, misc data-processing, load, store, FP, ASIMD,
crypto, CRC) and its special considerations §4.1–§4.12 contain no barrier
section. Those costs are therefore T5 for magnitude even where the *mechanism*
is T1/T2. This matters more here than it would elsewhere — see the dimension
inventory.

### The eight execution pipelines (T1, SOG §2.1 — definitive)

Instructions are fetched, decoded to Mops, renamed, dispatched; a Mop may
split into two uops at dispatch; uops then issue **out of order** to one of
eight pipelines, each accepting and completing one uop per cycle:

| # | Pipeline | Accepts |
| --- | --- | --- |
| 1 | Branch | branch uops |
| 2 | Integer Single-Cycle 0 | integer ALU |
| 3 | Integer Single-Cycle 1 | integer ALU |
| 4 | Integer Single/Multi-Cycle | shift-ALU, multiply, divide, CRC, SAD |
| 5 | Load/Store AGU 0 | load, store, special memory |
| 6 | Load/Store AGU 1 | load, store, special memory |
| 7 | FP/ASIMD-0 | ASIMD ALU/misc/int-mul, FP cvt/misc/add/mul/div/sqrt, crypto, **store data** |
| 8 | FP/ASIMD-1 | ASIMD ALU/misc, FP misc/add/mul, ASIMD shift, **store data** |

This reconciles the tables' port letters: **I** = pipes 2–4 (hence basic ALU
throughput **3**), **M** = pipe 4 only (throughput 1), **L** = pipes 5–6,
**D** (store data) = pipes 7–8, **B** = pipe 1, **V0/V1** = pipes 7–8.

**Consequence for the current model:** the live table is `alu = 2`,
`mem = 2`, `max_issue_per_cycle = 2`
([bench/wrela-cost-v1.toml](../bench/wrela-cost-v1.toml)). Real A76 is **3**
integer, **2** AGU, **8** pipelines, 8 uops/cycle dispatch. The current model
under-issues by ~4×, systematically over-costing independent work and
therefore *under*-crediting any opt that increases ILP.

### Front-end and out-of-order window

- **Dispatch (T1, SOG §4.1):** up to **4 Mops/cycle** processed; up to
  **8 uops/cycle** dispatched, subject to ≤2 uops to **B**; ≤4 to **S**
  (single-cycle integer); ≤2 to **M**; ≤2 to **each V**; ≤2 to **each L**.
  Oversubscription resolves oldest-to-youngest.
- **Decode/rename (T4):** 4 instructions per cycle — consistent with T1.
- **Out-of-order window (T4):** **128** in-flight instructions via a hybrid
  commit structure (instruction management split from register reclaim);
  **8 issue queues**, one per pipeline. Corroborated across AnandTech,
  WikiChip, and secondary deep dives. Pinned as a bounded reorder depth,
  **not** a simulated ROB (decision 1606).
- **Dispatch stall (T1, SOG §4.2):** a V-pipe uop with more than one
  quad-word register source previously written as single words stalls
  dispatch 3 cycles, first occurrence only. **wrela emits no such pattern**
  — recorded N/A in the inventory rather than silently skipped.

| Load register, reg offset, scale by 2 | `LDRH`, `LDRSH` | 5 | 2 | I, L |
| Load pair, W-form | `LDP` | 4 | 2 | L |
| Load pair, X-form | `LDP` | 4 | 1 | L |
| Store register (common forms) | `STR`/`STUR`/`STRB`/… | **1** | 2 | L, D |
| Store pair, X-form | `STP` | 1 | 1 | L, D |

Notes carrying model obligations:

- **Load latency 4 assumes an L1D hit** (§3.9 states this explicitly). The
  miss path is the cache model's job, not the table's.
- **Store latency 1 is to the store buffer**, not to cache: stores are split
  into address + data uops at dispatch and "buffered and committed in the
  background" (§3.10). The data uop occupies a **V pipe**, so store-heavy
  streams contend with FP/ASIMD — a contention the current 2-port model
  cannot express at all.
- **Divide is iterative and blocks subsequent divides on pipe M until
  complete**, with data-dependent early termination (§3.6 note 1). A range,
  not a scalar → sweep, and model the pipe block.
- **Multiply high stalls pipe M for 3 extra cycles** before any other M uop
  issues (§3.6 note 5); **X-form MAC stalls it 2 extra** (note 4). Both
  matter: `narrow_to_width` and checked-multiply overflow emit
  `SMULH`/`UMULH`.
- **`MOVZ`/`MOVK` are 1-cycle, throughput 3, port I.** NarrowImm's win is
  therefore almost entirely *fetch/footprint*, not latency. Item K must
  re-examine whether it still wins for the reason M19 believed.

| Block | Added latency | Reading |
| --- | --- | --- |
| 1 KiB – 64 KiB | 0.0 ns | fits 64 KiB L1D — **confirms L1D size** |
| 128 KiB | 1.1 ns | L2 |
| 256 KiB | 1.6 ns | L2 |
| 512 KiB | 1.9 ns | L2, at capacity — **confirms 512 KiB L2** |
| 1 MiB | 8.3 ns | L3 |

**This curve is why hardware validation is not needed.** Its inflections land
exactly on 64 KiB / 512 KiB / 2 MiB, independently confirming the geometry on
this board rather than on generic A76 silicon.

**Latency brackets (rechecked this pass; three independent directions now
converge).** At 2.4 GHz, 1 cycle = 0.41667 ns; the curve's figures are
*additional* to an L1 hit, so absolute = curve + 4.

| Level | From the T3 curve | T4 generic A76 | Bracket | **Pinned (1609)** |
| --- | --- | --- | --- | --- |
| L1D hit | — (T1 = 4) | 4 | — | **4** |
| L2 | ~7–9 cyc | 9 (×2 sources) – 11 (7-cpu) | 9–11 | **11** |
| L3 | ~24–33 cyc | **26–31 load-to-use** (DSU 2–4 MiB); 35 (7-cpu) | 26–35 | **35** |
| DRAM | ~289 cyc | ~347 (7-cpu: 11 cyc + 140 ns) | 289–347 | **347** |

The L3 figure is the one this pass improved: an independent vendor-adjacent
**load-to-use 26–31 cycles** for a 2–4 MiB DSU L3 brackets the T3 curve's
24–33 from the other side, so the L3 term is now the best-supported number in
the model after L1.

**Honest caveat, recorded because it changes interpretation:** random
single-read over 64 MiB with 4 KiB pages overflows the 1280-entry L2 TLB, so
the saturated 118.7 ns is DRAM **plus page walk**, not pure DRAM. For a cost
model that is the realistic figure and the conservative direction, so it is
used and labelled rather than corrected. It also means the T3 curve is the
only bracket the model has on TLB walk cost — see the inventory.

### Branch prediction and fetch (T4 penalty; T1 front-end rules)

- **Mispredict penalty: 14 cycles**, agreed by two independent third-party
  sources (7-cpu measured; A76 microarchitecture write-ups). A minority
  secondary source says 11; **11–14 is the sweep range**.
- Front-end rules with direct model consequences (T1, SOG §4.8): avoid more
  than **4 branches per aligned 32-byte** region; keep a branch and its
  target in the same **2 MiB** region; align subroutine entries and branch
  targets to **32 B**; a loop of **≤ 32 instruction bytes** should sit inside
  one aligned 32-byte region.
- **Range-crossing penalty** (T4): 6 cycles for 64–2048 B, 1 cycle at 4096 B.

**Why a real mispredict penalty is now safe, when M19's had to be zero.** The
current table sets `branch_penalty = 0`, with the reasoning recorded in
[bench/wrela-cost-v1.toml](../bench/wrela-cost-v1.toml): the model has no
predictor, so it can never argue a branch *is* mispredicted, and charging
mispredict cost would over-credit branch *removal* — making if-conversion look
like a multi-cycle win when a well-predicted branch costs the real machine
nothing. Block-grain `f` dissolves that: per-block counts give every branch
its taken ratio, so a **bias-derived** charge is ~0 for a well-predicted
branch and full for a near-50/50 one. Deleting a predictable branch earns ~0,
which is correct. The penalty becomes chargeable *because* item C exists —
which is why H gates on C.

**A consequence worth stating up front:** wrela emits an abort branch for
every check (`compiler.codegen.naive-locked`), and those branches are
always-not-taken in any run that does not abort. Under a bias-derived model
they cost ~0 mispredict — so the "emit every check" policy is far cheaper on
real A76 than the current model can argue. Item H should record that, because
it is the first quantitative defence of a core doctrine choice the ruler has
ever been able to produce.

### Prefetchers (T2 in kind, unmodelled by choice)

The load-store unit has a hardware prefetcher: the load side uses the
**virtual** address and prefetches into **L1 and L2**; the store side uses the
**physical** address and prefetches into **L2 only**. Existence and targets
are documented; aggressiveness, depth, and stream-detection thresholds are
not.

**Decision: do not model it, and state the resulting bias.** An unmodelled
prefetcher means strided loads are charged full miss cost, so the model
**over-costs sequential and strided loops** and therefore **under-credits any
opt that improves stride regularity**. That is a known bias in the safe
direction (decision 1609), and naming it here is what makes it safe: an
implementer who later sees a stride-improving opt score poorly must read this
paragraph rather than conclude the opt is worthless.

That is uncomfortable in a specific way worth stating plainly: for a
**message-passing machine on 3 cores**, cross-core publish/acquire cost is
plausibly the single most consequential thing the ruler could measure, and it
is exactly the thing the vendor optimization guide does not price. Rows 17–18
are therefore not a footnote — they get their own item (G), their own sweep
dimensions, and their own oracle. And under decision 1602 they **cannot be
pinned at all**, which is the provenance rule doing its job: the model is
forced to admit that its most important number is a range, rather than
quietly asserting 1 cycle as it does today.

## The soundness posture

M19's ruler is safe because it is **crude in a known direction**: 04 §5
requires that a proxy win never imply a real-machine loss, and the model
under-credits when unsure. Accuracy removes that margin. Three changes here
make the model *cheaper* — 3 integer ports instead of 2, 8-wide dispatch
instead of 2, and NZCV de-serialization — and each one lets a candidate look
better.

With hardware validation permanently out of scope, **nothing downstream will
catch an optimistic error**. Safety comes entirely from four places, all
load-bearing rather than ceremonial:

1. **Decision 1609**, the over-cost rule: pinned values take the pessimistic
   end of every bracket; unmodelled mechanisms never become discounts.
2. **Provenance tiers** (decision 1602): a T5 value cannot be pinned, so the
   model can never quietly rest on a guess — and rows 13/17/18/19 show this
   is not hypothetical.
3. **The ∀ sweep** (decision 1604): a candidate that only wins at a
   favourable point in the residual box does not land.
4. **The ruler oracles** (item L): null-opt, monotonicity, cliff witnesses,
   the ∃-cheat regression, and a per-dimension assertion that each pinned
   value really is its bracket's pessimistic end.

If an implementer finds a case where accuracy and conservatism genuinely
conflict and no ordering is obvious, the item **stops and records the
conflict** rather than picking. A model accurate on average and optimistic in
the tail lands an opt that loses on the real board — precisely the failure
04 §5 exists to prevent, with no second line of defence.

## Decisions

**1600. Full A76 microarchitectural model.** Ports, dispatch constraints,
bounded out-of-order issue, per-group latency/throughput, real cache geometry
with associativity, TLBs, alignment penalties, cross-core/barrier costs, and
a bias-derived branch model. Supersedes the first draft's capacity-only
decision.

**1601. Pinned to Pi 5 / BCM2712 / A76 facts** in a new `bench/a76-pi5.toml`,
digested, relock discipline copied from
[bench/workloads.toml](../bench/workloads.toml). `ghz = 2.4` moves here;
`ghz.rs`'s constant becomes a fallback, not a second source of truth.

**1602. Provenance tiers replace validation.** Every row carries its tier
(T1–T5) in the file, machine-checked rather than commented: `table.rs`
**rejects a pinned T5 row**, and the dump prints a **provenance digest**
summarizing the tier mix. Fidelity is claimed to the **published record**,
never to silicon this project measured. Rejected permanently: PMU counter
reads, PC-range attribution under replay, predicted-vs-physical agreement
reports. The measurement exists already (T3/T4); redoing it is not this
project's work.

**1603. I-side, TLB, and cross-core classification are per **core**, from
placement.** `PlacementTable::core_of`
([placement.rs:105](../crates/wrela-compiler/src/placement.rs:105)) seals
every actor and driver to a core, so per-core hot-text footprint is
statically computable (what the 64 KiB 4-way L1I and 48-entry I-TLB must
hold) **and so is whether a given load reads a line another core wrote** —
which is what makes dimension 18 classifiable despite its T5 latency. This is
the one place the model can be *better* than a general-purpose compiler's,
and it follows from sealed placement.

**1604. Pin the bracket's pessimistic end; sweep the bracket.** The sweep box
holds exactly: L2 (9–11), L3 (26–35), DRAM (289–347), mispredict penalty
(11–14), divide latency range, range-crossing penalty, **store-to-load
forwarding latency**, **TLB walk cost**, **`DMB` cost**, **cross-core snoop
cost**, **system-register flush cost**, effective L3 size (1–2 MiB, shared
with the housekeeping core), and every other T5 row. A candidate must not lose
at **any** box point (∀). No `∃`-form win predicate exists in the API — that
form is a search for a flattering assumption.

**1605. Goldens pin the canonical point only.** `--stage=cost` and the report
Cost summary stay single-valued at `a76-pi5`. The sweep lives in `opts::win`
and never enters a pinned dump.

**1606. No microarchitectural simulation.** The model is a *scoreboard with a
real port map*, not a cycle simulator: no predictor state machine, no
cache-line state machine, no coherency protocol simulation, no prefetcher
model, no ROB occupancy simulation. Reuse distance + associativity gives a
hit/miss verdict; branch bias gives a mispredict estimate; placement gives a
local/remote verdict; the 128-entry window is a bounded reorder depth. A
simulator would be a second implementation of the machine, no more
validatable than the model, and violates CLAUDE.md's "no layers for their own
sake." Rejected explicitly so nobody grows one incrementally.

**1607. Lane 2 coverage extends to `runtime` and `driver`; the coverage
denominator does not move.** Lane 2 instruments only `app`-owned fns
([codegen.rs:4304](../crates/wrela-compiler/src/codegen.rs:4304),
[codegen.rs:8152](../crates/wrela-compiler/src/codegen.rs:8152)) while
`cost-runtime` is the largest corpus case (2717 of release SUM 4518).
Attaching an app-only `f` would collapse coverage and auto-veto everything
under "coverage may not fall." **Rejected:** redefining coverage to the
instrumented set — the "reward measuring less" failure 04 §5 names.

**1608. The block bridge is proved, not assumed.** Lane 2 ids are assigned
over **MWIR** instructions
([codegen.rs:4426](../crates/wrela-compiler/src/codegen.rs:4426),
[codegen.rs:8389](../crates/wrela-compiler/src/codegen.rs:8389)); `s(b)` is
computed over **emitted-word** ranges
([score.rs:133](../crates/wrela-compiler/src/cost/score.rs:133)). Two
partitions. Codegen's two-pass emission already prefix-sums
`word_offsets[mwir_idx] → word index`, which is the bridge. Item C carries an
oracle that the partitions agree and fails closed on mismatch — never
attribute by nearest offset.

**1609. Round toward over-costing at every residual uncertainty.** Stated in
full under "The soundness posture." One place needs care: for a *penalty*
term whose removal is the win, a larger value is not automatically the safe
choice. The bias-derived branch model resolves that ambiguity — a
well-predicted branch is charged ~0 whatever the penalty is — which is why the
branch term may be real here when M19's had to be zero. The same care applies
to dimension 17: a large `DMB` cost over-credits *removing* a barrier, and
barriers are load-bearing for correctness, so item G must charge barriers
without ever making barrier *removal* look profitable.

### G. Cross-core, barrier, and system-op costs

The item this research pass added, and the one whose *magnitude* is least
supported by any source — which is exactly why it is explicit rather than
buried in a `barrier = 1` row.

**What wrela emits:** four `@dmb` sites at cross-core publish/acquire
(`stdlib/core/runtime.wr:1290`, `:1319` `ishst`; `:1362`, `:1391` `ishld`),
`CostRule::Barrier` and `CostRule::System`
([rule.rs:20](../crates/wrela-compiler/src/cost/rule.rs:20)), and abort
branches on every check.

**Model:**
- **Barrier (row 17).** Charge a swept cost per `DMB`, distinguishing `ishst`
  from `ishld` only if a source justifies it (none found — so one swept row
  for both, and say so). **Freeze 1633:** the charge must never make barrier
  *removal* profitable, since barriers are correctness-load-bearing and
  `machine.cross-core.publish-acquire-barrier` is already a known-risk gap in
  [BLOCKED.md](BLOCKED.md). Implement that as a hard rule in the win oracle,
  not as a hopeful coefficient.
- **Cross-core snoop (row 18).** `PlacementTable` makes local-vs-remote a
  *static* classification: a load whose line is written by an actor on another
  core is remote. Charge remote loads a swept snoop cost above the L3 path.
  This is the term that finally lets the ruler see what a message-passing
  machine actually spends.
- **System-register access (row 19).** SOG §4.10 gives, per register,
  whether access is non-speculative, in-order, or carries a flush
  side-effect — T1 for *which*, T5 for cost. Charge a swept flush cost only
  for the registers §4.10 marks with a flush side-effect; charge ordering
  constraints structurally (in-order = no reorder across it in the window).
- **Abort path (row 20).** Charge the abort branch; do **not** charge a
  handler body, because the handler never returns. Record that the naive
  "emit every check" policy is therefore cheap under this model.

**Cheap:** units — a remote load costs more than an identical local load with
the same reuse distance (the oracle proving placement is consulted); a `DMB`
costs more than an `ADD` and the win oracle refuses a candidate whose only
gain is deleting one; a flush-side-effect register write serializes the window
while an NZCV write does not (pairs with item I); the abort branch is charged
but no handler body is.

### H. Branch model from measured bias

Per-block `f` gives every branch a taken ratio; charge the swept mispredict
penalty scaled by bias (well-predicted ⇒ ~0; near-50/50 ⇒ full). Under
`W_flat` there is no bias information, so **the flat row charges zero
mispredict** — decision 1609 applied honestly: no data, no charge. It also
means a frequency-dependent branch opt cannot be argued on the flat row,
which is correct.

Add the §4.8 front-end terms: >4 branches per aligned 32 B region; branch and
target crossing a 2 MiB region; unaligned subroutine entry / branch target; a
loop over 32 instruction bytes that no longer fits one aligned 32 B region.
Plus the swept range-crossing penalty (row 27).

Record here the abort-branch consequence from the research block: always-not-
taken check branches cost ~0 mispredict, so this is the first quantitative
defence of the emit-every-check doctrine the ruler has been able to produce.

**Cheap:** units — a 99/1 branch is charged ~0 and a 50/50 branch the full
penalty under the same `s(b)`; the flat row charges zero; five branches in one
32 B region cost more than four; a loop crossing the 32 B window costs more
than one inside it; an abort branch at 1/10⁶ taken is charged ~0.

### I. NZCV/SP de-serialization + alignment penalties

SOG §4.10 note 1: NZCV and SP are fully renamed, so the scoreboard's NZCV
serialization is wrong for A76. Remove it. **This lowers costs**, so it can
flip existing rankings — run item K after it and record any flip rather than

Alignment penalties from §4.5: loads crossing a 64 B line; stores crossing a
16 B boundary. wrela's fixed frame uses 8-byte-multiple slots, so both are

term needs no dynamic information at all.

### L. Ruler oracles

Re-assert 04 §5's existing oracles under the new model and extend them:

- **Null-opt:** renaming every scored fn key must not rank as a win — now with
  block-grain `f` attached, at every box point.
- **Monotonicity:** a dead instruction never lowers a schedule, footprint
  cost, or mispredict charge.
- **Over-cost rule (1609):** one unit per swept dimension asserting the pinned
  value is its bracket's pessimistic end. **This is the oracle that replaces
  hardware validation** — if it is weak, nothing else catches an optimistic
  table.
- **Provenance (1629):** a table with a pinned T5 row fails to load; the
  provenance digest changes when any tier changes.
- **Inventory completeness (1632):** a `CostRule` variant with no inventory
  row fails the ledger check. This is what keeps the dimension list honest as
  the rule set grows.
- **Cliff witnesses:** L1I capacity, L1D 4-way conflict, I-TLB span, 32 B
  branch density, local-vs-remote load — each ranks in the expected direction,
  proving the term is live rather than decorative.
- **∃-cheat regression:** a candidate constructed to win only at the box's
  most generous point is vetoed.
- **Barrier-removal refusal (1633):** a candidate whose only gain is deleting
  a `DMB` is refused.
- **Synthetic partition adversary** (the pre-registered experiment): with
  [cost/ab.rs](../crates/wrela-compiler/src/cost/ab.rs)'s `prog()`/`word()`
  helpers, score the same instruction multiset as (i) N small fns + calls vs
  one fused fn and (ii) a loop body ×1 vs ×K unrolled. **Record the numbers;
  assert only what 04 §5 requires** (fusion must not read as a win). If fusion
  does read as a win, that is a hole in the null-opt oracle and the finding is
  the output — do not tune the table to hide it. This finally answers the
  mega-function question on a ruler that can see ports, fetch, trip counts,
  and cross-core traffic; it lands no transformation.

## Why this is a plan and not a cleanup

1. It lifts two explicit ledger hard-cuts and rewrites assertions in **two
   normative documents**, five code comments, two pinned dump strings, seven
   ledger notes, and seven ROADMAP passages (item A's inventory). A missed
   site leaves the tree self-contradicting, and CLAUDE.md makes the docs
   ground truth over the code.
2. It replaces the scoring core — ports, memory model, branch term, and a new
   cross-core term — moving the table digest repeatedly and with it every
   `cost-*` golden and every report Cost summary.
3. It **widens `CostRule::ALL`**, so the emitted-instruction census ratchet
   and every rule-count Terms line move.
4. It changes what the optimization gate admits by retiring the words veto —
   a change to what the project will let itself land.
5. It inverts the model's safety posture with **no hardware oracle behind
   it**, so decisions 1602, 1604, and 1609 and item L are not paperwork —
   they are the entire safety argument and must be reviewed as such.
6. Its most consequential dimension for *this* machine — cross-core
   publish/acquire cost — is unpriced by every available source, so the plan
   has to be explicit that the ruler's most important number is a swept range
   rather than a fact. That admission belongs in a reviewed plan, not in a
   commit message.
