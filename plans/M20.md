## The mandate (human, 2026-07-29)

Go all in on Pi 5's specific microarchitecture. Model the machine as
accurately as the published record permits, and accept Pi-5-specificity as
the point rather than a limitation: the model is for *this* board, and opts
tuned on it are expected to transfer to larger machines merely uncalibrated,
not wrong — because Pi 5 is small, so its capacity and issue pressure bind
first, and an opt that wins under binding pressure is not made worse by
slack.

**This reverses M20's first draft.** That draft's decision 1600 was "model
capacity; never policy," with an A76 port map named as a rejected
alternative. That is now the deliverable. Recorded once so it is not
relitigated: the earlier rejection reasoned that ILP fidelity buys accuracy
on the axis this machine wins least on (ROADMAP's "overheads that surround
compute … rather than … ALU throughput"). That reasoning still holds *for
prioritization* — which is why block grain (item C) comes first, and why the
cross-core/barrier dimension (item G) is treated as first-class rather than
as an afterthought behind the port map.

## The research

### Source tiers

Every row in the model carries one. The tier is data, not decoration: it
decides whether a value may be pinned (decision 1602) and how the over-cost
rule applies (decision 1609).

| Tier | Meaning | Sources |
| --- | --- | --- |
| **T1** | Vendor, this core, normative | Cortex-A76 Software Optimization Guide, PJDOC-466751330-7215 v8.0 (46pp) — "SOG §x.y" |
| **T2** | Vendor, this core or cluster, descriptive | Cortex-A76 Core TRM (100798); DynamIQ Shared Unit TRM (100453) |
| **T3** | Third-party measured, **on this board** | tinymembench random single-read curve, Raspberry Pi 5 / BCM2712 |
| **T4** | Third-party measured / derived, generic A76 | 7-cpu.com; WikiChip; AnandTech microarchitecture coverage |
| **T5** | Unresolved, conflicting, **or unpriced by any source** | → sweep box only, never pinned |

**T5 includes "unpriced by absence."** Verified this pass: the SOG contains
**no** barrier (`DMB`/`DSB`/`ISB`), no load/store-exclusive, no
system-register, and no prefetch instruction entry anywhere in its 46 pages —
its instruction tables run §3.3–§3.21 (branch, arithmetic/logical, move/shift,
divide/multiply, saturating, misc data-processing, load, store, FP, ASIMD,
crypto, CRC) and its special considerations §4.1–§4.12 contain no barrier
section. Those costs are therefore T5 for magnitude even where the *mechanism*
is T1/T2. This matters more here than it would elsewhere — see the dimension
inventory.

### The eight execution pipelines (T1, SOG §2.1 — definitive)

Instructions are fetched, decoded to Mops, renamed, dispatched; a Mop may
split into two uops at dispatch; uops then issue **out of order** to one of
eight pipelines, each accepting and completing one uop per cycle:

| # | Pipeline | Accepts |
| --- | --- | --- |
| 1 | Branch | branch uops |
| 2 | Integer Single-Cycle 0 | integer ALU |
| 3 | Integer Single-Cycle 1 | integer ALU |
| 4 | Integer Single/Multi-Cycle | shift-ALU, multiply, divide, CRC, SAD |
| 5 | Load/Store AGU 0 | load, store, special memory |
| 6 | Load/Store AGU 1 | load, store, special memory |
| 7 | FP/ASIMD-0 | ASIMD ALU/misc/int-mul, FP cvt/misc/add/mul/div/sqrt, crypto, **store data** |
| 8 | FP/ASIMD-1 | ASIMD ALU/misc, FP misc/add/mul, ASIMD shift, **store data** |

This reconciles the tables' port letters: **I** = pipes 2–4 (hence basic ALU
throughput **3**), **M** = pipe 4 only (throughput 1), **L** = pipes 5–6,
**D** (store data) = pipes 7–8, **B** = pipe 1, **V0/V1** = pipes 7–8.

**Consequence for the current model:** the live table is `alu = 2`,
`mem = 2`, `max_issue_per_cycle = 2`
([bench/wrela-cost-v1.toml](../bench/wrela-cost-v1.toml)). Real A76 is **3**
integer, **2** AGU, **8** pipelines, 8 uops/cycle dispatch. The current model
under-issues by ~4×, systematically over-costing independent work and
therefore *under*-crediting any opt that increases ILP.

### Front-end and out-of-order window

- **Dispatch (T1, SOG §4.1):** up to **4 Mops/cycle** processed; up to
  **8 uops/cycle** dispatched, subject to ≤2 uops to **B**; ≤4 to **S**
  (single-cycle integer); ≤2 to **M**; ≤2 to **each V**; ≤2 to **each L**.
  Oversubscription resolves oldest-to-youngest.
- **Decode/rename (T4):** 4 instructions per cycle — consistent with T1.
- **Out-of-order window (T4):** **128** in-flight instructions via a hybrid
  commit structure (instruction management split from register reclaim);
  **8 issue queues**, one per pipeline. Corroborated across AnandTech,
  WikiChip, and secondary deep dives. Pinned as a bounded reorder depth,
  **not** a simulated ROB (decision 1606).
- **Dispatch stall (T1, SOG §4.2):** a V-pipe uop with more than one
  quad-word register source previously written as single words stalls
  dispatch 3 cycles, first occurrence only. **wrela emits no such pattern**
  — recorded N/A in the inventory rather than silently skipped.

| Load pair, W-form | `LDP` | 4 | 2 | L |

| Store register (common forms) | `STR`/`STUR`/`STRB`/… | **1** | 2 | L, D |
| Store pair, X-form | `STP` | 1 | 1 | L, D |

Notes carrying model obligations:

- **Load latency 4 assumes an L1D hit** (§3.9 states this explicitly). The
  miss path is the cache model's job, not the table's.
- **Store latency 1 is to the store buffer**, not to cache: stores are split
  into address + data uops at dispatch and "buffered and committed in the
  background" (§3.10). The data uop occupies a **V pipe**, so store-heavy
  streams contend with FP/ASIMD — a contention the current 2-port model
  cannot express at all.
- **Divide is iterative and blocks subsequent divides on pipe M until
  complete**, with data-dependent early termination (§3.6 note 1). A range,
  not a scalar → sweep, and model the pipe block.
- **Multiply high stalls pipe M for 3 extra cycles** before any other M uop
  issues (§3.6 note 5); **X-form MAC stalls it 2 extra** (note 4). Both
  matter: `narrow_to_width` and checked-multiply overflow emit
  `SMULH`/`UMULH`.
- **`MOVZ`/`MOVK` are 1-cycle, throughput 3, port I.** NarrowImm's win is
  therefore almost entirely *fetch/footprint*, not latency. Item K must
  re-examine whether it still wins for the reason M19 believed.

**Latency brackets (rechecked this pass; three independent directions now
converge).** At 2.4 GHz, 1 cycle = 0.41667 ns; the curve's figures are
*additional* to an L1 hit, so absolute = curve + 4.

| Level | From the T3 curve | T4 generic A76 | Bracket | **Pinned (1609)** |
| --- | --- | --- | --- | --- |
| L1D hit | — (T1 = 4) | 4 | — | **4** |
| L2 | ~7–9 cyc | 9 (×2 sources) – 11 (7-cpu) | 9–11 | **11** |
| L3 | ~24–33 cyc | **26–31 load-to-use** (DSU 2–4 MiB); 35 (7-cpu) | 26–35 | **35** |
| DRAM | ~289 cyc | ~347 (7-cpu: 11 cyc + 140 ns) | 289–347 | **347** |

The L3 figure is the one this pass improved: an independent vendor-adjacent
**load-to-use 26–31 cycles** for a 2–4 MiB DSU L3 brackets the T3 curve's
24–33 from the other side, so the L3 term is now the best-supported number in
the model after L1.

**Honest caveat, recorded because it changes interpretation:** random
single-read over 64 MiB with 4 KiB pages overflows the 1280-entry L2 TLB, so
the saturated 118.7 ns is DRAM **plus page walk**, not pure DRAM. For a cost
model that is the realistic figure and the conservative direction, so it is
used and labelled rather than corrected. It also means the T3 curve is the
only bracket the model has on TLB walk cost — see the inventory.

### Branch prediction and fetch (T4 penalty; T1 front-end rules)

- **Mispredict penalty: 14 cycles**, agreed by two independent third-party
  sources (7-cpu measured; A76 microarchitecture write-ups). A minority
  secondary source says 11; **11–14 is the sweep range**.
- Front-end rules with direct model consequences (T1, SOG §4.8): avoid more
  than **4 branches per aligned 32-byte** region; keep a branch and its
  target in the same **2 MiB** region; align subroutine entries and branch
  targets to **32 B**; a loop of **≤ 32 instruction bytes** should sit inside
  one aligned 32-byte region.
- **Range-crossing penalty** (T4): 6 cycles for 64–2048 B, 1 cycle at 4096 B.

**Why a real mispredict penalty is now safe, when M19's had to be zero.** The
current table sets `branch_penalty = 0`, with the reasoning recorded in
[bench/wrela-cost-v1.toml](../bench/wrela-cost-v1.toml): the model has no
predictor, so it can never argue a branch *is* mispredicted, and charging
mispredict cost would over-credit branch *removal* — making if-conversion look
like a multi-cycle win when a well-predicted branch costs the real machine
nothing. Block-grain `f` dissolves that: per-block counts give every branch
its taken ratio, so a **bias-derived** charge is ~0 for a well-predicted
branch and full for a near-50/50 one. Deleting a predictable branch earns ~0,
which is correct. The penalty becomes chargeable *because* item C exists —
which is why H gates on C.

**A consequence worth stating up front:** wrela emits an abort branch for
every check (`compiler.codegen.naive-locked`), and those branches are
always-not-taken in any run that does not abort. Under a bias-derived model
they cost ~0 mispredict — so the "emit every check" policy is far cheaper on
real A76 than the current model can argue. Item H should record that, because
it is the first quantitative defence of a core doctrine choice the ruler has
ever been able to produce.

### Prefetchers (T2 in kind, unmodelled by choice)

The load-store unit has a hardware prefetcher: the load side uses the
**virtual** address and prefetches into **L1 and L2**; the store side uses the
**physical** address and prefetches into **L2 only**. Existence and targets
are documented; aggressiveness, depth, and stream-detection thresholds are
not.

**Decision: do not model it, and state the resulting bias.** An unmodelled
prefetcher means strided loads are charged full miss cost, so the model
**over-costs sequential and strided loops** and therefore **under-credits any
opt that improves stride regularity**. That is a known bias in the safe
direction (decision 1609), and naming it here is what makes it safe: an
implementer who later sees a stride-improving opt score poorly must read this
paragraph rather than conclude the opt is worthless.

their charge alongside `DMB`.

**The finding of this pass is rows 13, 17, 18, and 19.** All four are things
wrela actually emits, all four are currently priced at 1–2 cycles by a table
row with no source behind it (`barrier = 1`, `system = 1`,
`store_stack = 1`), and all four are **unpriced by every source found** — the
SOG has no barrier, exclusive, system-register, or prefetch entry at all.

That is uncomfortable in a specific way worth stating plainly: for a
**message-passing machine on 3 cores**, cross-core publish/acquire cost is
plausibly the single most consequential thing the ruler could measure, and it
is exactly the thing the vendor optimization guide does not price. Rows 17–18
are therefore not a footnote — they get their own item (G), their own sweep
dimensions, and their own oracle. And under decision 1602 they **cannot be
pinned at all**, which is the provenance rule doing its job: the model is
forced to admit that its most important number is a range, rather than
quietly asserting 1 cycle as it does today.

## The soundness posture

M19's ruler is safe because it is **crude in a known direction**: 04 §5
requires that a proxy win never imply a real-machine loss, and the model
under-credits when unsure. Accuracy removes that margin. Three changes here
make the model *cheaper* — 3 integer ports instead of 2, 8-wide dispatch
instead of 2, and NZCV de-serialization — and each one lets a candidate look
better.

With hardware validation permanently out of scope, **nothing downstream will
catch an optimistic error**. Safety comes entirely from four places, all
load-bearing rather than ceremonial:

1. **Decision 1609**, the over-cost rule: pinned values take the pessimistic
   end of every bracket; unmodelled mechanisms never become discounts.
2. **Provenance tiers** (decision 1602): a T5 value cannot be pinned, so the
   model can never quietly rest on a guess — and rows 13/17/18/19 show this
   is not hypothetical.
3. **The ∀ sweep** (decision 1604): a candidate that only wins at a
   favourable point in the residual box does not land.
4. **The ruler oracles** (item L): null-opt, monotonicity, cliff witnesses,
   the ∃-cheat regression, and a per-dimension assertion that each pinned
   value really is its bracket's pessimistic end.

If an implementer finds a case where accuracy and conservatism genuinely
conflict and no ordering is obvious, the item **stops and records the
conflict** rather than picking. A model accurate on average and optimistic in
the tail lands an opt that loses on the real board — precisely the failure
04 §5 exists to prevent, with no second line of defence.

## Decisions

**1600. Full A76 microarchitectural model.** Ports, dispatch constraints,
bounded out-of-order issue, per-group latency/throughput, real cache geometry
with associativity, TLBs, alignment penalties, cross-core/barrier costs, and
a bias-derived branch model. Supersedes the first draft's capacity-only
decision.

**1601. Pinned to Pi 5 / BCM2712 / A76 facts** in a new `bench/a76-pi5.toml`,
digested, relock discipline copied from
[bench/workloads.toml](../bench/workloads.toml). `ghz = 2.4` moves here;
`ghz.rs`'s constant becomes a fallback, not a second source of truth.

**1602. Provenance tiers replace validation.** Every row carries its tier
(T1–T5) in the file, machine-checked rather than commented: `table.rs`
**rejects a pinned T5 row**, and the dump prints a **provenance digest**
summarizing the tier mix. Fidelity is claimed to the **published record**,
never to silicon this project measured. Rejected permanently: PMU counter
reads, PC-range attribution under replay, predicted-vs-physical agreement
reports. The measurement exists already (T3/T4); redoing it is not this
project's work.

**1603. I-side, TLB, and cross-core classification are per **core**, from
placement.** `PlacementTable::core_of`
([placement.rs:105](../crates/wrela-compiler/src/placement.rs:105)) seals
every actor and driver to a core, so per-core hot-text footprint is
statically computable (what the 64 KiB 4-way L1I and 48-entry I-TLB must
hold) **and so is whether a given load reads a line another core wrote** —
which is what makes dimension 18 classifiable despite its T5 latency. This is
the one place the model can be *better* than a general-purpose compiler's,
and it follows from sealed placement.

**1604. Pin the bracket's pessimistic end; sweep the bracket.** The sweep box
holds exactly: L2 (9–11), L3 (26–35), DRAM (289–347), mispredict penalty
(11–14), divide latency range, range-crossing penalty, **store-to-load
forwarding latency**, **TLB walk cost**, **`DMB` cost**, **cross-core snoop
cost**, **system-register flush cost**, effective L3 size (1–2 MiB, shared
with the housekeeping core), and every other T5 row. A candidate must not lose
at **any** box point (∀). No `∃`-form win predicate exists in the API — that
form is a search for a flattering assumption.

**1605. Goldens pin the canonical point only.** `--stage=cost` and the report
Cost summary stay single-valued at `a76-pi5`. The sweep lives in `opts::win`
and never enters a pinned dump.

**1606. No microarchitectural simulation.** The model is a *scoreboard with a
real port map*, not a cycle simulator: no predictor state machine, no
cache-line state machine, no coherency protocol simulation, no prefetcher
model, no ROB occupancy simulation. Reuse distance + associativity gives a
hit/miss verdict; branch bias gives a mispredict estimate; placement gives a
local/remote verdict; the 128-entry window is a bounded reorder depth. A
simulator would be a second implementation of the machine, no more
validatable than the model, and violates CLAUDE.md's "no layers for their own
sake." Rejected explicitly so nobody grows one incrementally.

**1607. Lane 2 coverage extends to `runtime` and `driver`; the coverage
denominator does not move.** Lane 2 instruments only `app`-owned fns
([codegen.rs:4304](../crates/wrela-compiler/src/codegen.rs:4304),
[codegen.rs:8152](../crates/wrela-compiler/src/codegen.rs:8152)) while
`cost-runtime` is the largest corpus case (2717 of release SUM 4518).
Attaching an app-only `f` would collapse coverage and auto-veto everything
under "coverage may not fall." **Rejected:** redefining coverage to the
instrumented set — the "reward measuring less" failure 04 §5 names.

**1608. The block bridge is proved, not assumed.** Lane 2 ids are assigned
over **MWIR** instructions
([codegen.rs:4426](../crates/wrela-compiler/src/codegen.rs:4426),
[codegen.rs:8389](../crates/wrela-compiler/src/codegen.rs:8389)); `s(b)` is
computed over **emitted-word** ranges
([score.rs:133](../crates/wrela-compiler/src/cost/score.rs:133)). Two
partitions. Codegen's two-pass emission already prefix-sums
`word_offsets[mwir_idx] → word index`, which is the bridge. Item C carries an
oracle that the partitions agree and fails closed on mismatch — never
attribute by nearest offset.

**1609. Round toward over-costing at every residual uncertainty.** Stated in
full under "The soundness posture." One place needs care: for a *penalty*
term whose removal is the win, a larger value is not automatically the safe
choice. The bias-derived branch model resolves that ambiguity — a
well-predicted branch is charged ~0 whatever the penalty is — which is why the
branch term may be real here when M19's had to be zero. The same care applies
to dimension 17: a large `DMB` cost over-credits *removing* a barrier, and
barriers are load-bearing for correctness, so item G must charge barriers
without ever making barrier *removal* look profitable.

### F. Memory hierarchy: associativity, reuse distance, TLB, store buffer

Replace the 8-entry window + 4-key cap

**Store buffer and forwarding (inventory row 13).** Store latency 1 is to the
buffer, not to cache. A load of a slot a recent store wrote is satisfied by
forwarding — which is the **dominant pattern in a spill-everything frame**, so
this row matters more here than on most machines. Its cost is T5: model
forwarding as a swept latency, and pin nothing.

Per-core L1I footprint **and I-TLB pressure** from `PlacementTable` (decision
1603): a block is hot text when measured `f > 0`; contribution is its word
range rounded to 64 B; charge on exceeding 64 KiB, then L2; and charge
separately when a core's hot text spans more than 48 pages (I-TLB), then 1280
(L2 TLB). D-side TLB span likewise, with walk cost swept (row 14). Under
`W_flat` (`f ≡ 1`) every block is hot, making the flat row a static-footprint
row — assert that degenerate case. The image report gains the per-core
text/TLB budget line from item A.

Effective L3 is a sweep dimension, 1–2 MiB, because the housekeeping Linux
core shares it (row 38).

`working_set_surcharge` survives only if a unit shows it still adds ranking
information once reuse distance exists; otherwise delete it. Do not leave two
overlapping footprint terms — record which, and why, here.

**Record (landed 2026-07-29).** Five things this item's text did not
anticipate, each measured rather than reasoned.

1. **`working_set_surcharge` is DELETED, and the unit decided it.** Reuse
   distance charges the same direction through the mechanism the machine has
   and by a larger margin — an extra distinct **line** is a compulsory
   reference at `lat_l2` (7 cycles over an L1 hit) against the surcharge's 2
   — so it adds no ranking information. Where the two disagree, the surcharge
   was charging for pressure the geometry says does not exist: five live
   lines conflict with nothing in a 64 KiB 4-way cache. Its pre-M20 witness
   was also polluted — offsets 0/8/16/24/32/40 are all **one** 64 B line, so
   its "distinct keys" were one line and its deltas came from the added
   instructions. `MemCosts` / `CostTable::mem()` go with it: once the memory
   model reads `[geometry]` and `[sweep]` directly, a derived second
   spelling of the leaf latencies has nothing left to earn.
2. **A store now write-allocates instead of invalidating, and that is the
   whole cheapening.** Store-semantics change alone, on the six `cost-*`
   cases: **-38 / -117 / -96 / -33 / -35 / -504** proxy-cycles. The
   **forwarding path itself contributes exactly 0 at the pinned point**, by
   construction — `store_to_load_forwarding` is pinned at `lat_l1d_hit` = 4
   and a store leaves its line in L1D either way. At the bracket's low end
   (1) it moves the corpus by a further -18 / -25 / -35 / -15 / -35 / -171,
   so the term is live under item J's ∀ sweep rather than decorative, and
   the forwarding oracle is written on the **verdict** plus the swept
   dimension rather than on the pinned latency.
3. **A first touch is charged at its class's home level, not at DRAM**
   (`Stack` → `lat_l2`, `Cold` → `lat_l3`). DRAM would be the larger number
   but not the safe one: it is a per-load charge whose *removal* is a win,
   so a uniform 347 over-credits deleting a load — the same
   removal-sensitivity `[sweep.dmb_cost]` records for barriers. Accuracy and
   conservatism genuinely conflicted here and the conflict is recorded per
   decision 1609 rather than picked silently; the same applies to
   write-allocate (item 2), which is documented Core-TRM behaviour rather
   than a rounded guess.
4. **The store-buffer depth is a floor, not a fact.** No source gives one.
   Shallow is the over-cost end (forwarding is bracketed at or below
   `lat_l1d_hit`, so forwarding *less* costs more), so the depth is the
   shallowest at which the mechanism exists at all: one cycle's worth of
   store address uops, `cap_l_each` × the pipes `port_l` names = 4, derived
   from `[pipelines]` rather than invented.
5. **The finding item J has to act on: under `W_flat` the hot-text budget is

   everything. The budget only becomes a usable gate under item C's measured
   `f`. Page spans are comfortable either way (23 text pages against 48; 6

The per-core charge is **reported, not added to `total_proxy_cycles`**: 04 §5
makes the unified cost `Σ f(b)×s(b)` over per-fn schedules and the dump

The item this research pass added, and the one whose *magnitude* is least
supported by any source — which is exactly why it is explicit rather than
buried in a `barrier = 1` row.

**What wrela emits:** **six** `@dmb` sites, not four — item G's census

`CostRule::Barrier` and `CostRule::System`

- **Cross-core snoop (row 18).** `PlacementTable` makes local-vs-remote a

### H. Branch model from measured bias

Per-block `f` gives every branch a taken ratio; charge the swept mispredict
penalty scaled by bias (well-predicted ⇒ ~0; near-50/50 ⇒ full). Under
`W_flat` there is no bias information, so **the flat row charges zero
mispredict** — decision 1609 applied honestly: no data, no charge. It also
means a frequency-dependent branch opt cannot be argued on the flat row,
which is correct.

Add the §4.8 front-end terms: >4 branches per aligned 32 B region; branch and
target crossing a 2 MiB region; unaligned subroutine entry / branch target; a
loop over 32 instruction bytes that no longer fits one aligned 32 B region.
Plus the swept range-crossing penalty (row 27).

Record here the abort-branch consequence from the research block: always-not-
taken check branches cost ~0 mispredict, so this is the first quantitative
defence of the emit-every-check doctrine the ruler has been able to produce.

**Cheap:** units — a 99/1 branch is charged ~0 and a 50/50 branch the full
penalty under the same `s(b)`; the flat row charges zero; five branches in one
32 B region cost more than four; a loop crossing the 32 B window costs more
than one inside it; an abort branch at 1/10⁶ taken is charged ~0.

**Record (landed 2026-07-30).** The model lives in one file, `cost/branch.rs`;
`cost/score.rs`'s `branch_mispredict_charge` seam delegates to it, and
`CostTable::branch_penalty()` — the pre-M20 accessor returning a constant 0
"only until item H" — is **deleted** rather than set to a number, as its own
note promised. Seven things measured or found rather than reasoned.

1. **The scaling function is a bound, not a simulation.**
   `charge = ceil(mispredict_penalty × 2·min(t,n)/(t+n))`. `min(t,n)/(t+n)` is
   exactly the mispredict rate of the **majority-direction predictor** — the
   best any predictor can do knowing only this branch's marginal bias — so a
   history-based predictor can only do better and the term is an **upper
   bound on the rate obtainable from the datum the model holds**, doubled
   only to normalise this item's own mandated endpoint. Decision 1606 is
   satisfied structurally rather than by assertion: no predictor state exists
   anywhere (no table, no history register, no update rule, nothing mutated
   as words are walked) and the charge is a **pure function** of
   `(penalty, taken, not_taken)`, so the same branch scored twice gives the
   same number regardless of order or context — which a predictor simulation
   could never promise.

2. **`f ≡ 1` cannot reach a ratio at all, and that took a third guard.**
   `BlockCounts::Flat` returns `None` without consulting a count;
   `BranchBias`'s fields are private and its only constructor returns
   `Option`; and **two observations sharing one `BlockObs::source` are one
   datum, not a ratio**. The third is load-bearing rather than defensive:
   item C's Lane 2 ids are assigned over MWIR blocks while `s(b)` is over
   emitted-word blocks and one MWIR block spans several, so a branch whose
   two arms sit inside one Lane 2 span would otherwise read `1:1` and be
   charged the **full 14** — and *every abort branch has exactly that shape*.
   Without this guard the item's own headline finding would have inverted.

3. **An unmeasured branch charges nothing**, the same case as the flat row.
   At item C's 13.4% block coverage, treating one as 0.5 would put the full
   penalty on ~87% of branches: not a measurement, arithmetically
   indistinguishable from raising branch latency by a constant (so it ranks
   nothing), and an over-credit of branch removal — 1609's second clause, and
   what `branch_penalty = 0` existed to refuse. It does **not** conflict with
   compose's coverage honesty: that rule stops a transform deleting measured
   *mass*, and an unmeasured branch loses none — its `s(b)` is charged in
   full and only the surcharge is absent.

4. **Two §4.8 terms decided, two recorded undecidable — and the degeneration
   is the argument.** Fn entries are 4-byte aligned (`layout.rs`), so the fn's
   address modulo the 32 B fetch region is one of 8 permitted residues. Rows
   23 (>4 branches per aligned 32 B) and 25 (a ≤32 B loop not inside one
   region) take **item I's ∀ precedent**, scored at each residue with the
   worst taken *jointly* so one fn is priced at one placement. Rows 24 (2 MiB
   crossing) and 26 (unaligned entry / target) are **undecidable and charge
   0** per decision 1615: for any residue exactly one residue class of target
   offsets is 32 B-aligned and some residue leaves that class empty, so ∀
   charges **every branch target in the program** — arithmetically the
   unconditional branch penalty this item exists to replace; for entries it
   is a constant per fn, which ranks nothing and over-credits fusion; and row
   24's residue set mod 2 MiB has 524288 members. Residual risk stated: a
   transform worsening target alignment is priced at zero. The honest later
   fix is the **provable floor** — `#targets − (largest residue class)` are
   misaligned at *every* placement, a theorem rather than an invented
   incidence.

5. **A hole in the profile, reported rather than papered over.** §4.8 prices
   **none** of its four rules, so their magnitudes are T5 and unpinnable
   (1602). The profile declares exactly one swept front-end magnitude —
   `[sweep.range_cross_penalty]` — so rows 23/25 are charged at it through a
   `SweepPoint`; all four rules and row 27 are instruction-**fetch** effects
   and inventing four separate numbers is what 1602 forbids. Because it is
   swept, item J's ∀ makes a padding candidate win at 1 as well as at 6.
   **Row 27 therefore has no incidence of its own**: `[branch]` declares no
   range-crossing *threshold* row (the research block's "6 cycles for
   64–2048 B, 1 cycle at 4096 B" has no home in the table). Adding
   `[branch] range_cross_bytes` is a profile change and belongs to item D's
   owner. The fetch region is read from the profile and **cross-checked**
   across the three rows that spell 32, failing closed if a later edit splits
   them.

6. **Measured reach, and the flat row does not move.** Over all six `cost-*`
   cases: **216** `CostRule::Branch` words = **115** unconditional `B`
   (perfectly predicted, charged 0 as a *fact*) + **28** `RET` (no PC-relative
   target; the return-address stack predicts it) + **73** conditional with two
   resolvable successors — so only **73 of 216** branch words can ever carry a
   bias, and the census **fails closed** on any other unresolvable branch (an
   indirect `BR`, which nobody has priced). Under `W_flat`, **0** branches
   carry a bias. `dense_excess = 0` and `loop_crossings = 0`, so all six
   `--stage=cost` dumps are **byte-identical** before and after (153 / 172 /
   90 / 314 / 169 / 1954) and no `cost-*` golden moves. The frame is why, and
   it is item I's §4.5 result again: every branch is preceded by the compare,
   `cset`, spill and reload that materialised its condition, so five branches
   never fit one 32 B fetch region, and no loop body survives that frame at

   The **image report** Cost summary does move, entirely on row 23 in the

7. **Item L's monotonicity oracle cannot hold as worded, and that is real.**
   "A dead instruction never lowers a schedule" is false once row 23 is live:

   of the §4.8 rule. `unit:a_padding_word_can_lower_the_density_charge_and_that_is_real`

### I. NZCV/SP renaming + alignment penalties

**1616. Renaming removes WAR/WAW, not RAW. This item's own premise was
wrong, and the correction is recorded here rather than in a commit message.**
Item I's text below says SOG §4.10 note 1 ("NZCV and SP are fully renamed")
makes the scoreboard's flag serialization "wrong for A76" and instructs
"Remove it. **This lowers costs**." Item E removed it, and item I then found
the error while building the oracles: register renaming eliminates **false**
dependences — WAR (a writer waiting on an earlier reader) and WAW (two
writers serializing) — by giving each definition its own physical register.
It does nothing to a **RAW** dependence. `cmp` computes NZCV and
`b.cond`/`cset` consume it; `sub sp, sp, #N` computes the address a later
frame access needs. No renaming lets a consumer read a value before its
producer produced it.

Worse for the premise: this model **never had** a WAR or WAW flag stall to
remove — a flag write simply overwrote the producer time, and a write after
a read cost nothing — so note 1 licensed no change here at all, and the
deletion removed a correct edge. Its direction was **under-cost**, the one
direction 04 §5 forbids and the one this milestone has no hardware oracle to
catch (see "The soundness posture").

**Restored, 2026-07-29:** `flags_ready` and `sp_ready` carry real RAW edges
again. What item I was right about is narrower and is kept — register number
31 is **XZR** in almost every instruction group and **SP** only in
add/subtract (immediate), so the pre-M20 `ready[31]` edge invented a
dependence on every `str xzr` word, a constant with no producer. The two are
now tracked apart: a word reads SP only when its address is a **proven**
`MemClass::Stack` slot or its encoding names register 31 as an
add/sub-immediate `Rn` (`encode::reads_sp`, checked against the real
encoders in both directions). `ready[31]` stays permanently zero.

Measured cost of the restoration on the post-item-F corpus: **+84
proxy-cycles** (`cost-arith` +12, `cost-branchy` +12, `cost-calls` +5,
`cost-mem-locality` +1, `cost-runtime` +54, `cost-bounds-elide` 0), i.e. the
under-cost that had been shipped. Oracles: `nzcv_raw_edge_is_charged_like_a_gpr_dependence`,
`renaming_removes_war_and_waw_flag_hazards_but_not_the_raw_edge` (each shape
scored against a single-architectural-register counterfactual, so the two
models are asserted to **agree** on RAW and **diverge** on WAW),
`sp_raw_edge_holds_while_an_xzr_read_waits_on_nothing`, and
`reads_sp_distinguishes_sp_from_xzr_at_register_31`.

**Item I's remaining findings stand as recorded below** — the two per-fn rank
flips, the `cost-branchy` `cmp`→`cset` observation, decision 1615 on
undecidable `Cold` alignment, and the finding that wrela's fixed frame can

   that happen to share a trigger would silently restore a stale-reuse bug.
   Worth recording: encoding 31 is XZR outside load/store, so part of what
   this removes was a *false* dependence on every `str xzr` word.

5. **The §4.5 alignment terms are live and unexercised, and that is the
   result.** The frame arithmetic: `encode::scaled_offset` **asserts** every
   immediate offset is a multiple of its own transfer width; `LDAR`/`STLR`
   have no offset; no emitted access exceeds 8 bytes (no `LDP`/`STP`, no
   vector form — `CostRule::Neon` has zero emit sites). So every frame
   access is naturally aligned, and 8 divides both 16 and 64, so neither
   boundary can be straddled — for **any** `sp`, without knowing `sp`, since
   `sp ≡ 0 (mod 16)`. Measured over the whole corpus rather than argued:
   **1319 Stack accesses decided, 0 straddling; 90 Cold accesses not
   decided.** Corpus effect: **zero**. The terms are witnessed only
   synthetically, at frame offsets `codegen.rs` cannot emit. *The fixed
   frame makes both §4.5 penalties unreachable by construction* — a result
   about the spill-everything frame, and one of the few places where that
   frame is unambiguously cheaper than a register allocator would be.

6. **An access-width tag was added, and not the way this item's text
   proposed.** The width is tagged onto every `EmittedWord` **at
   construction** by `encode::access_width_bytes`, which reads back the
   `size` field `encode.rs` itself wrote. This item's text said "add it at
   emit time … never infer it from the mnemonic text"; both halves are
   satisfied (construction *is* the emit site; no mnemonic is read), but the
   route the text imagined — a `width` argument threaded through ~95
   load/store push sites — was rejected deliberately: unlike `CostRule` and
   `MemRef`, the width is **already in the encoding**, so a per-site
   parameter would create a second source of truth able to disagree with the
   word actually emitted, which is the defect freeze 1303 exists to prevent.
   It also keeps `codegen.rs` to two added frame constants while four other
   items are editing it. `encode::access_width_bytes` fails closed on any
   shape it does not encode, and `unit:access_width_round_trips_every_load_store_encoder`
   pins the projection against every load/store encoder in the module. No
   census or ratchet moved: the added function is not named `enc_*`, and the
   census needle is `encode::enc_`.

**1615. An undecidable alignment incidence charges nothing — the conflict,
recorded rather than resolved silently.** Required by this item's own
instruction and by "The soundness posture": two readings genuinely conflict
and neither dominates.

- **Reading A (decision 1609, literal).** A `Cold` base's alignment is not a
  fact this model has, so crossing is *undecidable*; the pessimistic end of
  an unknown incidence is 1.0, so charge every `Cold` load/store.
- **Reading B (rows 29/30 and decision 1602).** Both rows say "pinned
  (**statically decidable**)". The sweep box brackets the §4.5 **magnitude**
  (1–4); it says nothing about incidence. Pinning incidence at 1.0 is not
  taking the pessimistic end of a bracket the record gives — it is inventing
  a number the record is silent about, which is exactly what 1602 forbids.

**Resolved as B, charging 0 where the base alignment is unproven**, on three
grounds, each stated so a later reader can overturn it deliberately:

1. **It would double-count one uncertainty.** "This address is not proven" is
   *already* rounded toward over-costing in `mem_access_latency`: a `Cold`
   access is charged the L3 leaf (35) rather than an L1 hit (4), and an
   untagged one gets no reuse credit at all. Decision 1609 asks each residual
   uncertainty to round up once, not once per term that can see it.
2. **It would make the term decorative.** A constant charge on every `Cold`
   access is arithmetically indistinguishable from raising the `Cold` leaf
   latency, and it would leave the model unable to rank an alignment-improving
   transformation — the only thing the term exists to do.
3. **1609's own second clause.** For a penalty whose *removal* is the win, a
   larger value is not automatically safe: a blanket `Cold` surcharge
   over-credits deleting cold accesses, i.e. exactly the next rung's
   candidate list (spill-to-VPR, inlining, LICM).

**The residual risk, stated plainly:** if wrela ever emits a genuinely
misaligned access through a computed base, this model will price it as
aligned, and that is an under-cost of the kind 04 §5 forbids. Two things keep
that from being invisible. `encode::scaled_offset` makes a misaligned
*offset* unrepresentable, so the only route in is a misaligned *base*; and
`unit:stack_accesses_never_straddle_either_boundary_on_the_corpus` fails
closed the moment an emitted access appears that `encode::access_width_bytes`
cannot size. What is **not** oracled is base alignment itself — `MemRef`
carries no alignment fact, and giving it one is the honest fix if a later rung
needs this term to be real on `Cold`.

**Also recorded, because it is an under-cost the plan did not flag.**
"Renamed" removes WAR and WAW hazards; it does not remove a **RAW**
dependence, and `B.cond` genuinely needs NZCV. Item E's removal deletes the
flag *data* edge outright, which is stronger than SOG §4.10 note 1 licenses,
and the direction is *under*-cost — the one direction 04 §5 forbids. The
magnitude is bounded and small: one cycle per flag write→read pair, which on
this corpus is −75 of 3895, and in `cost-branchy` lands almost entirely on
`cmp` → `cset` rather than on a conditional branch. The same caveat applies to
the SP half (a stack access does need `sp`'s value; the edge deleted was worth
at most the 1-cycle prologue `sub`, against a false XZR edge it also deleted).
This is **not** re-litigated here — item E's removal is merged and item I was
told not to re-remove anything — but it belongs in the record rather than in a
commit message, and item L's over-cost oracle should decide whether a
1-cycle flag-consumer latency belongs back in the model.

**1618. Three §4.8 rows cannot be implemented as the inventory states, and
one of the plan's own research figures does not follow. Recorded by item H
and confirmed by the orchestrator.**

Rows 23 and 25 (branch density per aligned 32 B; a ≤32-byte loop fitting one
region) **are** decidable and are live: a fn entry is 4-byte aligned, so its
address mod the 32 B fetch region is one of 8 permitted residues, and item H
quantifies over all 8 and charges the worst — item I's `∀`-over-permitted-
alignments precedent (`crosses_boundary_quantifies_over_every_permitted_sp`),
maximised **jointly** across the two rows so one fn is priced at one
placement rather than at two different imagined ones.

Rows 24 and 26 are **not** decidable that way, and quantifying over
alignments degenerates rather than over-costing usefully:

- **Row 24** (branch and target crossing a 2 MiB region): the residue set mod
  2 MiB has 524288 members, and for any branch/target pair *some* member
  separates them — so ∀ charges **every** branch.
- **Row 26** (unaligned subroutine entry / branch target): for any residue,
  exactly one residue class of target offsets is aligned, and some residue
  leaves that class empty — so ∀ charges **every** branch target, which is
  arithmetically the unconditional penalty this whole item exists to replace.
  For entries it is a constant per fn, which ranks nothing and over-credits
  fusion.

Both therefore charge **0** and are recorded, on decision 1615's three
grounds transferred verbatim. The residual is stated rather than hidden: a
transform that worsens target alignment is priced at zero. The honest later
fix is a **provable floor** — at least `#targets − (largest residue class)`
targets are misaligned at *every* placement, which is a theorem rather than
an invented incidence.

**Row 27 has no incidence at all.** `[branch]` declares thresholds but no
range-crossing *distance* row, so there is nothing to test an incidence
against; inventing one would be a pinned number with no source (freeze 1629).
Its swept magnitude `range_cross_penalty` is instead the magnitude rows 23
and 25 are charged at, since §4.8 prices none of its four rules and the
profile declares exactly one front-end magnitude. **And the research figure
itself does not follow:** "6 cycles for 64–2048 B, 1 cycle at 4096 B" has the
penalty *decreasing* with distance, which reads as a garbled source. That is
why the sweep box collapses it to [1, 6] and why no incidence was built on
it. A reviewer wanting four separate front-end magnitudes must source them
first.

**Consequence for item L, which must not land a false oracle.** "A dead
instruction never lowers a schedule" is **false** once row 23 is live: a
padding word genuinely reduces branch density inside a 32 B fetch region, and
that is genuinely cheaper on A76 — it is the §4.8 rule's entire content, not
a modelling artefact. Item H pins the counter-example
(`unit:a_padding_word_can_lower_the_density_charge_and_that_is_real`). The
**mispredict** half of monotonicity does hold and is asserted separately.
Item L must reword the oracle to the claim that is true, and must not
"fix" the model to satisfy the old wording.

### L. Ruler oracles

Re-assert 04 §5's existing oracles under the new model and extend them:

- **Null-opt:** renaming every scored fn key must not rank as a win — now with
  block-grain `f` attached, at every box point.
- **Monotonicity:** a dead instruction never lowers a schedule, footprint
  cost, or mispredict charge.
- **Over-cost rule (1609):** one unit per swept dimension asserting the pinned
  value is its bracket's pessimistic end. **This is the oracle that replaces
  hardware validation** — if it is weak, nothing else catches an optimistic
  table.
- **Provenance (1629):** a table with a pinned T5 row fails to load; the
  provenance digest changes when any tier changes.
- **Inventory completeness (1632):** a `CostRule` variant with no inventory
  row fails the ledger check. This is what keeps the dimension list honest as
  the rule set grows.
- **Cliff witnesses:** L1I capacity, L1D 4-way conflict, I-TLB span, 32 B
  branch density, local-vs-remote load — each ranks in the expected direction,
  proving the term is live rather than decorative.
- **∃-cheat regression:** a candidate constructed to win only at the box's
  most generous point is vetoed.
- **Barrier-removal refusal (1633):** a candidate whose only gain is deleting
  a `DMB` is refused.
- **Synthetic partition adversary** (the pre-registered experiment): with
  [cost/ab.rs](../crates/wrela-compiler/src/cost/ab.rs)'s `prog()`/`word()`
  helpers, score the same instruction multiset as (i) N small fns + calls vs
  one fused fn and (ii) a loop body ×1 vs ×K unrolled. **Record the numbers;
  assert only what 04 §5 requires** (fusion must not read as a win). If fusion
  does read as a win, that is a hole in the null-opt oracle and the finding is
  the output — do not tune the table to hide it. This finally answers the
  mega-function question on a ruler that can see ports, fetch, trip counts,
  and cross-core traffic; it lands no transformation.

## Why this is a plan and not a cleanup

1. It lifts two explicit ledger hard-cuts and rewrites assertions in **two
   normative documents**, five code comments, two pinned dump strings, seven
   ledger notes, and seven ROADMAP passages (item A's inventory). A missed
   site leaves the tree self-contradicting, and CLAUDE.md makes the docs
   ground truth over the code.
2. It replaces the scoring core — ports, memory model, branch term, and a new
   cross-core term — moving the table digest repeatedly and with it every
   `cost-*` golden and every report Cost summary.
3. It **widens `CostRule::ALL`**, so the emitted-instruction census ratchet
   and every rule-count Terms line move.
4. It changes what the optimization gate admits by retiring the words veto —
   a change to what the project will let itself land.
5. It inverts the model's safety posture with **no hardware oracle behind
   it**, so decisions 1602, 1604, and 1609 and item L are not paperwork —
   they are the entire safety argument and must be reviewed as such.
6. Its most consequential dimension for *this* machine — cross-core
   publish/acquire cost — is unpriced by every available source, so the plan
   has to be explicit that the ruler's most important number is a swept range
   rather than a fact. That admission belongs in a reviewed plan, not in a
   commit message.
