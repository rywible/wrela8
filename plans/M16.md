## Goal

Make the stdlib and machine device story honest and testable before
spending the cleverness budget:

1. Normative 06 §6 split: thin device contracts vs queue/`@driver`
   contracts; say **virtio** only where the shipped contract is virtio.
2. Land `stdlib/drivers/` as a reserved-alias package sibling of
   `stdlib/core/`; relocate the virtio-blk `@driver` out of inlined
   golden bodies into `drivers.blk`.
3. Dual-tier in-wrela coverage: comptime `@test` / `@test(exhaustive)`
   over pure `core`; runtime goldens that import `drivers.blk`.
4. Wire the suite into `cargo xtask check` as named lane `stdlib-test`
   (fail closed if empty).

## Vocabulary (settled — do not blur)

| Term | Means |
| --- | --- |
| **Device** | VMM model + report/conformance (+ record/replay as applicable). Rows in the closed machine-v1 set. |
| **`@driver`** | Guest actor root that owns a multiphasic device protocol (pools/MMIO/DMA, receipts, optional mailbox). Language construct from 03. |
| **Thin guest surface** | Sealed language/runtime API for devices that do not earn a `@driver` (`now()`, console ring helpers, entropy effect). |
| **`stdlib/drivers/`** | Package tree containing **only** `@driver` modules. |

All machine-v1 rows are devices. Only some necessitate a full `@driver`.
Say **virtio** only where the shipped contract is actually virtio.

### When `@driver` earns its keep

Use `@driver` when there is multiphasic protocol / reset epochs, DMA
ownership, and a client messaging surface. Do not use it for abort-path
logging, monotonic clock reads, or "give me N random bytes."

| Device | `@driver`? | Why |
| --- | --- | --- |
| `blk` | yes | virtio-blk queues, DMA, receipts, reset |
| `input` / `display` | yes (pixels rung) | real protocol + clients |
| `clock` | no | sealed `now()` → trapping MMIO; deadlines depend on direct reads |
| `console` | no | fixed ring + VMM drain; must serve panic/abort without actor turns |
| `entropy` | no | recorded nondeterministic bytes; clock-shaped, not blk-shaped |

## Where this milestone starts (verified anchors, 2026-07-28)

### 06 overclaims "every device is virtio + has a stdlib `@driver`"

- `docs/language/06-machine.md` §6 (~120–136): "each a virtio-family
  contract whose driver ships in the stdlib"; table lists console as
  `virtio-console`, entropy as `virtio-rng`.
- Reality: console is the fixed ring + VMM drain (M5); clock is trapping
  MMIO + `now()` (M5/M6); entropy has **no** VMM model and **no** guest
  surface yet; only `blk` has a real virtio contract + inlined `@driver`
  bodies in goldens.
- `stdlib/README.md` (~1–6): claims "the machine's complete driver set."

### `stdlib/` has `core/` only — no `drivers/`

- Layout: `stdlib/core/*.wr` (list, time, runtime, enums, …); no
  `stdlib/drivers/`.
- Loader reserved alias is **`core` only** —
  `crates/wrela-compiler/src/loader.rs` `import_target` (~302–310);
  `stdlib_core_root` (~259–285). 02 §2.1 (~88–90): "ships no other
  acquirable package."

### Blk `@driver` bodies are inlined in goldens

Flagship body (layouts + `BlkDriver` + bring-up):
`tests/golden/boot-blk-roundtrip/input.wr` (~18–…, `@driver` at :57).

Other boot goldens that carry a virtio-blk-shaped `@driver` body (M16
owns relocating these onto `drivers.blk`, not redesigning them):

- `boot-blk-roundtrip`, `boot-blk-two-devices`
- `boot-device-bringup`, `boot-device-claim`, `boot-irq-isr`
- `boot-dma-reclaim`, `boot-receipt-recover`, `boot-driver-message`
- `boot-deadline-driver-turn`, `boot-cross-core-driver-mailbox`
- `boot-handle-index-distinct`, `boot-handle-space-multi-kind`

Feature-stub `@driver`s in err-/check- goldens that are **not** the
shared virtio-blk protocol body stay local (they test claim/provenance
edges, not the stdlib driver). Do not invent a framework to share them.

### Comptime `@test` exists; no stdlib suite under `check`

- `wrela test` / `eval::run_tests` / golden `check-tests-*` cover the
  language; nothing systematically runs `@test` over `stdlib/core/`.
- `cargo xtask check` (`crates/xtask/src/main.rs` `fn check`) has no
  stdlib-coverage lane. Absence of stdlib tests is currently silent.

### Entropy / console / clock (for honesty only)

- Entropy: named in 06 §6 / §10; no model, no guest effect — **M17**.
- Console / clock: thin today; M16 only renames them in docs unless a
  floor bug blocks honesty.

## Shape decisions this milestone freezes (do not relitigate mid-item)

Decision numbers: this plan reserves **1100–1199**.

1. **`drivers` is a reserved alias beside `core`.** Spelling:
   `from drivers.blk import BlkDriver` (and sibling modules later).
   Resolution mirrors `core`: sibling `stdlib/drivers/` next to the
   package root wins if present; else toolchain
   `crates/wrela-compiler/../../stdlib/drivers`. Missing tree → named
   `error[build]` (same fail-closed shape as `err-stdlib-missing`).
   Normative: extend 02 §2.1 ("no other acquirable package" → `core`
   and `drivers` are the two reserved aliases; still no lockfile /
   acquisition). **Rejected:** putting `@driver` modules under
   `stdlib/core/`; inventing a third import form; a plugin registry.
2. **`stdlib/drivers/` contains only `@driver` modules.** Console /
   clock / entropy helpers stay under `core` or runtime — never under
   `drivers/` unless they become true `@driver`s (rejected for v1).
3. **Move, don't redesign blk.** Canonical body starts from
   `boot-blk-roundtrip`'s layouts + `BlkDriver`. Shared layouts that the
   driver needs (`VirtioIrqMmio`, `BlkReqHeader`, …) live with the
   driver module (or a `drivers.blk_*` sibling if one file grows
   unreadable — prefer one file first: `stdlib/drivers/blk.wr` declaring
   `module blk`). Goldens import; they do not keep a second copy of the
   protocol body.
4. **Byte-identical transcripts preferred.** After relocation, owned
   boot goldens must keep their pinned transcripts. If import/module
   identity forces a dump or transcript change, re-pin in the same
   commit with an explicit ledger cite — never a silent drift.
5. **Comptime suite discovery root = `stdlib/tests/`.** Dedicated test
   modules (e.g. `stdlib/tests/list_test.wr`) import `core.*` and declare
   `@test` / `@test(exhaustive)`. Production modules under
   `stdlib/core/` and `stdlib/drivers/` stay free of `@test` so the
   suite root is enumerable and empty-by-accident is obvious.
   **Lane name:** `cargo xtask stdlib-test`. Wired into `check`.
   **Fail closed:** zero discovered `@test`/`@test(exhaustive)` fns
   under `stdlib/tests/` is a gate failure (not a quiet pass).
6. **Runtime tier = existing boot goldens + import path.** No new
   VMM. At least `boot-blk-roundtrip` (and every other owned blk boot
   above) imports `drivers.blk`. Runtime coverage of the driver is the
   transcript pin, not a second harness.
7. **Console helpers stay runtime-only in M16.** No new `core` console
   API unless a doc honesty edit requires naming an existing helper.
   No console `@driver`. No clock `@driver`.
8. **06 §6 rewrite lands in item A (human-reviewed).** Thin vs queue
   subsections as in the design; entropy row marked "lands M17" under
   thin contracts; virtio only on `blk` (and future queue devices when
   scheduled). Appliance-author sentence softens: stdlib ships
   `@driver`s for queue devices; thin devices use sealed surfaces.

## Verification policy (cheap per item; expensive at close)

`cargo xtask check` is the gate. It is **too expensive to run after every
item.** Split:

| Lane | When | What |
| --- | --- | --- |
| **Cheap (required per item)** | Before that item's commit | Unit tests + dumps for **new/changed** behavior; named goldens the item touches; `cargo xtask ledger` / `corpus` when docs move |
| **Focused boot** | Items C/D only | Named `boot-blk-*` (and any other owned boot the item migrates) via the golden runner paths alone — not the whole `boot-*` corpus |
| **Expensive (item G only)** | Milestone close | Full `cargo xtask check`; deep fuzz smoke is enough unless a loader/sema change warrants a deeper lane (record the call in G) |

**Rules:**

1. Every item's Cheap oracle must fail if the new behavior is wrong.
2. Do **not** run full `cargo xtask check` on items 0–F.
3. Item G is not optional. The rung is not COMPLETE until the expensive
   lane is green.
